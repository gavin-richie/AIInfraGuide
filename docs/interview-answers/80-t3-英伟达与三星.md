# 英伟达（校招-2：基础知识）

## 1. SIMT 的含义与工作原理

**（英伟达-校招-2 基础 1）**

**含义**：Single Instruction, Multiple Threads——一条指令同时驱动一个 **warp（32 个线程）**，是 NVIDIA GPU 的执行模型。与 SIMD（向量寄存器一条指令算一个向量）的关键区别：

- 每个线程有**独立寄存器与 PC**，写的是标量程序；warp 是硬件动态组成的执行单位，程序员不感知——"SIMT 让你用标量代码获得向量性能"；
- **分支用活跃掩码处理**：warp 内各线程走不同路径时，硬件按掩码把两条路径**串行执行**（见第 8 题 warp divergence），而 SIMD 需要程序员手工写无分支代码或 intrinsic；
- **warp 切换零开销**：每线程寄存器独立，调度器换 warp 只是换一组寄存器指针，无需保存/恢复现场（对比 CPU 上下文切换 μs 级）。

**工作原理**：SM 内 warp scheduler 每个 cycle 从驻留 warp 中挑"就绪"（不 stall 在访存/依赖/屏障）的发射一条指令 → 经 scoreboard 记录长延迟指令的目的寄存器 → 就绪后继续。Volta 起每线程独立 PC + 活跃掩码（ITS），保证分歧线程的推进保证（详见《01》Q17）。

## 2. Occupancy 受哪些因素影响，如何调控

**（英伟达-校招-2 基础 2）**

**定义**：occupancy = 每 SM 实际驻留 warp 数 / 每 SM 最大驻留 warp 数（如 64）。

**影响因素**（取最小者决定）：

| 因素 | 约束（sm_80/86） | 计算 |
|---|---|---|
| 寄存器 | 每 SM 65536 个 32-bit 寄存器 | ⌊65536 / (regs/线程 × blockDim)⌋ |
| Shared Memory | 每 SM 上限（A100 164KB） | ⌊smem 总量 / 每 block smem⌋ |
| 线程数 | 每 SM 2048 线程 | ⌊2048 / blockDim⌋ |
| Block 数 | 每 SM 16~32 个 block | — |

尾数浪费也常见：blockDim=96（3 warp）时每 block 占 3/64，2048/96=21.3 → 21 block = 63 warp，最后一个 warp 槽位浪费。

**调控手段**：
1. 减寄存器：`__launch_bounds__(maxThreadsPerBlock, minBlocksPerSM)` 让编译器 spill；`-maxrregcount`（全局，慎用）；
2. 减 smem：动态 smem 精确申请、复用 buffer（union）、降低 tile 尺寸；
3. 调 block 尺寸（64/128/256 扫一遍，`cudaOccupancyMaxActiveBlocksPerMultiprocessor` 直接算）。

**必说的反向认知**：occupancy 不是越高越好——寄存器被压缩后每线程 ILP 下降（见第 9 题），GEMM 类 kernel 常故意用 128+ 寄存器跑低 occupancy 换高 ILP；occupancy 的本质用途是**提供足够并发访存请求来填满带宽**（Little's Law，见《[81 篇](./81-t3-国产gpu厂商.md)》寒武纪 Q5）。

## 3. Bank Conflict 的粒度是多少

**（英伟达-校招-2 基础 3）**

**粒度：warp（32 线程）× 一条 shared memory 指令**。shared memory 物理上分 32 个 bank，每 bank 宽 4B、每 cycle 服务**一个**地址：

- **判定单位是 warp 级**：单线程（或 half-warp 时代的说法已过时）谈不上 conflict；同一条 `ld.shared` 中，warp 内 32 个地址落在不同 bank → 一次完成；
- 32 个地址访问**同一 bank 的不同地址** → n 路 conflict，串行化 n 个 cycle；**同一地址 → 硬件广播，不算 conflict**；Ampere 起多地址组播（几个不同地址被同 bank 多个 word 服务）也有优化；
- **64-bit 访问拆成两个 4B phase**，各 phase 独立判 conflict（double 数组相邻两元素同 bank 时无 conflict，恰是 8 字节 bank 模式的场景）；
- bank 编号 = `(addr / 4) % 32`，所以 stride 为 32 字节整数倍的按列访问是 32 路 conflict 的典型（解法 padding/swizzle 详见《01》Q7/Q11）。

## 4. GEMM 分块大小的选择受哪些因素制约

**（英伟达-校招-2 基础 4）**

分块（tile）选择是寄存器/共享内存/并行度三方约束的解，完整优化方法论见《[03 GEMM 与算子优化](./03-gemm与算子优化.md)》Q3，这里列制约因素：

1. **寄存器文件**：每线程累加器数 = (BM×BN)/线程数。128×128 tile / 256 线程 = 64 个累加器 + A/B 操作数与地址 ≈ 128+ 寄存器 → occupancy 掉到 25-50%。累加器数量是 tile 的硬下限约束；
2. **Shared Memory**：双层 buffer 的 A tile (BM×BK) + B tile (BK×BN)，128×32 + 32×128 × 2buffer × 4B = 64KB——逼近单 block 上限（A100 164KB、sm_86 99KB），还与驻留 block 数二次权衡（smem×驻留数 ≤ 总量）；
3. **Tensor Core 形状**：`mma.m16n8k16` 等指令片段决定 tile 最好是 16/8 的整数倍，warp 级 tile（如 64×64）由 8×8 个 mma 拼成；
4. **Wave 量化**：grid = ⌈M/BM⌉×⌈N/BN⌉ 个 block 波次地铺满 SM（3090 是 82 个）。tile 太大 → 波数少、尾波浪费（最后一波只跑一半 SM）；tile 太小 → 复用率降、装载占比升；
5. **L2 复用**：同一批 B tile 被同行 block 复用，tile 尺寸与遍历顺序（supergrouping）影响 L2 命中；
6. **问题形状**：M 很小（decode）→ 大 BM 浪费，考虑 split-K 用 K 维补并行度（见《81 篇》壁仞 Q1）。

工程答案：以 CUTLASS tile scheduler 的启发式为起点（64-128 边长、BK 32-64），拿 Nsight 扫 `BM×BN×BK×stage` 四元组。

## 5. 使用 float4 读写全局内存为何能提升性能

**（英伟达-校招-2 基础 5）**

1. **指令数与地址计算 ÷4**：一条 `LDG.128` 替代 4 条 `LDG.32`，发射压力、地址计算、寄存器占用都下降；
2. **事务利用率**：warp 32 线程 × 16B = 512B，恰好 4 个 128B 事务、每个 sector（32B）全被用上——对齐 16B 时合并访存达到理想值；逐 float 访问时若 stride 不当，一个事务只服务 4B 数据；
3. **内存级并行（MLP）**：每条指令挂起 4 倍字节，同等寄存器预算下 in-flight 字节数更多，更容易填满带宽（Little's Law 的应用）；
4. 限制：地址必须 **16 字节对齐**（`__alignas__(16)` / tensor 尺寸 pad 到 4 的倍数），非对齐会拆成两条指令反而变慢；尾块要 fallback 到标量路径。

## 6. 一个 Block 是否可能被调度到不同的 SM 上执行

**（英伟达-校招-2 基础 6）**

**不能**。Block 是 GPU Work Distributor 的**调度原子单位**：block 启动时被整体分配到某一个 SM，其寄存器、shared memory 在**该 SM 上物理分配**，直到 block 内所有线程执行完才释放。三个推论：

- block 内 `__syncthreads()` 之所以可行，正因为所有线程同驻一个 SM；
- block 一旦 resident 就**不会迁移**——迁移意味着搬寄存器/smem，代价远超收益；即使发生计算抢占（Pascal+），也是整 kernel 状态保存/恢复级别的操作；
- 正因为"block 不跨 SM、block 间无全局同步原语"，跨 block 通信才需要 kernel 边界、cooperative groups 或原子轮询 + `__threadfence()`（《01》Q12）。

## 7. 主流 GPU 型号的 Cache 容量

**（英伟达-校招-2 基础 7）**

L1 与 shared memory 共享同一块每 SM SRAM；L2 全芯片共享。常见型号（数据中心 + 消费级）：

| 型号 | 每 SM L1/smem | L2 | 显存带宽 |
|---|---|---|---|
| V100 (sm_70) | 128KB（smem ≤96KB） | 6MB | 900 GB/s |
| A100 (sm_80) | 192KB（smem ≤164KB/block） | 40MB | 2039 GB/s (SXM) |
| H100 (sm_90) | 256KB（smem ≤228KB/block） | 50MB | 3350 GB/s (SXM) |
| RTX 3090 (sm_86) | 128KB（smem ≤99KB/block） | 6MB | 936 GB/s |
| RTX 4090 (sm_89) | 128KB | 72MB | 1008 GB/s |

趋势：L1/smem 越做越大（Hopper 让 TMA + warp specialization 吃满它）；L2 从几 MB 涨到几十 MB（A100 起），**跨 block 数据复用、persistent kernel、graph 重跑的命中率收益显著**；答题时给出"L1/smem 共享、L2 全芯片、两者都参与 global 访问路径"即可，具体数字记 2-3 个常用卡。

## 8. Warp Divergence 对性能的具体影响

**（英伟达-校招-2 基础 8）**

**机制**：warp 内线程走到不同分支时，SIMT 单元用活跃掩码**串行执行每条路径**——两条路径都执行，各自只有掩码内的线程写回。

**具体影响**：
1. **吞吐按活跃比例下降**：if/else 两半各 50% 线程时，这段代码执行两遍，峰值吞吐 ÷2；32 个线程走 32 条路径的极端（如 `if (tid == i)` 的 switch）退化 32×；
2. **额外开销**：分支指令、掩码管理、reconvergence 点同步；嵌套分歧指数放大；
3. **不会死锁/饿死**（Volta ITS 后有 forward progress 保证，见《01》Q17），但 pre-Volta 的惰性 reconvergence 调度会造成类似"活锁"的表现；
4. **对访存的影响**：分歧后各路径的访存模式不同，合并访存被打散。

**对策**：按分支条件**预排序数据**（同 warp 数据同路径）；分支上提（不同路径拆成两个 kernel / grid-stride 按条件分段）；短分支用 predication/setp 让编译器生成无跳转代码；warp-aggregated atomics（`__match_any_sync` 聚合同类原子）。

## 9. NVIDIA GPU 中指令级并行（ILP）的实现方式

**（英伟达-校招-2 基础 9）**

GPU 核内是**顺序发射**的，ILP 靠"指令流中有互相独立的指令可以背靠背执行，长延迟指令的依赖不阻塞后续无依赖指令"实现，硬件上由 **scoreboard** 追踪：发射 load 后目的寄存器标记未就绪，后续用到它才 stall，不用的照常跑。

**构造 ILP 的手段**：
1. **多累加器**：GEMM 每线程 8×8=64 个独立累加器 → 64 条无依赖 FMA 可以连续发射，访存延迟被计算填满（这正是寒武纪"8×8 块"的考据，见《[81 篇](./81-t3-国产gpu厂商.md)》Q1）；
2. **循环展开**（`#pragma unroll`）：把迭代间独立的开出来；
3. **访存/计算交错**：先发起下一 tile 的装载再做本 tile 计算（double buffer 的软件形态）；
4. **MLP**：每线程同时挂多个 load（float4 × 多元素），一次 stall 换多份数据。

**ILP 与 TLP 的关系**：延迟隐藏的需求 = 带宽 × 延迟（Little's Law）。可以用更多 warp（TLP，靠 occupancy）或每线程更多独立工作（ILP，靠寄存器）满足——两者共用寄存器预算，此消彼长，这正是"occupancy 不是越高越好"的根因（见第 2 题）。

## 11. 实现向量外积运算

**（英伟达-校招-2 编程 11）**

`C[i][j] = a[i] * b[j]`。计算只有一次乘法，考点全在访存设计：

```cuda
// C(M×N) = a(M) ⊗ b(N)，行优先
__global__ void outer_product(const float* __restrict__ a,
                              const float* __restrict__ b,
                              float* __restrict__ c, int M, int N) {
    int i = blockIdx.y * blockDim.y + threadIdx.y;   // 行: 对应 a
    int j = blockIdx.x * blockDim.x + threadIdx.x;   // 列: 对应 b
    if (i < M && j < N)
        c[i * N + j] = a[i] * b[j];
}
// 启动: dim3 block(32, 8); dim3 grid((N+31)/32, (M+7)/8);
```

工程化：`solutions/cuda/src/elementwise.cu::outer_product`，ctest `test_elementwise`（非 32/8 整数倍的 M/N 边界对拍）。

访存分析（面试按 warp 讲）：同一 warp 内 threadIdx.x 连续 → **b 的读取合并**；`a[i]` 对 warp 内 32 线程是**同一地址，硬件广播**（不耗额外带宽）；写出 `c[i*N+j]` 行内连续 → **写合并**。进阶：b 整段可放 constant memory（≤64KB）或 `__ldg`；输出用 float4 每线程写 4 列减少线程数。语义参考实现与对拍：`solutions/python/src/answers/t3/outer_product.py`（`torch.outer`/`einsum("i,j->ij")` 三方一致）：

```bash
cd solutions/python && pytest tests/test_t3.py -k outer -q
```

**（英伟达-AI-Infra 项目 3）**

方法论（比结论更重要）：

## 15. 时针与分针的夹角（追问：毫秒级精度）

**（英伟达-AI-Infra 编程 4）**

**公式**：把时间统一换算成连续分钟数 `t = h%12*60 + m + s/60 + ms/60000`（h 取 12h 制），则

$$\theta_{hour} = 0.5^\circ \times t \quad(360°/12h = 0.5°/min),\qquad \theta_{min} = 6^\circ \times t \quad(360°/60min)$$

$$\text{angle} = \min(|\theta_{hour}-\theta_{min}| \bmod 360,\ 360 - |\theta_{hour}-\theta_{min}| \bmod 360)$$

**毫秒追问的正解**：不要用 `|30H - 5.5M|` 这类整分钟离散公式——它对秒/毫秒的扩展容易错。正确做法就是上面的"先换算成连续量再代入"，公式天然支持任意精度。若担心浮点误差，可全程用整数毫秒计算角度（角度单位取 1/120° 的整数倍）。

## 16. 三个线程按顺序循环打印递增数字（追问：线程异常退出不死锁）

**（英伟达-AI-Infra 编程 5）**

**基本版**：一个互斥量 + 条件变量 + `turn` 变量：线程 `i` 等 `turn == i`，打印下一个数字，`turn = (i+1)%3`，`notify_all`。（也可以三个 Semaphore 接成环，但 Condition 版更好扩展。）

**追问——异常退出不死锁**，三道防线（面试得分点）：

1. **try/finally 推进状态**：worker 的打印逻辑包在 try 里，异常时在异常处理中把 `turn` 推给下一个线程并 `notify_all`，绝不带着锁退出——其他线程继续完成剩余工作（或有序退出），而不是等一个已死的线程；
2. **wait 带超时**：`cond.wait_for(..., timeout)` 即使通知丢失也能周期性醒来检查"轮到我了吗 / 该停了吗"，把永久阻塞变成有界等待；
3. **全局停止标志 + 看门狗**：异常线程置 `stop` 标志，其余线程醒来即退出；关键服务再加监控线程检测心跳，超时强制回收。

## 20. C++ 函数重载的规则与实现

**（三星-一面-1 C++ 5）**

**规则**：同一作用域内同名函数，**参数个数/类型/顶层→底层 const 限定不同**即可重载；**返回值类型不参与**判定（调用处可以不接返回值，编译器无法消歧）；`const T&` 与 `T&` 可重载（绑定规则区分）。匹配优先级：精确匹配 > 常量转换/提升 > 用户定义转换；有歧义则编译错。

## 22. 构造函数能否声明为虚函数

**（三星-一面-1 C++ 7）**

**不能**，两个理由：

1. **机制上**：虚函数调用需要对象里的 vptr → vtable，而 vptr 是**构造函数负责设置的**——构造执行时 vtable 尚未就位（基类构造期间 vptr 指向基类 vtable），"虚构造"没有可用的派发基础设施；
2. **语义上**：虚函数的意义是"依实际类型动态派发"，而调用构造函数时必须**先知道确切类型**才能分配正确大小的内存——类型信息在构造之前就得有，因果倒置。

**对比**：析构函数**可以且常常应该是虚的**（基类指针 delete 派生类对象时不虚析构 = UB/资源泄漏），详见《09》Q8。想要"虚构造"的效果用 **clone 惯用法**（虚函数返回 `new Derived(*this)`）或工厂模式（恰好与三星-一面-2 的注册宏题呼应，见本篇 Q28）。

## 23. TCP 三次握手与四次挥手

**（三星-一面-1 网络 8）**

**三次握手**（建立连接）：客户端 `SYN(seq=x)` → 服务端 `SYN+ACK(seq=y, ack=x+1)` → 客户端 `ACK(ack=y+1)`。**为什么是三次**：双方各需要一个 SYN + 一个对方对自己 SYN 的确认才算"收发能力都验证"；两次无法阻止历史重复 SYN 建立的错误连接（旧 SYN 迟到，服务端单方面建连浪费资源）。

**四次挥手**（关闭）：主动方 `FIN` → 对方 `ACK`（此时对方还可继续发 = **半关闭**）→ 对方数据发完后 `FIN` → 主动方 `ACK`，进入 **TIME_WAIT 等 2MSL**（保证最后的 ACK 丢失可重发、旧连接报文自然消亡）。**为什么四次**：ACK 与 FIN 不能合并——收到 FIN 时对方可能还有数据没发完。

## 25. 有序二进制字符串中查找第一个 1

**（三星-一面-1 编程 10）**

串形如 `000...0111...1`（0/1 各成前缀后缀，**单调**），等价于求数组中的 lower_bound：

```python
def first_one(s: str) -> int:
    if not s or s[-1] == "0":          # 全 0（或空串）无解
        return -1
    lo, hi = 0, len(s) - 1
    while lo < hi:                     # 找最左的 '1'
        mid = (lo + hi) // 2
        if s[mid] == "1": hi = mid
        else:             lo = mid + 1
    return lo
```

O(log n)。**面试要点**：先声明单调性假设（任意 01 串只能 O(n)）；边界（空串/全 0/全 1）；若输入是 `uint64` 的位串可用 `__builtin_ctzll` / `int.bit_length` 一条指令（对应 `algorithms/math_bits.py::first_one_index`）。代码与随机对拍：`solutions/python/src/answers/t3/first_one.py`：

## 28. AI 框架前端中算子注册的机制；为什么宏定义即可完成注册

**（三星-一面-2 基础 3/4）**

**机制**：框架维护一张全局注册表（op name → 实现工厂/dispatch 函数）。以 PyTorch 为例：

```cpp
TORCH_LIBRARY(myns, m) {          // 定义算子签名（schema）
    m.def("silu_fp8(Tensor x) -> Tensor");
    m.impl("silu_fp8", torch::DispatchKey::CUDA, &silu_fp8_cuda);  // 按 key 注册实现
}
```

调度器（dispatcher）运行期按（op 名, dispatch key: CPU/CUDA/Autograd/...）查表调用；autograd、vmap 等模式也是不同的 key。自研框架常见形态是"字符串 → creator 函数"的工厂注册表。

**为什么一个宏就能注册**：宏在**每个算子源文件里展开成一个静态全局对象**，其构造函数在 `main()` 之前（静态初始化阶段）把 `(name, factory)` 插入全局注册表：

```cpp
#define REGISTER_OP(name, cls) \
    static Registrar _reg_##__COUNTER__(name, [](){ return new cls(); });

struct Registrar { Registrar(std::string n, Factory f) { registry()[n] = f; } };
```

三个要点答深：①**静态对象构造先于 main**，注册不依赖任何显式调用；②注册表通常用 Meyers 单例（函数内 static map）规避静态初始化顺序问题；③**坑**：注册所在的 .o 若没被引用且用静态库链接，链接器可能整个丢弃（`--gc-sections`/选择性链接），导致"注册丢失"——解法是 `WHOLE_ARCHIVE` 强制链接或中心化显式引用。这与虚构造题（Q22）互补：**工厂模式就是运行期的"虚构造"**。

## 29. 模板函数的编译过程

**（三星-一面-2 基础 5）**

模板**不是代码，是生成代码的配方**，编译分两阶段：

1. **定义期**（模板本身编译）：做不依赖模板参数的名字查找与语法检查；依赖参数的名字（`T::value_type`）推迟——这就是为什么需要 `typename T::value_type` 消歧（依赖名默认不视为类型）；
2. **实例化期**（调用点/显式实例化）：编译器对每个 `f<int>` 按实参推导生成一份具体代码再正常编译。推论：**模板必须放头文件**（每个翻译单元都要看到完整定义才能实例化，声明定义分离会链接错，除非显式实例化 `template class X<int>;` 集中在一个 .cpp——见《09》Q11）；**代码膨胀**（每种类型一份）；`extern template` 可抑制隐式实例化减少编译时间。与重载（Q20）对比：重载是链接期符号区分，模板是编译期代码生成。

## 30. STL 迭代器在遍历中删除元素的正确方式

**（三星-一面-2 基础 6）**

```cpp
for (auto it = v.begin(); it != v.end(); ) {
    if (pred(*it)) it = v.erase(it);   // erase 返回下一个有效迭代器
    else            ++it;
}
```

工程化对拍（含等价 erase-remove 惯用法）：`solutions/cpp/tests/test_language_basics.cpp`。

要点：**erase 的返回值接管循环**，删除后不 `++it`（原迭代器已失效）。按容器记失效规则：`list/map/set/unordered_*` 只有被删的那个迭代器失效（节点式存储，其余不动）；`vector/deque` 中间删除会使**之后全部迭代器失效**（元素搬移；deque 两端特殊）。`vector` 删除满足条件的元素用 **erase-remove 惯用法**更优（一次搬移）：`v.erase(std::remove_if(v.begin(), v.end(), pred), v.end());`。

## 31. 常用 STL 容器

**（三星-一面-2 基础 7、一面-3 基础 3）**

| 容器 | 底层 | 随机访问 | 插入/删除 | 适用 |
|---|---|---|---|---|
| `vector` | 连续数组 | O(1) | 尾部均摊 O(1)，中间 O(n) | 默认选择，缓存友好 |
| `deque` | 分段连续 | O(1) | 两端 O(1) | 滑窗/队列 |
| `list` | 双向链表 | O(n) | 已知位置 O(1) | 频繁中删（LRU 链） |

## 32. DAG 的实现方式、拓扑排序

**（三星-一面-2 数据结构 8/9、一面-3 数据结构 10、飞腾 Q3 同族）**

**DAG 表示**：邻接表 `vector<vector<int>> edges` + 入度数组 `indeg[]`（比邻接矩阵省内存且拓扑排序直接用）。**判 DAG**：拓扑排序能否消费全部节点，或 DFS 三色标记（灰→灰出现返祖边即有环）。

**拓扑排序**两种实现（O(V+E)）：

```python
# Kahn（BFS 入度法）: 反复摘入度为 0 的点
def topo_sort_kahn(n, edges):
    adj = [[] for _ in range(n)]; indeg = [0] * n
    for u, v in edges: adj[u].append(v); indeg[v] += 1
    q = deque(i for i in range(n) if indeg[i] == 0); order = []
    while q:
        u = q.popleft(); order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    return order if len(order) == n else []      # 空 = 有环
```

DFS 逆后序：完成时间逆序即拓扑序。**应用**：编译/算子调度依赖（执行计划 = 拓扑序）、任务编排、课程表。实现：`algorithms/graphs.py::topo_sort_kahn / topo_sort_dfs`（测试在 `tests/test_algorithms.py`）。

## 34. 编译器中 IR 的转换流程

**（三星-一面-3 编译器 5）**

通用编译器：`源码 → 词法/语法分析 → AST → 语义检查 → 降低(Implicit CFG/SSA) → IR → 优化 pass(常量折叠/内联/循环不变量外提/GVN...) → 后端(指令选择/调度/寄存器分配) → 目标码`。

## 35. 算子融合的常见策略

**（三星-一面-3 算子 6）**

**判据**：相邻、生产者-消费者关系、中间张量大（省访存收益高）、融合后可驻留 smem/寄存器且不炸寄存器。**常见模式**：

1. **elementwise 链**（scale+shift+激活）：逐元素 fuse 零成本，收益 = 中间张量 × 2 次读写全免；
2. **reduce + broadcast**（mean/var → normalize → scale：LayerNorm/RMSNorm 整体一个 kernel）；
3. **GEMM + epilogue**（+bias、+激活、+残差、+反量化：cuBLASLt/CUTLASS epilogue 机制）；
4. **matmul + 反量化**（W4A16：解包内嵌装载，见《[06 量化](./06-量化.md)》Q2 Marlin）；
5. **conv + BN + ReLU**（线性折叠，公式见《[03](./03-gemm与算子优化.md)》Q13）；
6. **整个 attention**（QK^T、softmax、PV 一个 kernel = FlashAttention 的本质）。

反例（融合变慢：寄存器溢出/并行度不匹配/损失向量化）见《03》Q7。融合收益估算公式：`(中间张量字节 × 2) / 总耗时`，先估算再动手。

## 36. Attention 算子的实现方式

**（三星-一面-3 算子 7）**

`Attention(Q,K,V) = softmax(QKᵀ/√d)V`。实现三阶段：**naive**——物化 S∈R^{S×S}（显存 O(S²)、读三遍）；**tiling + online softmax**（FlashAttention）——Q/K/V 分块驻留 smem，流式维护 (m, l) 归一化因子，S 从不物化（显存 O(S)、访存约 1/3，原理与手写代码见《[04 Attention 与 KV Cache](./04-attention与kvcache.md)》Q1/Q4/Q5，本仓库有 MHA/GQA/MLA/FA v1v2 全部可跑实现）；**decode 特化**——Flash Decoding 沿 KV 切分 + combine。多尺度变体（GQA/MLA/PagedAttention）同篇 Q3/Q6。

## 37. Softmax 的计算公式与数值稳定性处理

**（三星-一面-3 算子 8、后摩 Q3 同族）**

`softmax(x)_i = e^{x_i} / Σ e^{x_j}`。直接算会溢出（fp16 上 `exp(11)` 就 inf）——**减最大值**：`softmax(x) = exp(x_i - m) / Σ exp(x_j - m)`，m = max(x)，结果不变（分子分母同乘 e^{-m}）且指数参数 ≤ 0。GPU 两遍/online 单遍实现在《[02 CUDA 编程题](./02-cuda-编程题.md)》Q2（含 3090 实测与 Triton 825GB/s 版本）；PyTorch 逐步推导版 `answers/attention/online_softmax.py`。追问 underflow：减 m 后若某值极小 exp 下溢为 0，属于正常（该类概率本来就 ≈ 0）；log-softmax 场景直接用 logsumexp 保持精度。

## 38. 卷积算子的优化方法

**（三星-一面-3 算子 9）**

五条路线（详见《[03](./03-gemm与算子优化.md)》Q14）：**im2col + GEMM**（展开成矩阵乘复用极致 GEMM，框架默认路径，代价是展开的显存/访存）；**implicit GEMM + NHWC + Tensor Core**（把 im2col 地址计算内嵌装载、不物化展开矩阵，cudnn 快速路径）；**Winograd**（3×3 s=1 乘法 36→16，理论 2.25×）；**直接卷积**（小通道/特定 shape）；**FFT**（大 kernel 少用）。加上 **conv+BN+ReLU 融合**（《03》Q13）。C++ 手写 Conv2D 可跑版本：`solutions/cpp/src/vision.cpp`。
