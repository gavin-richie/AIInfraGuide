## Q1. 概述大模型的训练流程（一2 Q8）

三阶段 + 工程视角：

1. **预训练**：next-token prediction，万亿级 token，BF16 混合精度，分布式（DP+TP+PP+EP+ZeRO，见 [07](./07-分布式训练.md) Q12）；产出 base 模型；
2. **SFT（指令微调）**：构造 `<system/user/assistant>` 多轮模板，**loss 只保留 response 段**（prompt mask），几万~百万级高质量指令数据；对拍实现 `solutions/python/src/answers/torch_impl/sft_loss.py`；
3. **偏好对齐**：RLHF（RM + PPO）/ DPO / **GRPO + 可验证奖励**（数学/代码场景主流，见 Q17-Q21）；
4. 工程主线：数据 pipeline（Q2）→ 稳定性（loss spike 处置、梯度范数监控、warmup+余弦调度）→ 评测（ppl/MMLU/代码/安全）→ checkpoint 与容错。

讲项目时按"数据—并行策略—吞吐指标（MFU）—稳定性—评测"五段最清晰。

## Q2. 预训练阶段常用的数据清洗方法（一1 Q5）

- **抽取与格式**：boilerplate 去除（网页正文抽取）、PDF/HTML 解析、语言识别（fastText/LID）；
- **启发式过滤**：长度、符号/重复率（n-gram 重复占比）、特殊字符比例、平均词长、停用词密度；
- **质量模型**：小分类器给页面打分（如 fastText/BERT 质量分、LLM 打分蒸馏），概率阈值筛除；
- **去重**：精确去重（hash）→ 近似去重（MinHash+LSH）→ 语义/嵌入去重（重复数据严重的过拟合与记忆风险）；
- **安全**：毒性、PII 脱敏、广告/色情过滤；
- **去污染**：与评测 benchmark 做 n-gram 重叠剔除（否则评测虚高）；
- **配比与课程**：domain 配比实验（web/code/math/arxiv 权重）、长度分桶、质量-数量权衡（Phi"教科书数据"路线）。

## Q3. 大模型训练和推理过程中显存不足，有哪些优化方案？（一2 Q9 开放题）

**训练侧**（详见 [07 分布式训练](./07-分布式训练.md) Q3 ZeRO 三阶段）：

1. 显存构成先算清：参数 + 梯度 + 优化器状态（Adam 是参数的 2×4 字节）+ 激活；
2. **ZeRO-1/2/3**：优化器状态/梯度/参数分片，3 显存换通信；**offload** 到 CPU/NVMe；
3. **激活重计算**（选择性重算 attention/MLP 结构段）；**序列并行**（长序列必配，见 Q4）；
4. 精度：BF16 训练、8bit 优化器（bnb）、梯度累积代替大 batch；
5. 结构：GQA/共享 embedding、MoE 稀疏激活。

**推理侧**：量化（W4A16 见 [30](./30-阿里-推理与量化.md) Q14、KV FP8/INT4）、GQA/MLA 缩 KV、PagedAttention 消碎片、prefix cache、CPU offload 分层、PD 分离（KV 卸到解码池）、batch 上限与滑窗控制。

## Q4. 多轮对话场景下，超长上下文的训练方案有哪些？（实2 Q1）

1. **序列并行**：DeepSpeed Ulysses（头维切分 + All-to-All）与 Ring Attention（序列切块环形传递 KV，计算通信重叠）——长序列显存/通信主手段，常与 TP/ZeRO 组合（[07](./07-分布式训练.md) Q11）；
2. **位置编码扩展**：RoPE 外推——linear/position interpolation、NTK-aware scaling、YaRN（高频外推低频内插）；ABF 调 base；长上下文继续预训练（短→长课程）；
3. **数据工程**：长文档拼接保持上下文连贯、多轮对话模板（历史轮次 mask、只训 assistant）、长度分桶减少 padding 浪费；
4. **注意力效率**：FlashAttention（[04](./04-attention与kvcache.md) Q1）、滑窗/稀疏注意力降低 $O(L^2)$；
5. **多轮特有问题**：跨轮指代/省略的数据质量、超长对话的 loss 尖刺、system prompt 缓存复用（训练层面截断策略）。

## Q5. MoE 模型和多模态模型的训练，还有哪些可优化的方向？（实1 Q2）

**MoE**：负载均衡（无辅助损失的 bias 调整、EPLB 专家动态复制，见 Q12）、EP 通信（DeepEP 两跳 all-to-all 与计算重叠、fp8 传输）、容量因子调度、专家切分粒度（细粒度专家 + 共享专家）、router z-loss 稳定、推理侧专家权重驻存/换入换出。
**多模态**：视觉编码器分辨率/长宽比课程（NaViT 动态分辨率）、模态对齐数据配比、投影层设计（见 [32](./32-阿里-多模态与agent.md) Q2）、统一 token 化（video/audio）、训练效率（ViT 与 LLM 混合并行的负载均衡、视觉 token 压缩/token merging）、灾难性遗忘（纯文本能力回放）。

## Q6. 大模型预训练与强化学习训练在工程实践上还有哪些值得优化的环节？（实1 Q3）

**预训练**：数据 pipeline 吞吐（预处理不落盘、实时流式）、异步 checkpoint（秒级快照 + 故障恢复）、慢节点检测与弹性训练、MFU 每日回归、loss spike 自动回滚、通配符级评测看板。
**RL（RLHF/GRPO）**：**rollout 引擎与训练引擎解耦**（vLLM 生成 + FSDP/Megatron 训练，权重同步机制是核心难点）、rollout 吞吐（投机解码、KV 复用 prefix）、**样本效率**（重要性采样倍数、clip 下多 epoch）、KL/ref 模型常驻显存的卸载（只在算 KL 时加载）、数据流（异步优势计算、训练-生成比调度）、可验证 reward 的防作弊（test 越狱、格式 reward 与正确性 reward 分离）。

## Q7. MoE 架构中，专家路由是针对每个 token 还是每个序列？（一1 Q2）

主流（Mixtral、DeepSeekMoE、Qwen-MoE）是 **per-token**：router 对每个 token 的隐状态独立打分取 top-k，同序列不同 token 可去不同专家——细粒度组合能力来源。对比：per-sequence/静态路由（整段共享一组专家）省去序列内多次 dispatch、对推理友好，但表达能力受限制，研究性质居多。追问点：per-token 路由 → 训练/推理不一致问题（容量截断只在训练生效）、EP 下 token 重排开销（见 Q12）。

## Q8. 如何判断 MoE 模型真正实现了专家分工协作，而不是把 Dense 模型做了参数切分？（阿1 Q11）

（同族 [03](./03-gemm与算子优化.md) Q10，阿里这题聚焦"分工的度量"）：

1. **负载分布**：专家利用率熵/基尼系数——均匀 ≠ 分工（切分的特征恰是均匀），要叠加条件分布看；
2. **条件激活分析**：统计 expert 激活对 token 类型/领域（code/math/多语言/位置）的条件分布，出现稳定"专家特化"（某专家对某 domain 概率显著偏高）即分工证据；
3. **可替换性消融**：随机重路由/关闭某专家，看掉点是否集中在特定子群（分工：局部塌陷；切分：各处均匀小掉点）；
4. **组合多样性**：top-k 组合数与共现矩阵的结构性（切分模型组合分布接近独立均匀）；
5. **共享专家**的职责检验（承载通用表征，负载高且稳定）。

## Q9. RL + MoE 训练中 reward 引导路由偏差的问题与应对（阿1 Q12）

现象：策略为追逐更高 reward，rollout 分布漂移 → 大部分 token 涌向少数"高奖励捷径"专家，负载坍缩、capacity 截断丢 token，且训练（有容量截断）与推理（无截断）行为不一致，最终能力塌陷。应对：

1. **负载均衡约束**：无辅助损失的 bias-gated 均衡（DeepSeek-V3，梯度不过 bias）、aux loss 权重退火、router z-loss；
2. **EPLB**：按统计冗余复制热点专家（物理扩容而非惩罚路由），比惩罚更直接；
3. **容量与丢 token 监控**：放宽 capacity factor、统计 dropped-token 比例并设阈值告警；
4. **reward 侧防作弊**：可验证奖励 + 格式奖励分离，去掉可被 hack 的 proxy reward；
5. **评测一致性**：评测时关闭容量截断，train/eval 路由分布对齐校验。

（RL 场景 MoE 全景见 [03](./03-gemm与算子优化.md) Q10。）

## Q10. RL 场景下 MoE 模型的优化经验（阿1 Q9）

与 [03 GEMM 与算子优化](./03-gemm与算子优化.md) Q10 同题：rollout 小 batch + 策略漂移下的路由动态性（EPLB/动态容量/lost-token 控制）、EP dispatch/combine 与反向重叠（DeepEP fp8-RDMA、Two-Batch Overlap）、推理引擎 EP + 专家预取、TP×EP 混合避免小 batch 单专家加载瓶颈。阿里面试喜欢追问"训练与推理两个引擎的 MoE 配置如何对齐"（router 精度、容量截断、专家并行数一致性）。

## Q11. 千卡集群出现 NCCL Timeout，如何定位与解决？（阿1 Q3）

与 [03](./03-gemm与算子优化.md) Q9 同题，要点复述：**先找"谁没到集合通信点"**——NCCL_DEBUG=INFO 对齐各 rank 的 collective 序列找卡住者；py-spy dump Python 栈（最快）、gdb attach C++ 栈；常见根因按概率排序：某 rank OOM/进程死（log 尾 traceback）、慢卡（ECC 降频/抢占/时钟，nvidia-smi）、网络（IB flap/PFC 风暴/拓扑 fallback）、逻辑 bug（条件分支导致多调/少调通信）、dataloader 卡死。止损：`TORCH_NCCL_ASYNC_ERROR_HANDLING=1` 超时抛异常 + elastic restart；预防：分层拓扑检测（`nccl topo`）、通信超时按作业规模分级配置。

## Q12. Expert Parallelism 中 Dispatch 和 Combine 的具体流程（控 Q1）

EP 把不同专家放不同 rank，一层 MoE 前向两次 all-to-all（详见 [07](./07-分布式训练.md) Q2 通信原语、Q8 DeepSeek-V3）：

1. **Router**：本 rank 对 batch 内每个 token 打分 top-k，得到 `(token → expert_id, gate_weight)` 列表；
2. **Dispatch（all-to-all #1）**：按目标 expert 所属 rank 重排 token（可能按容量 padding），把 `(隐状态, gate 权重, 位置元数据)` 发往对应 rank——通信量 ∝ token 数 × top-k × hidden（DeepEP 走 RDMA、可用 fp8 压半）；
3. **专家计算**：每个 rank 对收到的 token 逐 expert 做 FFN（组内专家太大可再叠 TP），乘 gate 权重；
4. **Combine（all-to-all #2）**：结果发回原 rank，按元数据**还原原 token 顺序**并把 top-k 输出加权求和。
性能关键：两次 all-to-all 与计算重叠（hook/Two-Batch Overlap）、容量控制丢 token、dispatch 用低精度。反向则把两跳镜像执行。

## Q13. DeepSeek 系列模型的架构特点（控 Q2）

与 [07 分布式训练](./07-分布式训练.md) Q8 同题，六个关键词：

1. **MLA**：KV 低秩压缩 + 权重吸收，decode 访存近 MQA、质量近 MHA（[30](./30-阿里-推理与量化.md) Q8）；
2. **DeepSeekMoE**：细粒度专家 + 共享专家，激活参数少（V3：671B 总参/37B 激活）；
3. **无辅助损失的负载均衡**：bias 微调均衡、不污染梯度；
4. **MTP**：多 token 预测模块，训练提表征、推理做投机解码（[30](./30-阿里-推理与量化.md) Q18）；
5. **FP8 混合精度训练**：细粒度分块缩放（128×128 block），H800 上训练成本大幅下降；
6. **通信**：DualPipe/两批重叠把 EP 的 all-to-all 藏进计算；limit 跨节点带宽依赖（约束下的工程极致）。

## Q14. 多卡协同的卡间通信方式、NVLink 与 RDMA 的特点（云二1 Q5）

**方式分层**：机内——NVLink/NVSwitch（GPU 专用互连，H100 900 GB/s 全双工聚合、NVSwitch 全拓扑无阻塞）、PCIe P2P（受限 root complex）、单机多进程共享内存/CUDA IPC；机间——InfiniBand/RoCE 的 RDMA（GPUDirect RDMA 使网卡直接读写显存，绕过 CPU 与系统内存拷贝）、传统 TCP/以太网（NCCL 兜底路径，慢一个量级）。
**NVLink 特点**：带宽最高、延迟最低（<1μs 级）、cache 一致性（C2C/NVLink-C2C 连 CPU）、但距离/规模受限（机内）；**RDMA 特点**：内核旁路零拷贝、远端内存 verbs（write/read/send）、200/400 Gb/s 级、适合机间大块传输；时延高于 NVLink，长肥网络需调优。工程含义：TP 困在 NVLink 域（[30](./30-阿里-推理与量化.md) Q17 的 AllReduce 每层在关键路径），EP/PP 大块通信可跨机走 RDMA；NCCL 按 `nccl topo` 自动选环/树。

## Q15. Transformer 相比 RNN 的核心优势？Transformer 是否存在 Scaling Law？（校 Q1）

**优势**：① **训练并行**——RNN 沿时间步递归无法并行（序列是串行依赖），Transformer 全序列一次矩阵乘，吃满 GPU；② **长程依赖**——attention 任意两位置直接连边（路径长 O(1)），RNN 信息要逐步传递 O(L) 且梯度随路径衰减/爆炸；③ **统一算子**（matmul+attention）对硬件与编译优化友好；④ 位置信息显式注入（PE）而非隐式状态。RNN（及其变体 LSTM/GRU）的剩余优势：推理 $O(1)$ 状态、流式天然、参数少。
**Scaling Law**：存在——损失随参数量 N、数据量 D、算力 C 呈幂律 $L = L_\infty + (C_0/C)^{\alpha}$（Kaplan 2020；Chinchilla 2022 修正：固定算力下 20 token/参数最优配比）；Transformer 是首个把该规律做实的架构，也是它统治的根因。追问常延伸：推理侧 scaling（o1/R1 的 test-time compute）、数据质量打破配比（过训 Llama-3 15T token）。

## Q16. ResNet / Transformer 中残差连接的作用，展开分析（一2 Q5）

1. **梯度高速公路**：$y = F(x) + x$，$\partial y/\partial x = F'(x) + 1$，恒等项让梯度无衰减直通浅层——解决深层网络的梯度消失，使百层/千层可训练（ResNet 之前 56 层反而比 20 层差）；
2. **优化景观**：残差让网络只需学"相对目标的修正"（residual），损失面更平滑、深层网络退化为恒等映射也至少不差（Ensemble/valiant 浅层网络集成视角，Veit et al.）；
3. **Transformer 的 residual stream**：每层向"信息流"里读写，LayerNorm 稳定幅度；多头/MLP 都是对 stream 的增量修改——这也是机械可解释性（残差流分解）的基础框架；
4. 消融视角：去掉残差，Transformer 超过 ~10 层即难训；Post-LN → Pre-LN 的迁移也与残差路径稳定有关。

## Q17. 【重点】GRPO 与 PPO 的核心区别（淘2 Q1）

一句话：**GRPO 去掉 value 网络，用"同 prompt 组内奖励标准化"代替 GAE 优势估计，其余（策略梯度 + clip + KL）保留**。

| 维度 | PPO | GRPO（DeepSeekMath, 2024） |
|---|---|---|
| 优势估计 | Critic 网络 + GAE（TD-error 指数加权） | $A_i = (r_i - \mathrm{mean}(r_g))/\mathrm{std}(r_g)$，组内相对优势 |
| 额外网络 | value model（与策略同量级，LLM 下显存/计算翻倍） | 无（ref 模型可按需加载算 KL） |
| 奖励形态 | 标量 reward 即可（可稠密） | 序列级标量（常为可验证 reward：对错/格式），组内要有分辨性 |
| baseline | 学出来的 $V(s)$（逐 token 精细） | 组均值（粗但无偏、免训练） |
| KL 处理 | 通常无（或 reward 内惩罚） | loss 显式加 $\beta \cdot \hat{D}_{KL}(\pi_\theta\|\pi_{ref})$（k3 估计，见 Q19） |
| 代价 | 训练 critic 昂贵、critic 学不好拖垮策略 | 样本开销大（每 prompt 采 G 个）、全同奖励组无梯度、组内基线方差比 GAE 高 |

为什么 LLM 场景 GRPO 胜出：① value 网络与 70B 策略同规模，显存与算力不可接受；② 可验证任务奖励只在序列末尾，逐 token credit assignment 靠 critic 不可靠，组对比天然给出序列级信号；③ 工程链路短（vLLM 采样 + 轻量训练循环）。工程变体：重要性采样 clip（off-policy 多 epoch）、Dr. GRPO（去掉 std 归一化的长度偏差修正）、DAPO（clip-higher/动态采样）。

**可运行实现**：`solutions/python/src/answers/alibaba/grpo.py`（`grpo_group_advantage` / `ppo_clipped_surrogate` / `grpo_loss` / `k3_kl_estimator`），验证：`cd solutions/python && python -m pytest tests/test_alibaba.py -q -k "grpo or ppo or kl or ratio or masked"`。

## Q18. PPO 中 Clip 操作的具体作用（淘2 Q2）

目标：$L = \mathbb{E}[\min(r_t A_t,\ \mathrm{clip}(r_t, 1-\epsilon, 1+\epsilon)A_t)]$，$r_t = \pi_\theta/\pi_{\theta_{old}}$。

- **动机**：单步更新太大 → 策略偏离采样分布，重要性采样失效、性能崩塌。TRPO 用 KL 约束（二阶求解）保证信任域；PPO 用 clip 做"一阶、廉价的信任域"；
- **非对称截断**：$A>0$（好动作）时 $r$ 超过 $1+\epsilon$ 后 loss 不再下降 → **封顶**，防贪心猛推；$A<0$（坏动作）时 $r$ 低于 $1-\epsilon$ 后 → **托底**，防过度惩罚一个已经远离的动作；信任域内 $[\,1-\epsilon, 1+\epsilon\,]$ 梯度照常；
- **梯度行为**：截断生效处梯度为 0（min 选中 clip 支路）——这是"限制更新幅度"的直译，测试里可直接验证（`test_ppo_clip_blocks_gradient_outside_trust_region`）；
- $\epsilon$ 常取 0.1-0.3；注意 clip 只约束"单样本单步"，不保证全局 KL 小（所以有 PPO-penalty 变体改用自适应 KL 系数）。

## Q19. 重要性采样的作用？与 KL 散度约束更新的区别？（淘2 Q3）

**作用**（除配合 clip 限制更新幅度外）：

1. **off-policy 样本复用**：一批 rollout 跑多个 epoch 更新（on-policy 每步重采样太贵），用 $r=\pi_\theta/\pi_{old}$ 修正在"错误分布"下的期望——$\mathbb{E}_{x\sim p}[f] = \mathbb{E}_{x\sim q}[\frac{p}{q}f]$；
2. **难分布采样**：从易采样的 proposal 估计难解析目标分布的期望（如 reward 校正、CIS、变分推断 ELOBO）；
3. **方差缩减/负样本挖掘**（推荐系统 hard-negative 按重要性重加权）。

**与 KL 约束的区别**：clip 是**逐样本、对 ratio 的硬截断**（梯度级、局部、实现最简单，但截断处不可导信息丢弃，且不直接控制分布距离）；KL penalty 是**分布级、软约束**（$\beta \cdot \mathrm{KL}(\pi\|\pi_{ref})$ 连续可导、可自适应调 β、直接度量两个策略的差异），TRPO 是其硬约束版本（KL ≤ δ）。实践中 GRPO 用 k3 估计把 KL 加进 loss（$\hat{D}_{KL}$ 逐点非负、无偏低，`k3_kl_estimator`），PPO 系用 clip——两者常常组合出现（clip 限单步 + KL 限整体漂移）。

## Q20. 什么是马尔可夫性质？给出形式化定义（淘2 Q4）

若状态的转移只依赖当前状态与动作，而与历史路径无关，则过程具有马尔可夫性：

$$P(s_{t+1} = s' \mid s_t = s, a_t = a, s_{t-1}, \dots, s_0, a_{t-1}, \dots, a_0) = P(s_{t+1} = s' \mid s_t = s, a_t = a)$$

即**状态是历史的充分统计量**（state subsumes history）。MDP $(S, A, P, R, \gamma)$ 成立的前提；策略梯度/PPO/GRPO 的推导都建立在转移与奖励的马尔可夫性上。追问：LLM 的 RL 里"状态"是什么——**已生成 token 序列**（完整上下文），天然满足马尔可夫性（下一个 token 分布只由当前序列决定）；POMDP 对应"观测不完整"场景（如只看摘要生成）。GRPO 不依赖状态价值函数，只用序列级回报，对部分可观测更鲁棒。

## Q21. 从早期策略梯度到 GRPO，哪些模块被保留、哪些被舍弃？（淘2 Q5）

**保留的主干**（策略梯度定理一脉相承）：

$$\nabla J(\theta) = \mathbb{E}[\nabla_\theta \log \pi_\theta(a_t|s_t) \cdot \Psi_t]$$

① 对数概率梯度方向；② **优势/相对好坏信号** $\Psi_t$（从整条 return → baseline 减方差 → GAE，一直是"中心化的回报"）；③ 重要性采样 ratio（off-policy 化后保留至今）；④ 单步更新幅度约束的思想（TRPO 一脉）。

**被舍弃/替换的**：

| 阶段 | 引入 | 后续命运 |
|---|---|---|
| REINFORCE | Monte Carlo return | 方差大 → 被 baseline/GAE 替换 |
| Actor-Critic | 学习 value 网络 | LLM 下代价过高 → **GRPO 用组内均值 baseline 舍弃 critic** |
| TRPO | KL 信任域（二阶/共轭梯度） | 实现复杂 → PPO **clip**（一阶） |
| PPO | clip + GAE | 保留 clip；GAE 随 critic 一起被舍弃 |
| GRPO | 组相对优势 + 显式 KL（k3）+ 可验证奖励 | 当前 LLM RL 主线 |

**演进原因**：每一步都是"保持无偏/低偏差的前提下砍成本"——砍二阶求解（TRPO→PPO）、砍 critic 显存与计算（PPO→GRPO）、砍 RM 的不可验证性（RLHF→RLVR）。

## Q22. 算力受限条件下，如何用大模型蒸馏出 3B 小模型？（云二2 Q5 开放题）

蒸馏原理见 [11 深度学习与训练](./11-深度学习与训练.md) Q6；算力受限下的实操路线：

1. **数据蒸馏优先**（最省算力）：大模型批量生成指令-回答数据（多采样 + **拒绝采样**保留高质量）、self-instruct/evol-instruct 扩增、难度分层与领域配比（通用:代码:数学）；配合去重（MinHash）与规则校验（答案可验证的保留）；
2. **logits/分布蒸馏**（中等算力）：小模型 KL 拟合大模型 soft distribution（温度 T），可在公开语料上离线蒸（无需大模型在线推理参与训练循环）；CoT 蒸馏（长推理链数据 + 截断长度课程）；
3. **训练配方**：SFT（蒸数据）→ DPO/GRPO 轻量对齐（3B 上 RL 便宜）→ 领域加强（金融/代码专项）；混合 replay 防通用能力遗忘；
4. **系统侧省算力**：序列打包、BF16、梯度检查点、LoRA 蒸馏（冻结底座只蒸 adapter）再合并；
5. **评测卡点**：蒸馏数据质量抽检 + 通用 benchmark 不回退 + 目标领域专项集。

## Q23. 生成式推荐的基本思路（校 Q5）

把推荐从"判别式打分检索"改为**条件生成**：用户历史（交互序列）作为条件，目标 item 编码为 **Semantic ID（SID）**，模型自回归生成下一个 item 的 SID token 序列，beam search 直接"检索"出 item。收益：① 一次生成可覆盖全库（免维护近邻索引）；② SID 层级语义（RQ-VAE 码本）带来泛化（相似 item 前缀共享，冷启动友好）；③ 与 LLM/生成式范式统一（可接指令、可解释）。代表：TIGER（Google）、阿里后续的生成式召回工作；与判别式双塔的对比（召回效率、精确匹配 vs 泛化）是常追问点。

## Q24. SID（Semantic ID）的训练流程是怎样的？（校 Q6）

两阶段：

1. **SID 构造（RQ-VAE）**：对每个 item 的内容表征（标题/描述/多模态 embedding，来自 BERT/多模态编码器）训练 **Residual Quantized VAE**——向量经 encoder 到 latent，逐级量化：第 1 级 codebook 粗分（语义大类），残差再进第 2 级细分……得到层级码 $(c_1, c_2, c_3)$ 即 SID；codebook 用 EMA 更新，训练完可离线给全库 item 打 SID；
2. **生成式模型训练**：把用户历史 item 的 **SID token 序列**作为输入（item → 多个 SID token 展开），目标 item 的 SID 作为输出，encoder-decoder（T5 类）teacher forcing + 交叉熵训练；通常对各层 code 都加辅助损失；
3. **推理**：beam search 生成 SID → 前缀树/Trie 约束到合法 SID 集合（避免生成不存在的组合）→ 映射回 item 候选，交排序层。

## Q25. Tiger 为何没有采用 Decoder-Only 的架构形式？（校 Q7）

TIGER 用的是 **encoder-decoder（T5 类）**，理由：

1. **输入输出异构**：输入是"用户历史 SID 序列"（集合/序列语义，需要**双向编码**充分表征用户兴趣），输出是"目标 item 的 SID token"（自回归生成）——decoder-only 强迫历史侧也走单向注意力，每个历史 token 只能看到左侧，历史表征打折；
2. **Cross-attention 的对齐优势**：decoder 每步生成都通过 cross-attention 直接读取 encoder 输出的完整历史表征，比 decoder-only 里"目标 token 隔着整段历史做因果注意力"的路径更短；
3. **任务形态是 seq2seq**：与 TIGER 的前身（生成式检索的 Spartan/DSI）一脉，T5 预训练权重可直接复用。
   补充：decoder-only 并非不可用（后续工作证明统一 decoder + 适当 packing 也能做），面试表达"编码侧需要双向、生成侧需要自回归，enc-dec 天然匹配该任务"即可。

## Q26. 新闻推荐任务中正负样本如何确定？（校 Q10）

- **正样本**：曝光且点击（展现日志 join 点击日志）；时长/完读/互动可升级为多目标正样本（点击 vs 深度消费分开建模，ESMM/MMoE）；
- **负样本**：**曝光未点击**为主——注意其中混着"曝光了但没看到"（位置偏差）：用位置作为特征/倾向分纠正（IPW）、或首屏以上才算真负；
- **采样策略**：训练时负样本通常远多 → 负采样控制正负比（1:3~1:10）；召回阶段要用 easy + hard negative 混合（随机/未曝光 + 热门item），排序阶段用曝光空间内的真实负；
- **防泄漏**：按时间严格切分（特征与样本同刻）、序列特征只用历史窗口；
- **延迟反馈**：转化类目标当日未转化 ≠ 负样本（ESMM/延迟反馈建模）；新闻场景的时效性（新 item 冷启动、内容衰减）要单独设计。

## Q27. 交叉熵损失函数的定义及其在分类中的作用（云二 Q1、实一二·二面 Q2）

$$H(p, q) = -\sum_i p_i \log q_i$$，真实分布 $p$（one-hot 时退化为 $-\log q_y$），预测 $q$（softmax 输出）。作用：① 度量两个分布差异，最小化 CE = 最大化似然（MLE）；② 与 softmax 组合后梯度为 $\partial L/\partial z = q - p$——**无饱和、无梯度消失**（对比 MSE+sigmoid 的饱和小梯度）；③ one-hot 时 $H(p,q) = H(p) + \mathrm{KL}(p\|q)$，交叉熵之差即 KL，有信息论解释。二分类 BCE 是其两类特例；LLM 训练的 next-token loss = 词典上的 softmax CE（实现 `solutions/python/src/answers/torch_impl/sft_loss.py`）。

## Q28. Logistic 回归的公式、模型原理与损失函数（云二 Q2、云二2 Q2）

**模型**：线性打分再 sigmoid 概率化——$P(y=1|x) = \sigma(w^\top x + b) = \frac{1}{1+e^{-(w^\top x+b)}}$，决策 $\sigma\ge 0.5$ 即 $w^\top x+b \ge 0$（线性决策面）；$\sigma$ 把实数映射到概率且保持单调。

**损失**：伯努利分布的负对数似然（= 二分类交叉熵）：

$$L = -\frac{1}{n}\sum_i \left[y_i \log \hat{y}_i + (1-y_i)\log(1-\hat{y}_i)\right]$$

对 $z=w^\top x+b$ 的梯度恰为 $\frac{1}{n}\sum (\hat{y}_i - y_i)x_i$（与线性回归 MSE 同形、无饱和），是凸函数、有唯一最优；对数几率 $\log\frac{p}{1-p} = w^\top x+b$ 线性 → "对数线性模型"。追问常连 MSE 为何不用（非凸 + 梯度饱和）、与 SVM 的区别（概率输出/损失软硬、边界样本影响）、softmax 回归是其多类推广。

## Q29. GAN 和 CVAE 的基本原理与区别（实一二·二面 Q4）

**GAN**：生成器 $G$ 从噪声造样本，判别器 $D$ 区分真假，minmax 博弈 $\min_G \max_D \mathbb{E}[\log D(x)] + \mathbb{E}[\log(1-D(G(z)))]$；最优时 $p_g = p_{data}$（JS 散度视角）。**隐式生成**（无显似然）、样本锐利，但训练不稳（模式崩塌、博弈失衡）。
**CVAE**：变分自编码器加条件：encoder 把 $x$（条件 $c$ 下）编码为后验 $q(z|x,c)$，decoder 重建 $p(x|z,c)$，损失 ELBO = 重构项 + $\mathrm{KL}(q(z|x,c)\|p(z|c))$；显式的潜变量结构、训练稳定（单一目标），但重构偏模糊（高斯假设 + 采样方差）。
**区别一句话**：GAN 用对抗拟合隐式分布（锐利但不稳、无似然），CVAE 用变分下界优化显式潜变量模型（稳定可评估、但模糊）；采样时 GAN 直接 $G(z)$，CVAE 从先验采 $z$ 再 decode。两者常被追问联系：都是 $p(x)$ 建模的近似路线，对抗与变分可互补（VQ-VAE-2/扩散模型是后续统一者）。

## Q30. 时间序列数据：ML 方法筛选特征 + 规则方法建模（云二 Q5、云二2 Q4 开放题）

流程模板（按"探索→特征→筛选→融合规则"答）：

1. **EDA**：平稳性检验（ADF）、趋势/季节分解（STL）、自相关（ACF/PACF）定 lag 阶数、异常点定位；
2. **特征工程**：lag/rolling 统计量（均值/标准差/极值）、差分与增长率、日历特征（周几/节假日/时段）、外部协变量（促销/天气）、目标编码；
3. **ML 特征筛选**：树模型（GBDT/XGBoost）的 gain importance 与 permutation importance（更抗偏）、L1 稀疏选择、互信息/相关性过滤、null importance（打乱标签对比，防泄漏假特征）；时序必须**按时间切分**验证（防未来信息泄漏）；
4. **规则层融合**：ML 输出概率 + 业务规则后处理——阈值/分档规则、趋势突变规则（环比阈值）、专家先验硬约束（上下限、季节性强制）、**规则兜底 ML 未覆盖区**（新类目/极端值）；冲突时以规则为准并记录回流供后续训练；
5. 模型选择：表格特征为主选 GBDT，长序列依赖试 LSTM/TFT/时序基础模型；上线后做特征漂移监控。

## Q31. 【编程】手写 SVM 的核心实现（实一二·二面 Q6）

核心：hinge loss $L = C\cdot\mathrm{mean}(\max(0, 1-y(wx+b))) + \frac{1}{2}\|w\|^2$（$y\in\{-1,+1\}$），次梯度下降——margin≥1 的样本只贡献正则梯度，margin<1 的样本贡献 $-y_ix_i$ 项；预测 $\mathrm{sign}(wx+b)$；非线性靠核技巧（预计算 Gram 后在对偶空间训练）。

- 代码位置：`solutions/python/src/answers/alibaba/svm.py`（`hinge_loss` / `LinearSVM`（Pegasos 风格子梯度下降）/ `rbf_kernel` / `make_separable_blobs`）
- 验证命令：`cd solutions/python && python -m pytest tests/test_alibaba.py -q -k svm`
- 手写示例（内嵌，面试白板版）：

```python
class SVM:                       # 次梯度下降, y ∈ {-1, +1}
    def fit(self, X, y, lr=0.1, C=1.0, epochs=200):
        self.w, self.b = torch.zeros(X.shape[1]), 0.0
        for _ in range(epochs):
            margin = y * (X @ self.w + self.b)
            viol = margin < 1.0                    # 违反间隔的样本集
            grad_w = self.w - (C / len(y)) * ((X * y[:, None])[viol]).sum(0)
            grad_b = -(C / len(y)) * y[viol].sum()
            self.w -= lr * grad_w; self.b -= lr * grad_b
    def predict(self, X):
        return torch.where(X @ self.w + self.b >= 0, 1.0, -1.0)
```
