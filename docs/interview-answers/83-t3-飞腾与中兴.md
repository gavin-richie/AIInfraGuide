# 飞腾（实习 一面）

## Q1. 进程与线程的区别；Cache 层级与替换策略

**（飞腾 一面 1）**

**进程 vs 线程**（《[09 篇](./09-cpp与系统基础.md)》Q18）：进程是**资源分配单位**（独立虚拟地址空间、文件描述符表），线程是**调度执行单位**（共享所在进程的地址空间/全局变量/fd，私有栈/寄存器/PC）。切换开销：进程要换页表（TLB 失效）远贵于线程；隔离性：进程崩溃不互相牵连，线程一个段错误全进程完蛋；通信：进程要 IPC（管道/共享内存/socket），线程共享内存但要锁。选择：稳定性/多机用多进程（PyTorch dataloader 正是因 Python GIL 用多进程），高吞吐共享数据用多线程。

**Cache 层级**：L1d/L1i（每核，32-64KB，~4 cycle）→ L2（每核私有，256KB-2MB，~12 cycle）→ L3（全核共享，几 MB-上百 MB，~40 cycle）→ 内存（~200-300 cycle）；GPU 侧 L1/smem + L2 的对应关系见《[01 篇](./01-cuda-基础与体系结构.md)》Q6。**替换策略**：理想 LRU（缓存友好但硬件贵）→ 实际多用 **PLRU（伪 LRU，树形位标记）**和**随机替换**（大容量下与 LRU 差距 <2%，抗scan 攻击更好）；写策略：write-back（脏行驱逐时才写回）+ write-allocate 为主流。**缺失三分类**： compulsory（冷启动）/ capacity（放不下）/ conflict（组相联冲突——关联度不够时同组互相踢）。GPU 面试延伸：L2 128B line，跨 block 复用靠数据布局与调度顺序。

## Q2. FP16/FP32/FP64 的位宽分配

**（飞腾 一面 2）**

IEEE 754 浮点 = **符号位 S + 指数位 E + 尾数位 M**，值为 `(−1)^S × 1.M × 2^(E−bias)`：

| 格式 | S | E | M | 总位 | 动态范围 | 有效数字 |
|---|---|---|---|---|---|---|
| **FP16** 半精度 | 1 | 5 | 10 | 16 | ±6.1e-5 ~ 65504 | ~3.3 位十进制 |
| **BF16**（对比必说） | 1 | 8 | 7 | 16 | 与 FP32 同（±3.4e38） | ~2.4 位 |
| **FP32** 单精度 | 1 | 8 | 23 | 32 | ±1.2e-38 ~ 3.4e38 | ~7.2 位 |
| **FP64** 双精度 | 1 | 11 | 52 | 64 | ±2.2e-308 | ~15.9 位 |

要点：**指数位决定范围、尾数位决定精度**——FP16 范围窄是训练溢出（>65504 即 inf）的根源，BF16 砍尾数保指数所以训练稳（免 loss scaling）；E 全 1 且 M≠0 是 NaN、M=0 是 ±Inf；denormal（次正规数）补下溢间隙但硬件慢（可被 FTZ 冲刷）。FP8（E4M3/E5M2）与 FP4 见《[06 量化](./06-量化.md)》Q5。

## Q3. 快排的执行流程；堆的基本性质；拓扑排序适用场景

**（飞腾 一面 3、三星 Q24/Q32 同族）**

**快排**：选 pivot → partition（小于/大于两段，双指针一次线性扫描）→ 两段递归。平均 O(n log n)、最坏 O(n²)（有序输入 + 首元素 pivot），不稳定，原地 O(log n) 递归栈。工程优化：三数取中防最坏、小段切换插入排序、尾递归化控制栈深、三路划分（大量重复值）。实现：`algorithms/sorting.py::quick_sort / quick_sort_inplace`。

**堆**：**完全二叉树** + 父子有序（大根堆：父 ≥ 子）。数组隐式存储：`parent(i)=(i−1)/2`，`children: 2i+1, 2i+2`。建堆自底向上 O(n)（下沉 n/2 个节点）；插入/删除 O(log n)。TopK 应用见《[81 篇](./81-t3-国产gpu厂商.md)》Q10（求最大 K 个用**小根堆**）。

**拓扑排序**：**DAG 上的依赖排序**（每条边 u→v 保证 u 在前）。适用：编译单元依赖、算子/任务调度、课程表、包管理器安装顺序。Kahn 入度法 / DFS 逆后序，O(V+E)，实现见 `algorithms/graphs.py::topo_sort_kahn/dfs`（《[80 篇](./80-t3-英伟达与三星.md)》Q32 有完整代码）。

## Q4. Decoder-only 结构的特点；QKV 的生成过程；位置编码的嵌入时机

**（飞腾 一面 4）**

**Decoder-only 特点**：只保留 Transformer 的解码器栈（去掉 cross-attention），**因果掩码**使位置 i 只看 ≤i——与自回归生成天然匹配（训练时一次前向并行预测全部 next-token，训练效率比 encoder-decoder 高一个量级）、参数全部用于序列建模、scaling law 最优、zero/few-shot 涌现。代表：GPT/Llama/Qwen 全系。

**QKV 生成**：输入 `x ∈ (B,S,d)` 经过三个线性投影 `W_q, W_k, W_v ∈ (d, H·d_h)`（GQA 下 `W_k/W_v` 只输出 `n_kv·d_h`，拷贝共享到 `n_q` 个查询头）→ reshape 成 `(B,H,S,d_h)` 分头 → 计算 `softmax(QKᵀ/√d_h)V` → 合并头 → 输出投影 `W_o`。一次 QKV 融合投影（`cat[W_q,W_k,W_v]` 一个 GEMM）是标配优化。

**位置编码的嵌入时机**（本题的区分度所在）：

- **绝对位置编码**（learned/sinusoidal，BERT/GPT-2）：加在**输入 embedding 上**（进 block 之前，`x = tok_emb(x) + pos_emb(pos)`），之后 QKV 投影自然携带位置信息；
- **RoPE（现代主流）**：**在 Q/K 投影之后、算 attention score 之前**施加——把 Q/K 向量按二维子空间逐对旋转角度 θ_i·pos，使 `⟨q_m, k_n⟩` 只依赖相对位置 m−n；**V 不加位置**（值本身不需要位置偏置）。一次性的好处：外推性更好、不受序列长度训练限制（配合 NTK/YaRN 缩放）。

一句话：**绝对位置编"进输入"，RoPE 编"进注意力"**——答出这个对比基本稳了。

## Q5. RMSNorm 的公式、计算访存特性与优化角度

**（飞腾 一面 5）**

$$\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}} \odot \gamma$$

对比 LayerNorm：去掉均值中心化与 β 偏置，**少一遍归约、少一次减法**，快 ~10-60%（Llama 选它的原因），效果不掉。

**计算访存特性**：每行（token）读一遍 x 求 ms（mean square）→ 再读一遍做归一化写回——**memory bound**（算术强度 <2 FLOP/Byte，远低于机器平衡点）；朴素实现 HBM 读 2 遍写 1 遍，带宽就是天花板。

**优化角度**（题面给的三个提示逐个答）：

1. **负载均衡**：每行等长 → 天然均衡，一行一个 warp/block（`solutions/cuda/src/norm.cu` 的 RMSNorm kernel 即此）；**变长 batch**（打包不同长度 token）时按行起始偏移分配 block，防尾块倾斜；
2. **Double Buffer / 数据驻留**：第一遍的 x 缓存在 smem/寄存器，第二遍不再读 HBM（HBM 流量 3 遍 → 2 遍：读 1 + 写 1）；进一步与下游算子融合（RMSNorm+QKV 投影一个 kernel），中间张量完全不落 HBM；
3. **指令替换**：`1/sqrt` 用 `rsqrtf`（SFU 一条指令，精度 2 ulp 内；`__expf` 同理见《[01 篇](./01-cuda-基础与体系结构.md)》Q16）；`x*x` 用 FMA 累加、`#pragma unroll` 展开；float4 向量化装载；
4. 补充：归约用 warp shuffle 免 smem（行内 ≤1024 时单 warp 可做完两遍归约）。

实现对照：`solutions/cuda/src/norm.cu`（LayerNorm/RMSNorm，ctest 对拍）与 Triton 版 `answers/triton_kernels/layernorm.py`。

## Q6. Softmax 数值稳定性；Online Softmax 原理

**（飞腾 一面 6，三星/太初/后摩同族）**

**数值稳定**：减最大值 m=max(x)——`exp(x−m)` 指数参数 ≤0 不溢出，分母至少含 exp(0)=1 不为 0；结果与不减时数学等价。fp16 下尤其致命（exp(11)≈60000 已近上限）。**Online Softmax**：把"max → sum → normalize"三遍合成**单遍流式**——维护运行最大 m 与运行和 l，新块 x̃ 到来时：

$$m_{new}=\max(m_{old},\max\tilde{x}),\qquad l_{new}=l_{old}\,e^{m_{old}-m_{new}}+\sum_j e^{\tilde{x}_j-m_{new}}$$

历史部分和按 `e^{m_old−m_new}` 重缩放——这正是 FlashAttention 不物化整个 S 矩阵的数学基础。完整推导（PyTorch 逐步版 `answers/attention/online_softmax.py`）与 CUDA/Triton 实现见《[02 篇](./02-cuda-编程题.md)》Q2。

## Q7. 矩阵乘与反量化融合算子在内存方面的有哪些优化策略

**（飞腾 一面 7）**

即 W4A16/W8A16 的 **dequant-in-kernel** GEMM（理论见《[06 量化](./06-量化.md)》Q2 Marlin 三件套），内存侧策略分层答：

1. **消灭中间张量**：朴素流程"反量化全量权重 → GEMM"要额外 写+读 全尺寸 FP16 权重（显存 2N 遍）；融合后解包发生在**寄存器内**，装一块解一块用一块，HBM 只读 4bit 原始数据——**这是融合的本体收益**；
2. **读路径**：int4 打包成 int32/int128 布局，**按消费端的 tile 访问模式预排**（Marlin 全局重排：线程交错 + K 维交错），一次 128b 装载 = 32 个 int4 权重，摊薄地址计算；scale/zero 与对应权重 tile **同址存放**（L2 局部性）；
3. **解包成本**：LOP3 位操作（三条指令 8×int4→FP16），避免逐位 shift/分支；解包与 mma 双缓冲流水重叠；
4. **写出**：累加器 FP16/BF16、epilogue 融合 bias/激活避免再读回；
5. **量化粒度带来的内存放大**：per-group(128) scale 的存储 (~1/128×2B) 与随机访问要靠与权重同 tile 布局消化。

收益量级：decode（memory bound）下 W4 的权重读取字节 ÷4 → 瘦 GEMM 近 4× 带宽收益（cuBLAS FP16 的 3-4× 速度即 Marlin 的战绩）。

## Q8. SpMV 如何实现负载均衡与带宽优化

**（飞腾 一面 8）**

SpMV（稀疏矩阵 × 向量，`y = A·x`，A 用 CSR：`row_ptr/col_idx/val`）的难点：**行长极度不均**（一行可能 10 个也可能 10 万个非零）+ **间接寻址 x[col_idx]**（无合并访存、缓存不友好）。

**负载均衡**：
1. **按行分配的分层策略**：短行一个 warp 串行内积（warp 内 shuffle 归约）、中行长 `warp-per-row`（每 lane 承担一段 K）、超长行 `block-per-row` 甚至**行切分**（split-row，多个 block 各算一段再 atomic/二段合并）——运行时按 `row_ptr[i+1]−row_ptr[i]` 分派（light/heavy 双 kernel 简化版）；
2. **merge-path**（Bell & Garrison / Merrill）：把"行 × 行内偏移"展平成全局等大的工作单元，block 按二分搜索认领等量非零元——理论最优均衡；
3. **coo 排序/重排**：行列重排（对称置换）聚拢块状结构。

**带宽优化**：①**Blocked CSR/ELLPACK**：按 block 对齐存储（同 block 内 dense），val/col 连续装载 + x 的 block 常驻 smem/L2，间接访存变规则；②**向量化**：对 block 内 dense 部分用 float4/mma；③**x 预取/重排**：`__ldg`、按 col 排序提升局部性；④**格式选择**：ELL 适合均匀稀疏、CSR+Scalar 适合超稀疏、HYB 混合；⑤长度信息 `row_ptr` 差分用 `__ldg` 只读缓存。GNN/推荐场景的 grouped GEMM 是 SpMM 的现代延伸。

## Q9. Git 拉取远程分支：fetch+checkout 与 pull 的区别

**（飞腾 一面 10）**

```bash
git fetch origin && git checkout -b feat origin/feat   # 或 git switch feat（自动跟踪）
git pull [--rebase]                                    # = fetch + merge（或 rebase）
```

**fetch** 只把远端提交下载到 `origin/*` 远程跟踪分支，**不动工作区**——可以先 `git log HEAD..origin/main` 审查再决定怎么合；**checkout/switch** 基于远程分支建本地跟踪分支。**pull** 是 `fetch + merge`（默认）——直接改本地分支，有分歧就产生 merge commit；`--rebase` 变基使历史线性（团队 PR 流一般要求 rebase）。**选择**：要审查/多人协作/历史干净 → fetch + rebase；快速同步自己独占分支 → pull。冲突处理差异：merge 冲突一次解决产生 merge commit；rebase 冲突逐提交解决历史线性。

## Q10. 虚函数底层机制与 vtable 工作原理

**（飞腾 二面 1，太初 Q4 基础上的加深）**

**布局**：每个含虚函数的类一张 **vtable**（编译器生成，常驻 .rodata）：按声明序排列的虚函数指针 + 开头的 typeinfo（RTTI/dynamic_cast 用）+ offset-to-top（多继承 this 调整）；每个对象在**起始处（或各基类子对象处）藏一个 vptr**，构造时由构造函数写入（先基类后派生类——这正是构造中调虚函数绑定到当前层的根因，《[82 篇](./82-t3-cpp与系统.md)》太初 Q4）。

**调用**：`p->virt()` → `(*(void***)p)[idx](p)`——两次间接寻址（取 vptr、取函数指针）+ this 传参。**多继承**：对象内多个 vptr，第二个基类接口调用要经 **thunk** 调整 this 偏移；**虚继承**再加 vbase offset 表。代价：间接跳转阻止内联/优化 + 一次访存（vtable 通常在 cache，代价可控）。**追问防线**：为什么析构要虚（delete 基类指针时按 vtable 找到派生析构，否则只析构基类部分 = UB，《09》Q8）；虚函数能 inline 吗（编译期知道确切类型可以，`final`/devirtualization 帮编译器）；构造函数不能虚（机制+语义，见《[80 篇](./80-t3-英伟达与三星.md)》Q22）。

## Q11. 编译过程的四个阶段

**（飞腾 二面 2）**

`hello.c → 预处理 → 编译 → 汇编 → 链接 → 可执行`：

1. **预处理**（`gcc -E` → .i）：宏展开、头文件包含、条件编译（#if）、去注释——纯文本替换（这一步与三星"宏注册算子"联动：静态对象在此后按编译单元初始化）；
2. **编译**（`-S` → .s）：词法/语法/语义分析 → IR 优化（内联/常量折叠/循环优化）→ 生成**汇编代码**；
3. **汇编**（`-c` → .o）：汇编器把 .s 翻成机器码，产出**可重定位目标文件**（.text/.data/.bss/符号表/重定位表；函数符号此时地址未定）；
4. **链接**（ld → a.out）：**符号解析**（每个引用绑定到一个定义，找不到 = link error；重复定义 = 冲突）+ **重定位**（按最终地址改写 call/jmp/数据引用）；静态链接整段拷贝，动态链接只记录对 .so 的依赖（加载时/延迟绑定 PLT/GOT）。

一张图记住 gcc 背后的工具：`cpp → cc1 → as → ld`。动态/静态库、C++ 调 C 的 extern "C" 见《[09 篇](./09-cpp与系统基础.md)》Q17。

## Q12. 常见设计模式；单例与工厂的应用场景

**（飞腾 二面 3）**

**单例场景**：全局**只应存在一份**且有初始化顺序风险的东西——配置中心、日志器、线程池、驱动句柄/上下文（CUDA context、内存池）。实现与陷阱见《[10 篇](./10-cpp编程题.md)》Q6、DCL 隐患见《[82 篇](./82-t3-cpp与系统.md)》北极雄芯 Q4。

**工厂场景**：**创建逻辑与使用逻辑解耦**——调用方只给类型标识，不 new 具体类：框架按 op 名造算子（注册宏 + 工厂，三星《[80 篇](./80-t3-英伟达与三星.md)》Q28 是同一题的工程版）、按设备类型造 backend、按形状策略选 kernel 变体。**抽象工厂**再升一级（一族相关对象：CPU 工厂产 CPU tensor+CPU kernel）。其余高频：观察者（事件总线）、策略（kernel 调度策略可换）、适配器（旧接口包装）、装饰器、享元。

## Q13. 多进程与多线程的主要区别

**（飞腾 二面 4，一面 Q1 的决策版）**

记忆锚：**进程=资源隔离（稳但通信贵），线程=资源共享（快但要同步）**。决策表：崩溃隔离/安全边界/多机 → 多进程；高频共享数据/低延迟切换 → 多线程；Python 受 GIL 限制 CPU 密集必须多进程（IO 密集多线程可行，《09》Q19）；GPU 训练栈典型组合：**dataloader 多进程**（CPU 预处理）+ **训练主进程多线程**（CUDA stream 各自提交）。完整对照见本篇 Q1 与《[09 篇](./09-cpp与系统基础.md)》Q18。

## Q14. 针对特定 shape 的算子调优：如何超越官方库

**（飞腾 二面 5）**

官方库（cuBLAS/cudnn）为**通用性**付出的税，就是特化的空间。方法论五步：

1. **吃透 shape 与访问模式**：固定 shape → 一切尺寸变**编译期常量**：边界检查整个消失、tile 尺寸精确整除、`#pragma unroll` 全展开、寄存器分配最优；
2. **布局与预处理**：输入可以**离线预变换**（转置/pad/重打包成 kernel 最爱的布局，如 NHWC、int4 交织、weight 预排），税交一次收益每次；
3. **融合**：官方库边界处必须写回 HBM 的中间张量（GEMM 输出 → 激活 → 归约），特化 kernel 直接在寄存器/smem 传递（epilogue 融合 +bais/act/residual），省整段显存往返；
4. **专用指令与结构**：明确 shape 后可以选 `mma` 精确片段形状、split-K 固定段数、persistent kernel 固定 grid=SM 数、问题特有结构（对称性/稀疏/低秩）直接利用；
5. **暴力扫参数**：tile/block/stage 四元组在该 shape 下实测网格搜索（官方库是启发式，可能选不到你的最优）。

**验证与防过拟合**：对拍官方库结果（容差内）+ 在目标 shape 集合上全量 benchmark（防止只赢一个 shape、输入分布换了就输）+ 建立性能回归 CI。举例弹药：本仓库教学版 GEMM 在 1024³ 固定 shape 上 smem tiling 1.3×（《02 篇》Q3）；Marlin 在 batch≤32 的 decode shape 上 3-4× 于 cuBLAS（《06 篇》Q2）——都是"用 shape 特化打通用库"的实例。

## Q15. 融合算子的设计思路

**（飞腾 二面 6）**

**设计流程**：①**融合空间分析**——在计算图上找生产者-消费者 对，评估每对的收益 `(中间张量字节×2)/总耗时`；②**可行性判据**——数据可驻留（smem/寄存器装得下 tile）、并行度匹配（两个算子的并行维度能映射到同一 grid）、不炸寄存器/不涨 divergence；③**模式选择**（常见五类见《[80 篇](./80-t3-英伟达与三星.md)》Q35：elementwise 链、reduce+broadcast（norm 族）、GEMM+epilogue、dequant+GEMM、整个 attention）；④**同步与流水设计**——block 内 `__syncthreads()` 边界、双缓冲让两段重叠；⑤**验证**——数值对拍 + ncu 对比融合前后 SOL（确认访存下降而非被寄存器压力吃掉）。**反例意识**：融合变慢的五种情况（寄存器溢出/并行度不匹配/损失特化/smem 超限/本就 compute bound）见《[03 篇](./03-gemm与算子优化.md)》Q7——主动说出反例是加分项。

## Q16. 混合精度训练与推理的关键问题

**（飞腾 二面 7、中兴 Q6 同族）**

**训练**（FP16/BF16 计算 + FP32 主权重）：①**溢出/下溢**——FP16 范围窄：激活/梯度下溢是主要风险 → **loss scaling**（loss 乘 S 放大梯度，更新前再除回；S 动态调整）；BF16 范围同 FP32 免 scaling（A100 后首选）；②**精度保持**——权重主副本、优化器 m/v、loss/norm 的 reduce、softmax 累加保 FP32；③**舍入误差**——梯度累加用 FP32 累加器（Tensor Core 的 FP32 accumulate）；④**层差异化**——敏感层（norm/首尾层）保高精度。**推理**：量化（W8A8/W4A16/FP8）后精度评测链（ppl→下游→敏感 case，《[06 篇](./06-量化.md)》Q7）；KV Cache 与激活的动态范围处理。一句话：**训练怕数值范围（scaling/主权重），推理怕精度损失（校准/评测）**。

## Q18. KV Cache 的工作原理；FlashAttention 的内存优化核心思想

**（飞腾 二面 9）**

**KV Cache**：自回归 decode 每步只需新 token 的 Q，但 K/V 是**全部历史**的——缓存每层每头的 K/V 避免每步重算整个前缀（计算 O(S)→O(1)，代价是显存 O(S)）。大小公式：

$$\text{bytes} = 2 \times L \times n_{kv} \times d_h \times B \times S \times \text{dtype}$$

（Qwen-7B、B=1、S=2048、FP16 → 1.07GB；GQA 8 头 → 1/4；可算：`answers/t3/gpu_memory_estimator.py::kv_cache_bytes` 与 `answers/attention/gqa.py::kv_cache_size`）。优化全景（量化 FP8/INT4、GQA/MLA、PagedAttention 分页、prefix cache 复用、offload）见《[04 篇](./04-attention与kvcache.md)》Q7。

**FlashAttention 的核心思想**：标准 attention 要物化 `S = QKᵀ ∈ R^{S×S}`（显存 O(S²)、HBM 读写多遍）。FA 把 Q/K/V 切 block 装入 smem，**外层循环 Q 块、内层流式扫 K/V 块**，用 **online softmax**（运行 (m,l) 重缩放，见本篇 Q6）在从不物化 S 的情况下得到精确结果；输出逐块累加到 HBM。效果：显存 O(S²)→O(S)、HBM 访存约 ÷（S/BLOCK）量级、kernel 融合后实际更快。实现（v1/v2 与 SDPA 对拍）：`answers/attention/flash_attention.py`（《04》Q1）。

## Q22. 16 卡训 200B 的分布式方案设计

**（中兴 5，承接 Q21 的计算题）**

**先算账（面试官要的就是这个）**：200B 参数，混合精度 + Adam：

- 模型状态 16N = **3200GB**；ZeRO-3 均摊 16 卡 = 每卡 **200GB** > H100 80GB ❌——**纯 GPU 放不下，结论先行**；
- 还要留激活（B·S·L·34h，sequence 长/不加 checkpointing 时几十 GB）与通信 buffer。

**结论：16 卡（1-2 机）全参训练 200B 在显存上不可行，必须引入 offload；要么改任务形态**。诚实给出三条路线：

1. **ZeRO-Infinity（显存不够拿 CPU/NVMe 垫）**：ZeRO-3 + 优化器/参数 offload 到 CPU 内存（NVMe 兜底）——能跑，但每步参数要经 PCIe allgather，**MFU 掉到 <10%**，只适合实验验证不适合生产；加 ZeRO++（1-bit 通信）缓解跨机带宽；
2. **改训练形态**：全参 → **LoRA/QLoRA 微调**（可训权重 ≪1%，底座 4bit 常驻 ~100GB/16 卡=6.5GB/卡，完全可行）——业务上 200B 这个规模微调本来就以 PEFT 为主；
3. **承认规模错配并给出正确配置**（最加分）：200B 全参预训练业界至少 64-256 卡起步；若题目允许扩到 64 卡：TP=8（机内 NVLink）× PP=4（跨机）× DP=2 + ZeRO-1，模型状态 3200/64 = 50GB/卡 + 激活（开 checkpointing）勉强可跑；或 128 卡纯 ZeRO-3 更稳。

**答题结构**：算显存 → 指出不可行 → 给 offload/PEFT/扩卡三选一并说明代价 → 补充工程细节（activation checkpointing、1-bit 通信、梯度累积凑大 batch、容错 checkpoint）。测试断言了这个不可行结论：`tests/test_t3.py::test_training_memory_200b_16gpu_is_infeasible_without_offload`。

## Q26. 算子融合的原理及对性能的影响

**（中兴 9）**

**原理**：相邻算子的中间结果不写回 HBM——生产者在 smem/寄存器直接喂消费者。**性能影响**（正面）：省中间张量的写+读（每融合一个中间张量省 2 次全量 HBM 访问——memory bound 算子收益线性）；省 kernel launch 与同步间隙；数据驻留 smem 后访问模式可控（无 L2 竞争）。**代价与反例**：寄存器/smem 压力→occupancy 降甚至 spill、并行度不匹配、损失各自最优 tile、compute bound 算子融合无收益（《[03 篇](./03-gemm与算子优化.md)》Q5/Q6/Q7）。常见融合模式清单见《[80 篇](./80-t3-英伟达与三星.md)》Q35。

## Q27. Python 基础：数据结构、GIL、装饰器

**（中兴 10）**

**数据结构底层**：`list`（动态数组，均摊 O(1) 尾插，超配 1.125×/几何扩容）、`dict`（开放寻址哈希，插入序保证，key 必须可哈希）、`set`（哈希）、`tuple`（不可变，可作 dict key）、`str`（不可变）。可变/不可变与函数传参（对象引用传递）。**GIL**：全局解释器锁使同一时刻仅一个线程执行 Python 字节码——CPU 密集多线程无加速（用多进程），IO 密集多线程仍有效（等 IO 时释放 GIL）；numpy/torch 的 C 层计算会释放 GIL，`multiprocessing`/原生扩展绕开。完整版见《[09 篇](./09-cpp与系统基础.md)》Q19。**装饰器**：本质是**高阶函数**，`@deco` = `f = deco(f)`；带参装饰器再多一层嵌套 `deco(arg)(f)`；`functools.wraps` 保元数据；典型用途：计时、缓存（`@lru_cache`）、重试、注册路由（框架的路由表——与算子注册宏异曲同工）：

```python
import functools, time
def timed(fn):
    @functools.wraps(fn)
    def wrapper(*a, **kw):
        t0 = time.perf_counter()
        try:     return fn(*a, **kw)
        finally: print(f"{fn.__name__}: {time.perf_counter()-t0:.3f}s")
    return wrapper
```
