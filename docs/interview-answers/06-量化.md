## Q1. 量化技术分类与 INT8 对称/非对称量化（面经-1 DL 7、综合-7 Q8）

**分类**：
- 按 stage：**PTQ**（训练后量化，校准即可）vs **QAT**（量化感知训练，伪量化插入训练图，精度最好但成本高）；
- 按对象：Weight-Only（W8A16/W4A16）、Weight+Activation（W8A8）、KV Cache 量化、梯度量化（训练）；
- 按 granularity：per-tensor / per-channel / per-group（如 group=128）——粒度越细精度越高、存储/计算开销略升；
- 按格式：INT8/INT4、FP8（E4M3/E5M2）、FP4、混合精度（敏感层保留高精度）。

**对称量化**：$x_q = \mathrm{clamp}(\mathrm{round}(x/s)),\ s = \frac{\max|x|}{127}$，零点固定 0——反量化 $x \approx s \cdot x_q$。优点：去零点项，GEMM 可直接整数累加；缺点：动态范围不对称（如激活多为正）时浪费分辨率。

**非对称量化**：$s = \frac{x_{max}-x_{min}}{255},\ z = \mathrm{round}(-x_{min}/s)$，$x_q=\mathrm{round}(x/s)+z$——分辨率利用充分，但计算多一项零点校正（可吸收进 bias）。

**QAT 推理细节**：训练时 forward 用伪量化（quant-dequant）模拟误差，straight-through estimator 让 round 的梯度直通；推理时真整数 kernel + 反量化 scale 融合。

## Q2. Weight-Only 量化方案与 kernel 访存优化、Marlin（综合-2 基础 6）

**Weight-Only（W4A16/W8A16）**：权重压到 4/8bit，激活与计算保持 FP16。动机：decode 是 memory bound，收益主要来自**权重读取量减少**（W4 显存 1/4、带宽需求 1/4 → 瘦 GEMM 提速接近 4×）；代表：GPTQ、AWQ、HQQ（无校准）。

**kernel 访存优化要点**：
1. **反量化融合**：装载权重 tile → 解包（位操作 unpack 4bit→FP16）→ mma，全程寄存器/smem 内完成，不写回 HBM（"dequant in register"）；
2. **布局重排**：int4 打包成 int32，按后续 tile 访问模式预排（列主/交错），避免解包时的跨字节 gather；group scale/zero 与权重 tile 同址放（L2 友好）；
3. **向量化装载**：128bit/线程一次取 32 个 int4 权重，摊薄地址计算；
4. **K 维展开与双缓冲**：解包与 mma 流水线重叠。

**Marlin**（W4A16 高性能 GEMM kernel）：面向 batch ≤ 32 的 decode 场景，把 4bit 权重按**marlin 格式**全局重排（线程间交错、tile 内按 K 交错），装载即对齐 mma 片段形状；解包用 LOP3 位操作三指令完成 8×int4→FP16；配合 smem 双缓冲与异步拷贝，**速度≈FP16 cuBLAS 的 3-4×**（当 batch 小时），几乎无损吞吐。面试能讲"重排 + 位操作解包 + 融合 mma"三件套即可。

## Q3. GPTQ / AWQ / SmoothQuant 对比（百度-实习-一面-3、智谱）

| 方案 | 对象 | 核心思想 | 校准数据 | 特点 |
|---|---|---|---|---|
| **GPTQ** | 权重 | 逐列最小化逐层输出误差，Hessian 近似下贪心 + 误差补偿（OBQ 的工程化） | 需要（128 样本） | 精度好、量化慢（分钟级）；适合 W4 |
| **AWQ** | 权重+激活分布 | 激活大通道对应权重重要 → **per-channel 缩放保护**（等价变换 W,s 与激活缩放，不改输出） | 需要（统计激活 max） | 快、稳、不靠反向传播；W4 常用默认 |
| **SmoothQuant** | W8A8 | 难点在激活离群值 → 平滑因子 $s=\max|X|^\alpha/\max|W|^{1-\alpha}$ 把激活的量化难度**迁移**给权重（等价缩放） | 需要 | 让 per-tensor INT8 全模型可行 |

共同点：都是"**在等价变换空间里找更好量化配置**"，不重训练；差异在误差度量（输出 MSE / 激活分布）与可变换自由度。

## Q4. 量化粒度与校准方法（智谱、蚂蚁、遂原）

- **粒度**：per-tensor（1 组 scale，最快/最粗）→ per-channel（输出通道一组，W8 主流）→ per-group（如 128 元素一组，W4 必须，精度再升）；离群值越多越需要细粒度。
- **minmax 校准**：直接取 $\max$——快但对离群值敏感；
- **percentile**：取 99.9% 分位截断离群——折中；
- **KL 散度校准（TensorRT 经典）**：搜索截断阈值 T，使截断前后的分布 P/Q 的 KL 最小（信息论意义下最保分布）；
- **MSE 校准**：网格搜索 scale 使逐层输出 MSE 最小（GPTQ 的近亲）。
- 手写两种校准：`solutions/python/src/answers/algorithms/` 未含（纯张量操作），可直接写 20 行：percentile = `torch.quantile(|x|, q)`；KL 版对 |x| 直方图按阈值二分/枚举计算 KL 取 argmin——面试常现场手写（智谱真题）。

## Q5. FP8 与 FP4（蚂蚁-三面、智谱 NV FP4、遂原 A100/H100 支持）

- **FP8 E4M3**（4 指数 3 尾数，动态范围小、精度高）→ 权重与前向激活；**E5M2**（5 指数，范围大）→ 梯度/反向。Hopper 起有 FP8 Tensor Core（1979 TFLOPS dense），训练推理都可用；per-tensor 的 **delayed scaling**（维护历史 amax 滑动最大）解决动态范围。
- **NV FP4**（E2M1 + 2bit scale（E4M3）×16 元素块）：Blackwell 的原生格式。scale 维度：**每 16 个元素一个 block scale**（向量级），比 per-channel 细得多——这是 FP4 可用的关键（纯 per-channel E2M1 精度不够）。
- KV Cache 量化：FP8 KV 几乎无损（per-head/per-block scale），INT4 KV 需要非对称 + 离群保护（KIVI：按 key 通道/ value token 分别处理）。
- A100：无 FP8 硬件（支持 INT8 TC 与 BF16）；H100：FP8；B200/GB200：FP4。

## Q6. 量化异常值处理（百度-实习-一面-3、摩尔线程 -10000 离群）

1. ** SmoothQuant 迁移**（见 Q3）；
2. **细粒度分组**：离群集中在少数通道 → per-group/per-channel 圈住；
3. **混合精度**：离群层/通道保留 FP16（LLM.int8 的 outlier 分解：0.5% 离群列走 FP16，其余 INT8）；
4. **clip 策略**：percentile/KL 截断（Q4）；
5. 极端场景（-10000 这类超大离群）：先做 **log/clip 变换**或把离群通道显式抽出到旁路（gemm 拆两块）。

## Q7. 量化收益怎么算、何时无收益（字节-校招-1 量化收益）

- 权重量化收益：显存 ∝ 位宽；decode 加速比 ≈ min(带宽收益, 计算收益)——memory bound 时接近位数比，compute bound（大 batch prefill）时无加速甚至更慢（解包开销）。
- 激活量化（W8A8）：主要收益在大 batch/长序列的计算受限场景（INT8 TC 2× 于 FP16）。
- KV 量化：批间共享 KV 命中率越高收益越大（L2/显存压力下降）。
- 精度评测链：ppl → 下游 benchmark（MMLU/GSM8K）→ 长文本/重复类敏感 case；PPL 正常但下游掉的"隐性损失"要专门测。
