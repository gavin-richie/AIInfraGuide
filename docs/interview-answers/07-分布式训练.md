## Q1. All-Reduce 通信开销推导（综合-5 Q4）

**Ring AllReduce**（NCCL 主用）分两阶段：

- **Reduce-scatter**：N 卡环，每卡把数据分 N 份，传 N-1 轮，每轮传 $\Psi/N$（$\Psi$ 为总字节），结束后每卡持有完整归约结果的一份分片；
- **All-gather**：再把 N 个分片转一圈，每轮同样 $\Psi/N$，N-1 轮。

$$\text{每卡通信量} = 2\Psi\frac{N-1}{N} \approx 2\Psi\quad(\text{与卡数无关！})$$

$$\text{墙钟时间} \approx 2(N-1)\cdot\frac{\Psi/N}{B_{link}}\ \ (\text{链路瓶颈侧};\ \text{机间要除以双向带宽因子})$$

树形（Tree）AllReduce：$O(\Psi\log N)$ 但延迟低，小消息快；NCCL 按消息大小自动选 Ring/Tree/双环。

**推导要点**（面试常要求现场写）：注意"每卡发送量"与"时间"的区别，环算法的精髓是**把总量摊到 N 段链路上流水**。

## Q2. NCCL 通信原语与一次参数更新的通信次数（综合-3 Q11）

原语：`Broadcast / Reduce / All-Reduce / All-Gather / Reduce-Scatter / All-to-All / Scatter / Gather`（后两个多为逻辑层）。

**DP 一次 step（DDP 梯度桶式）**：每个 bucket 一次 **AllReduce**（融合的 reduce-scatter+allgather），假设 bucket 数为 k，则 k 次 AllReduce；从"逻辑原语"计 = 每参数 2×(N-1)/N 通信量。**ZeRO-2** 用 **Reduce-Scatter**（梯度分片）替代 → 通信量减半；**ZeRO-3** 前向再 All-Gather 权重（每层 2 次：fwd/bwd）。

## Q3. ZeRO Stage 1/2/3 通信量差异与"论文与代码的差距"（综合-2 基础 8、中兴）

显存（FP16 混合精度、参数量 N、优化器状态 12N（Adam fp32 m/v + fp32 master）+ 梯度 2N + 参数 2N）：

| Stage | 切分对象 | 单卡显存 | 通信量 |
|---|---|---|---|
| DDP | 无 | 16N | 2Ψ |
| ZeRO-1 | 优化器状态 | 4N + 12N/d | 2Ψ（RS+AG 桶化后不变） |
| ZeRO-2 | +梯度 | 2N + 14N/d | 2Ψ → 实现用 RS 替代 RS+AG 的一半 → ≈2Ψ |
| ZeRO-3 | +参数 | 16N/d | 3Ψ（fwd AG + bwd AG + bwd RS） |

论文口径：ZeRO-1/2 与 DDP 通信量相同、ZeRO-3 增加 1.5×。**代码差距**：①实现里 ZeRO-1/2 的 bucket AllReduce 仍是 2Ψ（论文假设的 RS 替代需要 contiguous grad buffer 配合，DeepSpeed 的 `reduce_scatter` 配置项决定是否真减半）；②ZeRO-3 的 prefetch/层级通信（NVLink 域内 RS + 域间 AG）会改变实际字节；③offload 到 CPU 还会引入 PCIe 流量。回答"知道有差距 + 说得出哪一项"即可。

## Q4. TP 先按列切还是先按行切（综合-5 Q6）

Megatron 的层内切分约定：

- **f(x)=xA^T**（Attention 的 QKV）：A 按列切（A=[A1,A2]）→ 各卡算 [xA1^T, xA2^T] 即各持一部分输出列 → f 需要 **All-Gather**（或保持"分列"直接进下一算子）。
- **f(x)=A x**（FFN 第二层）：A 按行切 → 各卡算部分和 → 需要 **All-Reduce**（部分和相加）。
- 标准组合（两次线性层夹一次非线性）：Y = GeLU(XA)B —— A 列切、B 行切：**All-Reduce 从 4 次降为 2 次**（非线性挡住了部分结果的直接相加，中间结果天然分片无需通信），这是 Megatron TP 的关键设计。
- 结论表述：列切让输出可并行无通信（partial 输出拼接）、行切产生部分和必须 reduce；切分方式决定通信原语（AG vs AR）与次数。

## Q5. Megatron-LM 的通信优化与序列并行（综合-3 Q5、综合-2 基础 7）

- **TP 通信优化**：上述列/行切把每层 AllReduce 从 4 次（fwd 2 + bwd 2）压到 2 次；进一步的 overlap：通信与计算分桶流水（scatter-gather 通信器）、层次化 allreduce（先 NVLink 域再跨机）。
- **序列并行（SP）**：在 TP 基础上把**序列维**也切开（LayerNorm/Dropout 等非权重算子的激活按 S 切分到各 TP 卡），fwd/bwd 的 AllReduce 变为 **Reduce-Scatter + All-Gather**（总量不变！），但 LN 等的激活显存降为 1/tp；与 TP 一起把大模型的 activation 内存压下来，是与 context parallel 不同的正交维度（SP 管 LN 激活，CP 管长序列 attention）。

## Q6. Two-Batch Overlap 与负优化场景（综合-3 Q4）

把一个 step 的 batch 切成两个 micro-batch，micro-batch A 的**通信**与 micro-batch B 的**计算**重叠（DualPipe/DeepSeek 的双向流水更进一步，把 PP 气泡也吃掉）。

**负优化场景**：
1. micro-batch 太小 → 单 batch 计算本身吃不满 SM，切两半后 kernel 效率更低，重叠收益抵不过开销；
2. 通信占比本来就低（NVLink 单机、小模型）→ 重叠省的时间 < 调度与同步开销；
3. 显存翻倍压力（两份 micro-batch 激活同时驻留）触发重计算 → 总时间反而涨；
4. 依赖强的场景（MoE dispatch 与本 batch 计算强耦合）时拆批破坏通信-计算配对。

## Q7. Muon 与 AdamW 为何不能在 pretrain/post-train 间混用（综合-3 Q7）

- **Muon**：对动量矩阵做 Newton-Schulz 正交化（近似正交化梯度方向）再更新，隐式学习率谱与 Adam 的逐元素尺度完全不同（按矩阵谱归一而非元素归一）。
- Pretrain 阶段（大规模同分布、损失面平滑假设）与 post-train（SFT/RL，小数据大步长、易过拟合）的曲率差异大；混用意味着更新量的量纲/尺度规则中途改变——Muon 的正交化把每步更新限制在固定谱半径，切回 Adam 会突然失去该约束（或反之），等效于灾难性的有效学习率跳变。
- 稳妥做法：post-train 沿用 pretrain 优化器并降低 lr，或专门做 optimizer state 的 warm restart；两个阶段都用 Muon 是一致的（Kimi/Moonshot 实践）。

## Q8. DeepSeek-V3 关键优化点（综合-3 Q9）

1. **MLA**：KV 压缩 + 权重吸收（KV Cache 降为 MHA 的 ~1/10 量级）；
2. **DeepSeekMoE + 无辅助损失负载均衡**（bias 调节 + 丢 token 策略），细粒度专家 + 共享专家；
3. **FP8 混合精度训练**（细粒度块量化 + 提高累加精度）；
4. **MTP（多 token 预测）**：一个隐藏分支同时预测下 2 个 token，训练信号更密 + 推理可投机解码加速；
5. **DualPipeOverlapping**：计算-通信双向重叠（EP 场景）；
6. **FP8 GEMM/三层矩阵吸收的 decode kernel**、sailfish 式低精度传输。加分项：DSA/NSA（见 Q9）、Yarn 长文本。

## Q9. DSA / NSA / MoBA 的区别（综合-3 Q10）

都是 DeepSeek 系/开源的**稀疏注意力**（NSA=Native Sparse Attention（DeepSeek-V3.2/训练友好）、MoBA= mixture-of-blocks attention（月之暗面）、DSA=DeepSeek Sparse Attention（NSA 后继，硬件对齐））：

- 共同范式：把 KV 按块（block）组织，用轻量路由/打分选出 top-k 相关块，只做稀疏 attention → 复杂度从 O(S²) 降到 O(S·k·block)。
- **MoBA**：门控网络（利用当前 query 的中间表示）选择 KV 块，块粒度可变（top-k gating），训练可微。
- **NSA**：**硬件对齐的原生稀疏**——块选择 + token 级压缩 + 稀疏 kernel 融合（选择、聚合一次 kernel 完成），训练推理一致、可从预训练就用稀疏。
- **DSA**：把"选择"变成可训练的确定性结构（如 index-based 静态稀疏 + 训练时学到的稀疏模式），进一步降低训练-推理不一致与 kernel 复杂度。
- 区别记忆点：MoBA=门控选块；NSA=硬件友好的块稀疏+压缩+融合 kernel；DSA=确定性稀疏模式（后继演进）。

## Q10. 小数据量 NVSHMEM 直接读 vs Ring All-Reduce（综合-3 Q12）

小消息下 Ring 的固定开销（N-1 轮启动延迟、每轮同步）远大于带宽收益：

- Ring 时间 ≈ 2(N-1)·(latency + Ψ/(N·B))，Ψ 小时被 latency 主导；
- **NVSHMEM one-shot**：每卡直接 RDMA 读其他卡的输入（N-1 次 get），本地归约 → 时间 ≈ latency + Ψ/B + 归约计算，一轮完成、无逐跳流水。
- 适用边界：Ψ 小（KB~MB 级）、要求低延迟（同步屏障、RL 的 reward 聚合、EP 小 batch 的 dispatch）；大数据量下带宽受限于"每卡同时收到 N-1 份"的入向带宽，仍需 Ring/Tree。

## Q11. 超长序列的并行策略设计（综合-3 Q13）

组合拳（按瓶颈选）：

1. **Context Parallel（CP）**：序列切分，attention 内部用 Ring/Load-balance 的 KV 交换（ULLS/DeepSeek-UVLin 类），解决 activation 显存与单卡 S 上限；
2. **TP+SP**：层内切分吃满 NVLink 带宽，SP 压 LN 激活；
3. **ZeRO-3 + 激活重算（checkpointing）**：基线显存手段；长序列下激活重算比例要精细控制（选择性重算 attention softmax 部分）；
4. **CPU offload 与 3D 并行组合**（DP×CP×PP/EP），小 EP 域内用 NVLink all-to-all；
5. 数据侧：序列打包/样本切分避免 padding、flash-attn 的 varlen 支持。

## Q12. 分布式训练原理与框架 / DeepSpeed 核心功能（综合-7 Q2/3）

- 原理：数据并行（梯度同步）、模型并行（TP/PP）、序列/专家并行的组合 + 通信库（NCCL/HCCL）+ 容错（elastic）。
- 框架：Megatron-LM（3D 并行参考实现）、DeepSpeed（ZeRO + offload + 弹性）、FSDP（PyTorch 原生 ZeRO-3 类）、Colossal-AI、Angel/盘古类。
- DeepSpeed 核心：ZeRO 1/2/3、ZeRO-Offload/Infinity（CPU/NVMe 卸载）、ZeRO++（1-bit 通信量化、分层 allgather）、混合精度、pipeline 并行、MoE 支持、activation checkpointing、elastic training。

## Q13. 训练慢排查 / 通信瓶颈 / loss 震荡 / 梯度累加（综合-7 Q5/6/10/7）

**训练慢排查**（按层剥）：
1. 单卡 MFU：profiler 看 kernel 占比（是否 FA？是否重计算过多？数据加载饿 GPU？）；
2. 多卡：等待时间线（NCCL wait 占比）→ 通信/负载不均/straggler（某卡慢：ECC 降频、co-locating 任务、数据倾斜）；
3. 系统：CPU dataloader（num_workers）、存储 IO、page cache、网络 pflip。
通信瓶颈优化：大桶 AllReduce 与计算重叠、层级通信、拓扑感知（NVLink 域内 TP）、ZeRO/PP 重组、压缩（1-bit/FP8 梯度）。

**loss 震荡原因**：lr 过大/调度 bug、数据分布突变（shuffle 不充分/脏数据）、batch 内长尾样本、混合精度 loss scale 抖动、梯度裁剪阈值不当、某卡数值异常（参数损坏、NaN 传播）、MoE 路由塌缩、断点续训 optimizer 状态没恢复。

**梯度累加**：小 batch 多次前向、梯度累加到同一 `.grad`，第 k 次才做 zero_grad+step；通信等价于大 batch DP（bucket 的 no_sync 控制），与 optimizer.step 的频率解耦——省通信不省计算；注意与 BN/LN 统计、loss 平均（÷accum_steps）配合。

## Q14. 训练/推理效率的时间与资源两维度（综合-7 Q4）

- 时间维度：MFU/吞吐（tokens/s）↑：kernel 优化、并行策略、通信重叠、算法（MTP/distill）。
- 资源维度：单卡显存/能耗/成本 ↓：ZeRO、重算、offload、量化、弹性调度（闲时抢占）。
- 两者平衡的度量：**每 token 成本**（$/M tokens）与**收敛所需总 FLOPs**（算法效率）相乘才是总拥有成本。

## Q15. Ampere → Hopper 算子迁移改造（综合-3 Q14）

1. **TMA（`cp.async.bulk.tensor`）** 替代逐线程 LDG：异步、多维 tile 描述符、绕过 L1 可选——装载代码重写；
2. **Warp Specialization + mbarrier**：producer/consumer 分工（FA3/GEMM 结构性改造，见《GEMM 与算子优化》Q8）；
3. **FP8 Tensor Core**：量化 kernel 适配（scale 融合）；
4. **wgmma（warp group mma）** 替代 mma.sync：异步指令、寄存器-寄存器输出，调度逻辑重排；
5. **smem 100→228KB**：tile 可以加大（要调 launch bounds 与 occupancy 的平衡）；
6. 频率/SM 数变化 → grid 配置与 split-k 策略重新 autotune；
7. 指令延迟模型不同 → 流水线 stage 数（cp.async 多级缓冲）需要重新调。
