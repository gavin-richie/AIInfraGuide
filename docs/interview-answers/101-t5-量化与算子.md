## 一、量化与数值格式

### Q1. FP8 两种格式 E4M3 与 E5M2 的区别与计算方式（飞星 Q2，重点题）

**位格式**（OCP FP8 标准）：

| | E4M3 | E5M2 |
|---|---|---|
| 位分配 | 1 符号 + 4 指数(bias=7) + 3 尾数 | 1 符号 + 5 指数(bias=15) + 2 尾数 |
| 规格化数 | $(-1)^s 2^{e-7} 1.m$ | $(-1)^s 2^{e-15} 1.m$ |
| 次正规数 | $2^{-6} \times 0.m$（最小 $2^{-9}$） | $2^{-14} \times 0.m$（最小 $2^{-16}$） |
| 最大有限值 | **448**（$2^8×1.75$；指数全 1 只留尾数全 1 作 NaN，无 Inf） | **57344**（$2^{15}×1.75$；指数全 1 是 ±Inf/NaN） |
| 相对精度 | 尾数 3 位 → ~6.25% | 尾数 2 位 → ~12.5% |
| 适用 | 权重/激活/KV Cache（动态范围小、精度重要） | 梯度（动态范围大、精度可让） |

**计算方式**：FP8 只是**存储/传输格式**，运算遵守"FP8 输入 → 高精度乘累加 → （可选）缩放回 FP8 存储"：

1. 量化：$x_{fp8} = Q(x / s)$，$s = \mathrm{amax}/448$（或 57344），舍入用 RNE（round-to-nearest-even）；
2. Tensor Core 把两个 FP8 矩阵相乘、**累加进 FP16/FP32 寄存器**（绝不直接 FP8 累加——e4m3 只有 3 位尾数，累加几步就崩）；
3. 输出按需反量化（乘回 $s_a s_b$）或继续以 FP8 存下一层输入。

**软件模拟与验证**：`solutions/python/src/answers/t5/fp8.py` 实现了位级编解码（含次正规数、RNE、饱和）、W8A8 GEMM 模拟，并与 `torch.float8_e4m3fn` 对拍一致：

```bash
cd solutions/python && pytest tests/test_t5.py -k fp8 -v
# 已知位模式: 1.0 = 0_0111_000 (E4M3); E4M3 饱和 1000→448, E5M2 →1024
# 同数据下 E4M3 的 GEMM 误差 < E5M2（尾数多一位）
```

### Q2. NVIDIA GPU 对 FP8 的硬件优化（飞星 Q1）

1. **FP8 Tensor Core**（Hopper 起，Transformer Engine 驱动）：同一周期 FP8 吞吐 = 2×FP16（H100 SXM：1979 vs 989 TFLOPS）——乘法器位宽变短省下的面积换密度；
2. **Transformer Engine**：每个 GEMM 自动选 FP8/FP16（按激活分布动态范围），per-tensor/per-block scaling 计算 + 转换在 tensor core 旁的硬件完成；
3. **高精度累加**：FP8 输入在 Tensor Core 内部以 FP32/FP16 累加（软件可见的 accumulate 精度），保证数值下限；
4. **Blackwell 进一步**：FP4（NVFP4/MXFP4，2×FP8）、microscaling（MX）块缩放格式硬件支持；FP8 与 TMA/异步搬运配合保持 Tensor Core 喂数据；
5. 显存/带宽红利：FP8 存储**减半**权重与 KV 的搬运字节——decode（memory bound）场景即使不算力收益也直接提速。
   注意答"软件协同"：FP8 收益依赖细粒度缩放（DeepSeek 的 1×128 block scaling，见 [104](./104-t5-其余公司杂题.md) DeepSeek 要点题）与 outlier 保护，纯 per-tensor 缩放在 LLM 上常掉精度。

### Q3. FP8 存储的 KV Cache 大小计算（飞星 Q3）

公式（详见 [04](./04-attention与kvcache.md) 与 `solutions/python/src/answers/t5/kv_cache_size.py`）：

$$\text{KV bytes} = 2 \times n_{layer} \times n_{kv\_head} \times d_{head} \times S \times B \times 1\,\text{Byte}$$

FP8（1B/元素）相对 FP16 直接减半。例：Llama-3-8B（32 层 GQA-8、head_dim 128）、batch 4、4096 token：$2×32×8×128×4096×4×1 ≈ 1.07\,GB$（FP16 则 2.15GB）。MLA 下公式变为 $n_{layer}×(512+64)×S×B×1B$。注意点：FP8 KV 通常存 **E4M3**（精度）且 K 敏感可保 K 高精度 V 用 FP8 的混合方案；TensorRT-LLM/vLLM 的 `kv_cache_dtype=fp8` 即此。运行验证：`pytest tests/test_t5.py -k kv_cache`。

### Q4. BF16 与 FP16 的区别；为什么训练用 BF16（讯飞校面 Q1）

| | FP16 | BF16 |
|---|---|---|
| 位分配 | 1+5+8（尾数 10 位） | 1+8+7（尾数 7 位） |
| 指数范围 | ~±65504、$2^{-14}$ 最小正规 | **与 FP32 相同**（8 位指数，$3.4×10^{38}$） |
| 精度 | 相对 ~$2^{-11}$ | 相对 ~$2^{-8}$ |

训练选 BF16：① **动态范围 = FP32**——大模型训练中激活/梯度量级跨越数十个数量级（loss spike、梯度尖峰），FP16 极易上溢/下溢，必须配 loss scaling；BF16 天然免疫，基本免 loss scaling；② 硬件原生支持（Ampere 后 NVIDIA、TPU 一贯）；③ 尾数 7 位对"梯度的有效信息"够用（梯度噪声本身远大于量化误差），换来的指数健壮性更值。推理端 FP16 精度更高时（小模型对精度敏感）仍常用 FP16；混合精度训练的 master 权重 + 更新在 FP32，前向/反向 BF16。

### Q5. GPTQ 与 SmoothQuant 的原理（小厂实1 Q4）

两者解决同一痛点——LLM 激活里的 **outlier（离群大值）** 破坏 INT8 量化——但层级不同（详见 [06 量化](./06-量化.md)）：

- **GPTQ（后训练权重量化，W4A16/W8A16）**：基于二阶信息（近似 Hessian $X X^\top$）逐列贪心量化权重——量化一列后把误差**补偿传播**到未量化列（OBQ 的批量近似，Cholesky 分解实现），最小化逐层输出重构误差。只压权重（激活仍 FP16），推理时权重反量化进 FP16 计算（或 Marlin W4A16 kernel），省显存+decode 带宽；对激活 outlier 天然免疫。
- **SmoothQuant（W8A8 的激活-权重难度迁移）**：利用"激活 outlier 集中在少数通道、对应权重该通道数值较小"的观察，逐通道缩放 $s_j = \max|X_j|^{\alpha}/\max|W_j|^{1-\alpha}$——激活除以 $s$（把 outlier 压平）、权重乘 $s$（难度挪到好量化的权重侧），之后**激活和权重都可 INT8**，乘 GEMM 走 INT8 Tensor Core（延迟比 FP16 还低）。
  一句话对比：**GPTQ 压权重的精度（W4A16）、SmoothQuant 让激活也能 INT8（W8A8）；可叠加（先 smooth 再 GPTQ）**。选型：显存/带宽瓶颈选 GPTQ/AWQ，算力瓶颈（prefill、大 batch）选 SmoothQuant/FP8。

### Q6. 量化相关技术有哪些、各自适用场景；量化的基本原理与流程（海康 Q6、贝壳 Q12、传音 Q8）

原理一句话：$x_q = \mathrm{clamp}(\mathrm{round}(x/s)) + z$，$s=(\max-\min)/2^b$（非对称）或 $\max/2^{b-1}$（对称），反量化 $x ≈ (x_q - z)·s$；误差来源=网格密度（位宽）+ outlier 挤压动态范围。技术谱系与适用场景（详见 [06 量化](./06-量化.md)）：

| 技术 | 场景 |
|---|---|
| PTQ（后训练量化）：per-tensor/channel、minmax/entropy(Percentile/KL) 校准 | 部署快、无训练成本——服务首选 |
| QAT（训练模拟量化，STE） | 端侧低比特（INT4/混合）精度敏感 |
| GPTQ/AWQ/OBQ（权重二阶/激活感知） | LLM W4A16 显存/带宽受限 |
| SmoothQuant / outlier 抑制 | W8A8 全 INT8 GEMM |
| FP8(E4M3/E5M2) | Hopper+ 训练推理全链路（本篇 Q1/Q2） |
| KV Cache 量化（FP8/INT4，KIVI 非对称+per-block） | 长上下文/大 batch 显存瓶颈 |
| Weight-only 专用 kernel（Marlin/exllama、W4A16） | decode memory bound |
| 混合精度分层（embedding/LN 保高精度、GEMM 量化） | 精度兜底 |

**流程**（PTQ 为例，答"操作流程"）：准备校准集 → 逐层前向收集激活分布 → 选 scale（minmax/entropy/percentile）→ 量化权重+插入 Q/DQ → 精度评估（见 Q9）→ 不达标回退混合精度或换 QAT。

### Q7. 量化后精度下降如何排查与定位（海康-一面 Q5）

排查思路（自顶向下二分）：

1. **定位层**：逐层/逐模块对比量化前后输出（cosine 相似度、KL 散度、相对误差）——写 hook 抓每层激活，找误差放大最陡的层（往往是含 outlier 的层/第一个大方差的 FFN down_proj）；
2. **定位张量类型**：权重 vs 激活 vs KV——关掉激活量化只留 W8A16 看恢复多少；再关 KV 量化；常见激活 outlier 是主因；
3. **定位通道**：per-channel 误差排序，看是否少数通道 outlier（→ SmoothQuant/混合精度保护该层）；
4. **检查校准**：校准集分布是否覆盖真实流量（长度分布、领域）、样本量（128-512 条通常够）、校准方法（minmax 被 outlier 拖垮 → 换 entropy/percentile/mse）；
5. **检查任务类型**： perplexity 掉多少？生成任务看实际输出 diff；困惑度对量化不敏感的任务（代码/数学）单独评；
6. **修法优先级**：敏感层保高精度（跳过量化）→ per-block/per-group scale → AWQ/GPTQ 换更稳的算法 → QAT 兜底。

### Q8. 量化后模型（INT8/INT4）运行时内存占用估算（荣耀二面 Q5）

三块相加：**权重 + KV Cache + 运行开销（激活/CUDA context/碎片，~10-20%）**。速算：权重 GB ≈ 参数量 B × 每元素字节（INT8=1、INT4=0.5）；KV 用 [04](./04-attention与kvcache.md) 公式（乘 batch、seq）。例（`solutions/python/src/answers/t5/kv_cache_size.py::quantized_model_footprint`）：32B INT8 ≈ 32GB 权重 + KV + 15% 开销 ≈ **37GB+ → 单卡 32GB 放不下，需 TP=2 或 W4A16（16GB+，单卡可跑）**；7B INT4 ≈ 3.5GB 权重，加上 KV/开销 ~5GB，消费级显卡轻松。答题给公式 + 一个速算例，再点一句"INT4 权重在内存里可能仍按 INT8/packed 存储，实际略有出入"。

### Q9. 传音量化系列：校准集选取 / 精度评估 / scale 计算 / 吞吐计算（传音 Q7/Q9/Q10/Q11）

- **校准集选取**：① 分布匹配——覆盖真实推理流量的长度分布/领域/难例（文本：多领域混合、含目标语言；CV：含各种光照/尺度）；② 规模 128-512 条通常饱和，多了边际收益小；③ 剔除异常样本（全 padding、极端 outlier 主导 amax）；④ 每层统计独立（跑一遍前向逐层收集，不共用）；⑤ 维护回归集跟踪版本间精度。
- **精度评估**：任务指标优先（生成: 困惑度+人工/LLM-judge 对比；检测:mAP；分类:Top-1），配合量化专用指标——逐层输出余弦相似度/SQNR、权重相对误差；输出 diff 率（量化前后预测不一致的比例）；报告时分数据分桶（长度/类别）找最差桶。
- **scale 计算**：minmax（快、被 outlier 拖垮）→ percentile（99.9%/99.99% 截断）→ **entropy/KL**（把 FP 直方图聚成 INT 桶，最小化量化前后分布 KL，TensorRT 经典）→ MSE（最小化量化误差平方）；粒度 per-tensor → per-channel（权重标配）→ per-token/per-block（激活/FP8）。
- **吞吐计算**：$吞吐 = \frac{output\_tokens}{总时间}$（服务级 tokens/s）或 $吞吐 = \frac{请求数}{时间}$（QPS）；注意只计稳定段（去预热）、并发固定、报告 P50/P99 时延同时给吞吐（时延-吞吐曲线才是全貌）；加速比对比同 batch 同长度基线。公式：$tokens/s = \frac{B \times L_{out}}{T_{total}}$，$T_{total}=T_{TTFT}+(L_{out}-1)×TPOT$。

### Q10. 为什么用 TensorRT 做 PTQ；项目对推理速度的要求（小厂实4 Q2）

答"选型理由 + PTQ 判定"：TensorRT 的量化优势——① 校准 API（entropy/minmax percentile）成熟，INT8/FP8 精度-速度工程化最佳；② 算子融合+kernel 自动选择（builder 试跑选最快实现），INT8 后常见 2-4× 于 FP16（CV 模型）；③ 有明确 latency 硬指标（如视频流实时 <33ms/帧、目标检测 P99 < 20ms）时，TRT 是 NVIDIA 上事实标准。**是 PTQ 还是 QAT**：若项目只做校准（喂校准集生成 scale）即 PTQ；若在训练框架里插入伪量化节点微调（恢复精度）才是 QAT——面试按自己项目实际答，并说明为什么够用（CV 模型对 PTQ-INT8 通常只掉 <1% mAP）。速度要求给量化数字：帧率预算、P99 延迟、并发路数。

## 二、算子与 kernel 优化

### Q11. CUDA 算子优化的一般方法与流程（好未来 Q1、识渊 Q2、小厂一 Q10、上海AI Q6、小光子 Q4、南湖 Q12、Teleai Q2 汇总）

七家同题，给统一答法（流程 + 方法清单，细节各自引用已有篇目）：

**流程**：正确性 baseline → profile 定位（Nsight Compute/Systems，看 roofline 位置，见 [08 编译器与性能分析](./08-编译器与性能分析.md)）→ 按 bound 类型下刀 → 对拍 + 基准 → 迭代。

**方法清单**（背熟这张表，按"访存/计算/并行/编译"四组）：

| 组 | 手段 |
|---|---|
| 访存 | 合并访问（coalescing）、共享内存 staging + padding、向量化 load（float4）、常量/纹理/L2 复用、减少冗余读写、异步拷贝（cp.async/TMA） |
| 计算 | 寄存器分块（tiling）、算术强度提升（重复数据复用）、warp shuffle 快速原语、FFMA/ILP 指令级并行、查表/近似（exp2 代替 exp） |
| 并行 | grid/block 形状调优、避免 warp 分歧（分支重构）、occupancy 与寄存器 spill 平衡、persistent kernel/atomics 归约 |
| 编译/系统 | `-O3 --use_fast_math`、`#pragma unroll`、kernel 融合（launch 摊薄）、CUDA Graph、多流重叠、避免同步 |

案例答法（识渊"描述一个完整优化过程"/Teleai"达到什么水平"）：挑一个自己的 kernel 按"naive → 发现瓶颈（如 uncoalesced）→ 手段（smem 转置/padding）→ 数据（GB/s 或加速比）"四段讲。仓库可引用实测：[02 CUDA 编程题](./02-cuda-编程题.md)（reduce 124×、histogram 19.9×、GEMM tiling、转置 padding）。

### Q12. 什么是 bank conflict，如何避免；共享内存还有哪些优化方式（海康 Q1、小厂实4 Q7）

原理与避免方式详见 [01 CUDA 基础与体系结构](./01-cuda-基础与体系结构.md) bank conflict 题：共享内存按 bank 交错分布（32 bank×4B），**同一 warp 内多条地址落在同一 bank 不同槽** → 串行化（2/4/8 路冲突）；广播（同地址）不冲突。避免：① 访问模式错开（列访问转行访问）；② **padding**（stride+1 打乱 bank 映射，转置 kernel 经典）；③ 数据布局重排（结构体分块 AoS→SoA）；④ 64 位访问拆成 32 位；⑤ 用 `cudaOccupancyMaxPotentialBlockSize` 后实测验证（ncu 指标 `l1tex__data_bank_conflicts`）。

**共享内存其他优化**：动态 vs 静态分配（extern smem 省资源）、双缓冲（pipeline 掩盖全局内存延迟）、分块复用（GEMM tile 常驻）、swizzle（用 XOR 重排线程-数据映射替代 padding，不浪费容量、对编译器更友好，FlashAttention/cutlass 用）、与寄存器/L1 权衡（`__launch_bounds__` 控制占用）。

### Q13. 如何实现 CUDA 版 Softmax；负载不均衡问题；warp 级与 block 级的差异（海康 Q2、讯飞校面 Q6、智源二 Q4）

**实现路线**（三段式：读入 → 归约求 max/sum → 归一化写回）：

1. **数值稳定**：先减行 max 再 exp（防 e^x 上溢）——$softmax(x_i) = e^{x_i - m}/\sum e^{x_j - m}$；
2. **一行一 block**（行长大）：block 内线程协作——每线程读一段做局部 max → **块归约**（smem 树归约 or `__reduce_max_sync`）广播 max → 同法归约 sum（两遍）→ 各线程写回；
3. **一行一 warp**（行长 ≤ 1024）：warp shuffle 归约（`__shfl_xor_sync`），免 smem、免 `__syncthreads`，延迟更低——这就是"warp 级 vs block 级"的差异：**warp 级免块内同步、免共享内存、适合短行；block 级能处理任意长度、用 smem 树归约与同步，适合长行但同步开销大**；
4. **one-pass online softmax**（本篇 Q14）把两遍合成一遍，配合 FA。

**负载不均衡**（讯飞校面 Q6，NPU/GPU 语境）：softmax 按行切时行长不一（变长序列/_padding 差异）→ 有的线程多算。解法：① 按 token 总数而不是行数切分（ flatten 后均衡）；② 分桶（短行 warp 级、长行 block 级，双 kernel 或动态选择）；③ persistent kernel + 原子取任务（工作队列自调度）；④ padding 到桶 + 调度器把同长行捆一起（推理引擎 bucketing）。可运行实现：`solutions/cuda/src/`（softmax 数值稳定版 + Online Softmax）、Triton 版 `solutions/python/src/answers/triton_kernels/softmax.py`（4096² 实测 0.163ms / 825GB/s）。

### Q14. Online Softmax 与 FlashAttention 的核心思想（海康 Q3、讯飞校招 Q1）

**Online Softmax**：朴素 softmax 两遍扫（先 max 后 sum）→ online 用** running max/sum 增量修正**：来一块新数据 $x$，更新 $m_{new}=\max(m, m_{block})$、$l_{new} = l \cdot e^{m-m_{new}} + l_{block}$——一遍扫完同时得到 max 与 sum，数值不溢出。这就是 FA 能分块的关键（`solutions/python/src/answers/attention/online_softmax.py` 可运行对拍）。

**FlashAttention**（核心优化点，详见 [04 Attention 与 KV Cache](./04-attention与kvcache.md) FA v1/v2/v3 题）：

1. **分块计算（tiling）**：Q/K/V 分块装进 SRAM，在片上算 score×V，$O(N^2)$ 的 attention 中间矩阵**从不物化到 HBM**——显存从 $O(N^2)$ 降到 $O(N)$；
2. **Online softmax**：块间 max/sum 增量修正，分块下 softmax 依然精确；
3. **kernel 融合 + 减访存**：一次 kernel 完成 QK^T、softmax、PV，HBM 访问从 $O(N^2)$ 次降到 $O(N^2 d / M)$（M 为 SRAM 大小）——**FA 是 IO 感知算法，降的是访存不是 FLOPs**；
4. v2 改进：减少非乘法运算、并行度切到 seq 维（长序列 decode 更快）、warp 分工优化；v3（Hopper）用 warp specialization + TMA + FP8 异步流水。
   答题结构：先说动机（attention 中间矩阵访存爆），再三点（分块、online softmax、IO 复杂度），最后一句"FA 严格数学等价于标准 attention"。

### Q15. Reduce 算子的优化策略（类脑 Q17、好未来 Q2、智源二 Q3）

实现思路与多级优化详见 [02 CUDA 编程题](./02-cuda-编程题.md) 归约题（实测 atomic 1.962ms → 树归约+warp shuffle 0.016ms，124×）。阶梯答法：

1. **原子加（naive）**：全局 `atomicAdd`——冲突串行化，慢（但无需中间内存，适合多 kernel 累加场景）；
2. **树归约（block 内）**：数据装 smem，每轮活跃线程减半；注意消除分歧（步长遍历 + 越界线程空闲）与 smem bank conflict；
3. **warp shuffle**：最后 32 个元素用 `__shfl_down_sync` 在寄存器内归约——免 smem 免同步；
4. **两阶段 grid**：每 block 归约出一个部分和写回 → 第二个 kernel 或单 kernel 的最后 block（`atomicAdd` 计数器判"我是最后一个"）合并——**grid 同步不全靠原子**；
5. **向量化读取**（float4）+ 展开每线程累计（ILP），先把带宽吃满再谈归约；
6. 数值策略：pairwise/成块求和保精度，避免长序列顺序累加大误差。

### Q16. CUDA 计算模型：grid/block 配置及对性能的影响；blockDim 与 blockIdx（智源二 Q1、好未来 Q3）

**基本概念**：kernel 以 grid（三维 block 网格）组织，block 内最多 1024 线程按 32 个/warp 调度；`blockIdx` 定位 block 在 grid 的坐标、`blockDim` 是 block 尺寸、`threadIdx` 是块内坐标——全局 id = `blockIdx*blockDim + threadIdx`（各维）。共享内存/同步（`__syncthreads`）只在 block 内有效。

**配置对性能的影响**：① **warp 完整性**——blockDim 取 32 倍数（128/256 常用），尾巴不满 warp 浪费调度槽；② **occupancy**——block 越大每 SM 寄存器/smem 资源越紧，能同时驻留的 block 数越少；小 block（128）灵活、大 block（512）省 launch 但可能压 occupancy；③ **尾块负载**——grid 尺寸除不尽数据量时最后一批 block 半负载（persistent kernel 或 grid-stride loop 平滑）；④ **维度映射要与访存对齐**（行/列选错直接毁掉合并访问）；⑤ 归约类 kernel 常取 128-256 线程 + 每线程多元素（grid-stride）；GEMM tile 则由 register/smem 预算倒推。经验法则：从 128×(数据量/128) 起步，用 ncu 看 achieved occupancy 与内存带宽再调。

### Q17. 同一 block 内不同 warp 之间如何通信（智源二 Q2）

没有 warp 间直接指令——通信靠**共享内存 + barrier**：

1. warp A 写 smem → `__syncthreads()`（block 级栅栏，保证可见性）→ warp B 读；
2. 细粒度可用**命名 barrier**（`barrier.sync`/`__syncwarp` 变体、CUDA 9+ cooperative groups 的 `tiled_partition` + `barrier_arrive/wait`）——两个 warp 互相等；
3. warp 间也可经 **L1/全局内存**（`__threadfence_block()` 保证序）或原子操作（smem `atomicAdd`）传递信号；
4. 例外：**同 warp 内**用 shuffle（`__shfl_sync`）直接交换寄存器值——这也是"warp 是最小调度/通信单元"考点的出处：跨 warp 就必须经内存 + 同步。
   加分：warp specialization（生产者/消费者 warp 组 + 命名 barrier + smem 环形缓冲）是 Hopper FA3/cutlass 的标准结构（见 [03 GEMM 与算子优化](./03-gemm与算子优化.md)）。

### Q18. 卷积算子的实现方式与优化手段（智源一 Q1、传音 Q14）

**实现方式**：① 直接卷积（im2col 免掉之前的六重循环展开）→ **im2col + GEMM**（把输入展开成矩阵后调 cuBLAS——主流框架的通用后端，代价是显存膨胀与展开开销）；③ **Winograd**（F(2×2,3×3) 理论乘法 2.25×减少，小 kernel 整数步幅专用）；④ **FFT**（大 kernel）；⑤ **隐式 GEMM**（不显式物化 im2col，在 kernel 内即时索引——cuDNN/cutlass 路线）；⑥ **深度可分离卷积**单独优化（batch ch 维度、向量乘+广播）。

**优化手段**：输入分块驻留 smem（tile + halo 边界处理）、寄存器分块累积、NHWC 布局（C 维连续利于向量化与 Tensor Core）、向量化 load（float4/INT8×8）、kernel 融合（conv+bn+relu）、NCHW↔NHWC 转换融合进前后算子、Tensor Core（INT8/FP16 卷积走 IMMA）、多核切 N/H 维、auto-tune tile（cuDNN benchmark / Triton autotune）。C++ 参考实现在 [10 C++ 编程题](./10-cpp编程题.md)（Conv2D），CUDA 转置/融合思路见 [02](./02-cuda-编程题.md)。

### Q19. 矩阵乘法的分块优化策略（传音 Q15）

GEMM tiling 完整推导与实测见 [03 GEMM 与算子优化](./03-gemm与算子优化.md)：朴素 $O(n^3)$ 每次乘加都要读全局内存 → **两层分块**（C 的 tile 进寄存器、A/B 的 tile 进 smem，复用率 ×(tile 大小)）→ **寄存器分块**（每线程算 tile 内小微块，数据进寄存器后反复用）→ 双缓冲预取掩盖延迟 → 向量化/对齐（+float4、bank padding/swizzle）→ Tensor Core（mma 指令，16×8×16 分片）。关键量：算术强度 = $\frac{2mnk}{2(mk+nk+mn)\cdot bytes}$，tile 越大强度越高但寄存器/smem 爆——3090 实测 naive 2166 → smem tiling 2804 GFLOPS。数学本质一句话：**把"每 FLOP 搬一次数据"改成"每搬一次数据服务多次 FLOP"**。

### Q20. FlashAttention v1 与 v2 的核心改进对比（智源二 Q8）

详见 [04 Attention 与 KV Cache](./04-attention与kvcache.md) FA 题系列。速答表：

| | v1 (2022) | v2 (2023) |
|---|---|---|
| 并行维度 | batch×head（长序列下 block 少） | 增加 **seq 维并行**（Q 块切分）——decode/长序列打满 SM |
| 线程分工 | K/V 块跨线程split，smem 交换中间值（非乘法指令多） | **每线程连续算一个 Q 行块**，非乘法指令大减（~2×） |
| warp 角色 | 对称分割 | 接近 warp specialization雏形（reduce warp 分工） |
| 速度 | 1.5-2× cuBLAS 等 | GPT-2 训练端到端 ~2×，A100 达 50-73% 峰值 |

v3（Hopper，追问）：warp specialization + TMA 异步 + in-flight FP8 GEMM/softmax 重叠，1.5-2× 于 v2。

### Q21. 算子融合有哪些常见方式（上海AI Q2）

按融合模式分类（详见 [03 GEMM 与算子优化](./03-gemm与算子优化.md) 融合方法论）：

1. **逐元素链融合**（epilogue/prologue）：x+bias→act→dropout→residual——一读一写，省中间往返 HBM；
2. **归约类融合**：matmul+softmax+matmul（FA 本质）、LayerNorm 与相邻 GEMM、reduction+cast；
3. **GEMM epilogue 融合**：bias/激活/residual/add 进 GEMM kernel 尾部（cuBLASLt epilogue、cutlass EVT）；
4. **水平融合**（同输入多分支）：一份数据喂多算子合并 kernel（编译器自动 common subexpression + horizontal fusion）；
5. **pattern 替换**：图匹配替换成手工融合库（softmax+drop、attention 整体）；
6. 代价与边界：融合 kernel 寄存器压力/复用率下降时反而慢；中间值需要被多消费者用时不宜融合；动态 shape 频繁重编译的治理（bucket/cache）。

### Q22. TVM 的核心功能（上海AI Q5）

详见 [08 编译器与性能分析](./08-编译器与性能分析.md) TVM 题。一句话：**张量计算的深度学习编译器**——前端接 TF/PyTorch/ONNX，Relay/Relax IR 做图级优化（融合/布局/量化），TensorIR 做算子级调度（schedule：tile/并行/向量化/unroll），auto-tuning（AutoTVM/Ansor 搜索 schedule）生成各后端（CUDA/ROCm/Vulkan/CPU/NNPU）代码；TVM runtime（graph executor/VM）+ BYOC 路线对接厂商工具链。考点：分离 schedule 与计算描述、TIR 的 block-iterator 抽象、与 torch.compile 的差异（AOT/边缘部署 vs 训练态即时编译）。

### Q23. GPU 显存层级结构与特点；影响 GPU 性能的硬件因素（小厂实4 Q6、小厂实面 Q2/Q3）

完整版见 [01 CUDA 基础与体系结构](./01-cuda-基础与体系结构.md)。速答：**寄存器（每线程私有，最快）→ 共享内存/L1（每 SM 内，~20-100KB，延迟 ~30 cycle，bank 组织）→ L2（全 SM 共享，数 MB~100MB，~200 cycle）→ HBM/显存（GB 级，400-4000 cycle，带宽为瓶颈常量）**，与 CPU 端还有 PCIe/NVLink。数据移动越外层越贵——优化=把热数据放内层 + 减少搬运次数（tile/复用/融合）。

**影响性能的硬件因素**：① 计算峰值（FLOPs：SM 数×频率×每周期指令×宽度，Tensor Core 倍增）；② **访存带宽**（HBM 位宽×频率——decode 类负载的第一瓶颈）；③ **SRAM/寄存器容量**（决定 tile 大小与 occupancy）；④ 专用单元（Tensor Core/视频单元/拷贝引擎 async）；⑤ 互联（NVLink/PCIe——多卡与 PD 分离的瓶颈）；⑥ 缓存一致性/原子吞吐、指令发射带宽（warp scheduler 数）。答题把"算力 vs 带宽"的 roofline 二分放最前（见 [03](./03-gemm与算子优化.md) Roofline 题）。

### Q24. CUDA 加速图像预处理的具体实现与优化（小厂实4 Q3、Q4）

典型任务：解码后处理（resize/归一化/NHWC→NCHW/BGR→RGB/letterbox）。实现要点：

1. **一个融合 kernel 做完**（decode→resize(bilinear)→HWC→CHW→normalize→减均值除方差）：每线程算一个输出像素，按目标坐标反向采样源图（预计算 x/y 映射表进 smem 或常量内存）；
2. **合并访问**：输出按行连续写（每线程 4 像素 float4/uchar4）；源图读取用纹理对象（`tex2D`）免费拿双线性插值与边界处理；
3. **向量化**：uchar4/float4 一次 128b；颜色转换是纯 ALU，向量化后吃满带宽即可；
4. **流水线**：NVDEC 硬解码（DMA 直达显存）→ CUDA 预处理 kernel → 推理，多流重叠（解码流/处理流/推理流 + 事件同步）；
5. **实测案例的答法**（向量化未产生加速——小厂实4 Q4 追问）：先测 roofline——若 kernel 原本就没吃满带宽（如启动开销主导、或数据量太小 L2 全命中），向量化不会显式加速；或是访问模式没对齐（非 16B 对齐的 float4 会拆成多次事务反而变慢）、编译器已自动向量化（auto-vectorization 早就合并了）。**答"先 profile 再解释"比背结论加分**。

### Q25. NPU 开发的主要难点与应对（讯飞校面 Q5）

① **算子覆盖/生态**：新结构（MLA/投机采样/MoE 路由）官方库滞后——应对：预留 CPU fallback 路径、自研算子走厂商 IR（Ascend C/TBE）；② **动态 shape**：NPU 编译器对静态优化激进，变长序列反复编译——bucketing/_padding 到档位 + 编译缓存；③ **调试工具链**：精度问题难定位（黑盒算子）——对拍 GPU/CPU 逐层 dump，硬件仿真器慢；④ **多卡/集群**：HCCL 与 NCCL 行为差异（调优参数、拓扑感知）——集合通信 benchmark 先行；⑤ **内存管理**：统一地址/DDR 混布，带宽模型不同——重写调度假设（如 KV 放哪级存储）；⑥ 性能可移植性差——抽象层（torch_npu）能跑但慢，真正吃性能要下沉。应对总结：**早对拍、常 benchmark、档位化 shape、关键算子自研**。

### Q26. Tensor Parallel 切分的对象与通信操作（讯飞校面 Q7）

TP 切分的是**层内权重矩阵**（attention 的 QKV/O 投影、FFN 的 up/down 投影），按矩阵维度切：头维（QKV 按注意力头分组切）或 N/M 维（GEMM 输出/输入维）。通信：**前向两次 all-reduce（行切分后 all-gather、列切分后 reduce-scatter 的组合）**——Megatron 方案每层 2 次 all-reduce（前向 1 + 反向 1，共 4 次/层含梯度）；推理 TP 只需前向 2 次（attention out all-reduce + FFN out all-reduce）。详细推导与 MLP 行列切分组合见 [07 分布式训练](./07-分布式训练.md) TP 题与 [104](./104-t5-其余公司杂题.md) Megatron 切分题。

### Q27. ARM NEON 指令集的概念与应用（传音 Q16）

NEON = ARM 的 128-bit SIMD 向量单元（AArch64 上 32 个 128b 寄存器 V0-V31），一条指令处理 16×int8 / 4×float32 / 8×int16。应用：① 图像/信号处理（色彩转换、resize、滤波——`vld1q_s8`/`vmlaq_f32`）；② 量化推理 kernel（int8 点积 `vdotq_s32`（dotprod 扩展）、矩阵乘微内核）；③ 内存拷贝/比较优化。使用方式：intrinsic（`arm_neon.h`）为主，汇编次之，编译器 auto-vectorization（`-O3 -mcpu=...+simd`）兜底；效果取决于数据对齐（16B）与布局（C 维连续）。答端侧推理时补一句：NCNN/MNN 的 ARM 后端核心就是把 conv/gemm 写成 NEON 微内核（4×8/6×16 tile）+ 汇编调度。

### Q28. ARM 平台的性能优化方法（小厂实4 Q8）

① **NEON 向量化**（上题）+ 数据对齐；② **内存布局**（NHWC、pack 后的权重——预重排让内层连续）；③ **cache 友好**：分块 tile（L1/L2 容量倒推）、预取（`__builtin_prefetch`）、避免伪共享；④ **big.LITTLE 调度**：绑核（性能核跑主循环）、线程池与 NUMA/簇内共享；⑤ **多线程**：OpenMP/pthread 按核数切、任务粒度避免过细（同步开销）；⑥ **量化**（INT8 NEON 点积 4× 于 FP32）；⑦ 省掉不必要的内存拷贝（零拷贝 buffer、内存池）；⑧ 工具：perf、Streamline、简单 rdtsc 计时。

### Q29. CUDA Core 与 Tensor Core 的区别（类脑 Q15）

**CUDA Core**：通用标量 ALU（每 SM 内大量，每周期每核 1 次 FP32 FMA）——适合控制流复杂、低密度计算、任意数据类型。**Tensor Core**：矩阵乘累加专用单元（一条指令完成小矩阵乘，如 HMMA 16×8×16、WGMMA 64×256×16）——FLOPs 密度 4-16× 于 CUDA Core，支持 FP16/BF16/INT8/FP8/FP4，但只吃规则 GEMM 模式（对齐 tile、无复杂控制流）。类比：CUDA Core 是 Swiss Army knife、Tensor Core 是专用机床。实践：DL 负载先设法变成 GEMM（im2col、FA 分块）喂 Tensor Core，剩余逐元素/归约留在 CUDA Core；利用率差距（MFU）来自喂不满 Tensor Core。

### Q30. 华为达芬奇架构的设计特点（类脑 Q16）

达芬奇（DaVinci）是昇腾 NPU 的核心：① **Cube 矩阵计算单元**（16×16×16 矩阵乘一次完成，FP16/INT8）+ **Vector 向量单元**（逐元素/激活函数）+ **Scalar 标量单元**三单元异构——对应 DL 负载"GEMM+激活+控制"三类计算；② **Cube 优先的存储层级**：L0A/L0B/L0C（矩阵专用缓冲）→ L1 buffer（用户管理 SRAM）→ L2 → HBM/DDR——编译器显式搬运（异步 double buffer）；③ AI Core 阵列 + AI CPU 兜底非张量算子；④ 指令集（CISC 长指令，一次发射一个融合操作）；⑤ 软件栈 CANN（图编译把算子编排到 Cube/Vector，见 [100](./100-t5-推理引擎.md) Q24）。与 GPU 差异：**显式内存管理**（编译期规划 vs GPU 运行时缓存自适应）、矩阵单元粒度更粗（16³ vs warp 级 mma）、控制流弱（依赖 AI CPU）。适合大 GEMM 密集的 Transformer，动态 shape/长尾算子是短板。

### Q31. 面对新模型在指定硬件上的优化思路；尚未充分探索的研究方向（格灵 Q2/Q3）

**优化思路**（方法论题，答流程）：

1. **先测基线**：端到端时延分解（prefill/decode 分开、每层耗时、算子耗时 top10），确定 compute/memory bound（roofline）；
2. **先套通用手段**：量化（PTQ W8A8/W4A16）、图优化（融合）、引擎（选 TRT-LLM/vLLM/端侧框架）、batching 策略——零改动收益最大；
3. **再下深水区**：热点算子手写/替换（FA 类）、内存布局重排、调度（chunked prefill/CUDA Graph）、权重/KV 分级存储；
4. **硬件对齐**：tile 尺寸对齐 SRAM/缓存、精度对齐专用单元（Tensor Core/NEON）、多核/多卡切分与通信隐藏；
5. **闭环**：每步用固定 benchmark 验证（时延 P50/P99 + 精度），记录 ablation。

**开放研究方向**（挑 3 个言之有物）：① 长上下文注意力稀疏化/压缩的**训练-推理一致性**（DSA 类索引器的可学习性与硬件协同）；② decode 的算术强度天花板——量化到 FP4/2bit 的 kernel 与精度协同、投机采样与 batch 的最优组合；③ PD 分离/异构算力下的全局调度与 KV 传输的**学习型策略**；④ 动态 shape 下 AOT 编译的编译开销摊销；⑤ 端云协同推理的任务切分（分层投机/早期退出）；⑥ MoE 推理的专家编排与 all-to-all 优化（EPLB 之上在线自适应）。

### Q32. 常见图像处理算子；如何保障系统高性能（识渊 Q3/Q4）

**图像算子**：几何（resize/rotate/warp/crop——插值：最近邻/双线性/双三次）、颜色（cvtColor/直方图均衡/CLAHE/Gamma）、滤波（box/高斯/中值/Sobel/Laplacian——可分离卷积加速）、形态学（腐蚀/膨胀/开闭）、特征（Canny、Harris、HOG）、融合类（add/blend/阈值/查表 LUT）。CUDA 实现要点见本篇 Q24（合并访问、纹理采样、融合 kernel）。

**系统高性能保障**（工程实践题）：① 全链路 profile（瓶颈定位——GPU/CPU/IO/网络谁卡）；② 流水线并行（解码/预处理/推理/后处理多流多线程，零拷贝交接）；③ 资源隔离与预算（每环节 deadline，超时降级）；④ 缓存与复用（模型常驻、内存池、prefix/result 缓存）；⑤ 自动化基准回归（CI 跑性能用例，防性能劣化合入）+ 监控告警（QPS/时延/GPU 水位）；⑥ 容量规划与弹性扩缩容；⑦ 降级预案（跳帧/降分辨率/切轻量模型）。

### Q33. 大模型推理场景的算子优化方向（Teleai Q2）

与 Q11 通用方法互补，LLM 特有视角：① **decode 的 GEMV/瘦 GEMM 优化**（weight-only 量化 kernel、权重驻留、split-K）；② **attention kernel 族**（FA/FA2/FA3、PagedAttention、MLA 吸收版、prefix 复用版，见 [100](./100-t5-推理引擎.md) Q4）；③ **融合组件**（RMSNorm+residual+add、RoPE 融合、采样 top-k/top-p 融合、MoE 的 group gemm+激活融合）；④ **动态 shape 处理**（bucket kernel、变长 attention 的 gather/scatter）；⑤ **调度类优化**（CUDA Graph 静态化、多流双缓冲、NCCL 与计算重叠）；⑥ MoE 专属（all-to-all 通信与 expert GEMM 重叠、grouped GEMM）。答完补一句 profile 驱动的优先级：decode 看带宽、prefill 看算力。
