## Q1. TVM 的基本概念与思想（面经-1 HPC 14、vivo）

TVM：**深度学习编译栈**，把计算图一步步 lowering 到目标硬件代码。

- **概念层次**：Relay（图级 IR，含算子融合/布局变换等图优化）→ TensorIR/TIR（张量级 IR，循环/并行/内存调度在此变换）→ 目标代码（LLVM/CUDA/专用后端）。
- **核心思想**：**计算与调度分离**（继承 Halide）：算子只声明"算什么"（`T.compute`），"怎么算"由 schedule（tile/并行/向量化/unroll/缓存分级）决定，AutoTVM/Ansor 自动搜索调度。
- **执行流程**：前端框架图 → Relay 优化 pass（融合、常量折叠、布局）→ 算子 lowering → 调度优化 → codegen → 运行时（VM/图执行器）。
- 局限（遂原/燧原考点）：动态 shape 支持弱、自动调度搜索成本高、对专用 NPU 的后端适配要手写 intrinsics。

## Q2. MLIR 与多面体模型（遂原、元戎、腾讯）

**MLIR**：可复用的编译基础设施——**多层 Dialect**（toy/affine/linalg/vector/gpu/llvm…），每层 IR 有明确抽象层级，通过 **Pass 渐进 lowering**（linalg → affine → vector → llvm）。相比 TVM 的单栈：可定制 dialect（torch-mlir/TOSA/MemRef）、统一 infra（pattern rewrite、bufferization 处理张量→内存），适合多方（框架/芯片厂商）共建生态。

**多面体模型（Polyhedral）**：把循环嵌套建模为整数多面体（迭代空间 + 依赖 = 约束不等式），用仿射变换做**循环交换/分块/倾斜/融合**的自动推导——保证变换不改语义（依赖保持）。MLIR 的 affine dialect 就是多面体 IR；TVM/isl 也用它做调度推理。

**Halide 思想**（腾讯、OPPO）：同 TVM 的计算-调度分离祖宗，强调 pipeline（producer-consumer）级融合调度，rule-based 自动搜索。

## Q3. MLIR 常见组件考点（元戎启行）

- **自定义 Dialect**：`mlir::Op` 注册（TableGen .td 定义 op/traits/约束），lowering 用 pattern（DAG-to-DAG rewrite）逐 dialect 下降；
- **TOSA/Tensor Level → Bufferization**：张量（值语义）到 memref（指针语义）的转换——in-place 分析决定 buffer 复用（追问"计算图最小内存"：本质是 bufferization 的 liveness + alias 分析）；
- **LLVM isa/dyn_cast**：MLIR/LLVM 的 RTTI 替代——类名编码进类名（`classof`），`isa<T>` 判类型、`dyn_cast<T>` 安全转换，O(1) 字符串/标记比较。

## Q4. Graph Fusion 算法（综合-5 编程 8）

面试手写"图融合"一般指：给定计算图（DAG）+ 可融合规则（如 elementwise 链、消费者单一的 producer），输出融合后的图。核心是 **DAG 上的支配/连通判定**：

```python
def graph_fusion(nodes, edges, fusable):
    # 典型贪心: 按拓扑序遍历, 若 node 与其(唯一)consumer 都可融合且满足规则 → 合并
    # fusable(a, b): b 是 a 的唯一 consumer 且 a 的输出不再被别人用, 且二者类型可融合
    merged = {n: n for n in nodes}
    for n in topological_order(nodes):
        consumers = [c for c in succ(n) if live(c)]
        if len(consumers) == 1 and fusable(n, consumers[0]):
            merge(n, consumers[0])       # union-find / 重定向边
    return contract_graph(merged)
```

要点：①拓扑序保证 producer 先处理；②"唯一消费者 + 输出不被其他分支用"是安全融合条件（否则融合会重复计算或破坏共享）；③进阶可讲支配树（XLA 的 fusion 用 dominator 分析选择融合窗口）。

## Q5. Nsight 工具链的使用（腾讯-实习一二面、OPPO、快手-校招-一面）

- **Nsight Systems（系统时间线）**：看 kernel 时序/空隙、多流重叠、 cudaMemcpy 占比、CPU launch 延迟。回答"GPU 利用率为什么低（gap 多）"。
- **Nsight Compute（kernel 剖析）**：SOL（计算/访存屋顶线百分比）、Occupancy、Warp State（stall 原因：long scoreboard=全局访存等待、short scoreboard=共享内存/屏障、selected/not selected、branch divergence）、Memory 表（L1/L2 命中、事务/请求比 → 合并访存是否好）、指令统计（寄存器/溢出）。
- 用法：`ncu --set full -k "regex:kernel" ./app`；对比优化前后同一 kernel 的 SOL/时长；`ncu --section MemoryWorkloadAnalysis` 专看带宽。
- 判读经验：SM% 与 Mem% 谁接近 100 谁是瓶颈；两者都低 → 并行度不足（occupancy/launch 配置）；dram 带 宽高但 L2 低 → 数据没复用。

## Q6. 图优化 / 算子调度类开放题（蔚来、卓驭）

推理引擎图优化 checklist：常量折叠、算子融合（见 Q4 规则）、布局推导（NCHW/NHWC 全局选择）、死代码消除、shape 特化（动态转静态 + CUDA Graph）、算子替换（用等效低成本实现）。算子调度：拓扑序执行 + 多流并行（无依赖分支分派到不同 stream）+ 内存复用（活跃区间分析分配 buffer 池）。
