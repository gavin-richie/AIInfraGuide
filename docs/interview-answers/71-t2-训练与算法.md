## 一、MiniMax：RAG / Agent / 应用层

### Q1. 什么是 RAG？如何改善生成质量？标准方案的不足？与传统"先检索再生成"的本质差异？（MM一 1）

- **是什么**：检索增强生成——生成前先按 query 从外部知识库（向量库/BM25/混合）检索 top-k 相关片段，拼进 prompt 作为上下文，让模型"开卷作答"；
- **改善质量的方式**：① 注入预训练未见/私域/时效知识（模型参数不用重训）；② **降低幻觉**（有据可依、可引用溯源）；③ 支持知识更新与权限控制（库级增删）；④ 小模型借外部知识逼近大模型的事实问答；
- **标准方案不足**：检索质量是天花板（召回不准/排序差 → 上下文污染）；**静态单轮**——一次检索定终身，query 写得差就全错；chunk 切割破坏语义；多跳推理弱（一次检索拿不全链条证据）；长上下文注入贵且稀释注意力；知识冲突（库间矛盾）无仲裁；
- **本质差异（vs 固定管线"检索→拼 prompt→生成"）**：Agentic RAG 把检索从**固定前置步骤**变成**模型可调用的工具**——模型自己决定要不要检索、检索什么、检索几次（query 改写/拆解/迭代验证），检索与推理交错进行。从"流程写死"到"策略模型化"，这是 RAG → Agent 的分水岭（也正对 Q4"封装为 Agent 的好处"）。

### Q2. SFT 的主要工作流程？训练数据集如何构建与筛选？（MM一 2）

**流程**：基座模型选择 → 数据构建（下）→ 模板化（chat template，多轮拼 prompt，见 Q11 loss mask）→ 训练（full/LoRA，lr 1e-5~2e-5、epoch 2-3、packing 长序列拼 batch）→ 评测（held-out + benchmark + 人工/LLM 打分）→ 迭代。

**数据构建**：① 来源：开源指令集、人工标注/众包、**更强模型蒸馏合成**（self-instruct/Evol-Instruct 扩增）、业务日志回流；② **筛选**（重要考点）：规则清洗（长度/语言/敏感词）→ 去重（MinHash/精确哈希）→ 质量分类器（reward 模型/LLM-as-judge 打分过滤）→ 去污染（与评测集 n-gram 重叠剔除）→ 配比（指令类型/难度/领域分布均衡，防能力跷跷板）；③ 规模：通用 SFT 1e4~1e5 高质量样本已够（LIMA 结论：质量>数量），领域增强再加量。

### Q3. 数学视角理解 Attention（MM一 3）

三种口径都算对，层层递进：

1. **加权平均/信息路由**：$\text{Attn}(Q,K,V)=\text{softmax}(QK^\top/\sqrt d)V$——输出是 V 的凸组合，权重由 query-key 相似度经 softmax 归一化，即"按相关性路由信息"；
2. **核回归/非参数平滑**：定义核 $k(x_i,x_j)=\text{softmax 分数}$，attention 就是在做 **Nadaraya-Watson 核回归** $\hat y(x)=\frac{\sum_j k(x,x_j)v_j}{\sum_j k(x,x_j)}$——把每个 token 的 value 向"相关上下文"平滑插值；$\frac{1}{\sqrt d}$ 是高维内积方差控制（防 softmax 饱和成 one-hot）；
3. **随机矩阵/图**：softmax 行随机矩阵 A（每行和为 1）作用在 value 上 = 在全连接图上做一步**带权消息传递**；堆叠 L 层 = 复合转移算子，谱（低秩性、token uniformity）决定表达与可辨识性（这也是 MLA 低秩假设、attention 稀疏化的出发点）。

### Q4. Agent 技术：把 RAG 封装为 Agent 形态的好处？（MM一 4）

Agent = LLM 大脑 + 工具调用 + 记忆 + 规划循环（感知→规划→行动→观察）。把 RAG 封装成 Agent 的收益：

1. **可控性反转**：检索时机/次数/query 由模型决策（Q1 的本质差异），多跳问题可"检索→读→再检索"迭代；
2. **可组合**：检索与计算器/代码/数据库/API 并列成工具箱，路由与 fallback 统一处理（Q13）；
3. **可观测可评估**：轨迹（调了什么工具、传了什么参数）显式化，归因与回归测试比端到端黑盒容易；
4. **工程解耦**：检索服务独立扩缩容、独立迭代索引，不绑死在 prompt 管线里。

### Q5. 如何系统评估 RAG 系统？（MM一 5）

分两层（+ 端到端）：

- **检索层**：recall@k / precision@k、MRR、nDCG（带增益排序质量）——用标注的 query-文档对；
- **生成层**（RAGAS 框架四件套，LLM-as-judge）：**faithfulness**（答案是否忠于检索内容，幻觉率反面）、**answer relevancy**（答案与问题的相关性）、**context precision/recall**（检索上下文里有效信息的排序与覆盖）；
- **端到端**：标准数据集（BEIR/Natural Questions/KILT、业务评测集）、人工抽检、延迟/成本（SLO 维度）。
- 方法论：分层评估才能**归因**（检索差还是生成差），这是"系统性"三个字的得分点。

### Q6. 多轮对话 Agent 中 Attention 会暴露哪些不足？（MM一 9）

1. **KV 线性累积**：每轮历史全量进上下文，KV Cache 与注意力计算随轮数线性膨胀 → 显存/延迟劣化（公式见 [04](./04-attention与kvcache.md) Q7）；
2. **长程稀释与 lost-in-the-middle**：注意力被大量无关历史稀释，中部信息利用率低；
3. **外推限制**：训练长度外位置编码失真（RoPE 插值缓解，[04](./04-attention与kvcache.md) Q8）；
4. **无持久记忆/无状态**：跨会话知识无法存进注意力，只能外置记忆库再检索（又回到 RAG）；
5. **前缀复用与动态前缀矛盾**：多轮共享前缀可用 prefix cache，但 system state/工具结果动态插入破坏前缀匹配；
6. **上下文窗口硬上限**：超窗只能截断/摘要，截断策略（保头保尾/检索式历史）本身是新问题。

工程缓解：PagedAttention+prefix cache、滑动窗/StreamingLLM、H2O 驱逐、历史压缩（summary memory）——[04](./04-attention与kvcache.md) Q7 全景。

### Q7. 工具调用的调度机制与 Fallback 降级？（MM一 13）

- **调度机制**：工具注册表（schema：名称/参数/鉴权/超时/配额）→ LLM 产出结构化调用意图（function call JSON）→ **路由层**校验参数+选择执行体（本地/远程/缓存）→ 执行器池（并发上限、队列、超时熔断）→ 结果回填上下文继续推理。多工具并发时按**依赖 DAG** 拓扑执行，无依赖的并行发；
- **Fallback**：超时/限流/5xx → 重试（指数退避+抖动，幂等才重试）→ 同能力备用工具/备用模型降级 → 缓存旧结果/默认值 → 最终"向用户坦白失败"。配套：熔断器（连续失败跳闸冷却）、舱壁隔离（每工具独立并发池防雪崩）、降级链要在工具元数据里显式声明。

### Q8. Modular Agent 如何做多步规划？Agent 评估体系？（MM一 14/15）

- **多步规划**：① **ReAct**（推理-行动交错，每步显式 thought → action → observation）；② **plan-and-execute**（先产出完整计划 DAG，逐步执行、失败局部重规划）；③ **分解器**（task → 子任务树，路由到子 Agent/工具）；④ **反思/自纠**（执行后 critique 一步，失败回滚重试）。Modular 的要义：规划器只做决策，执行在模块间以显式契约（typed input/output）流转，方便替换与测试；
- **评估体系**：任务成功率（端到端，按任务难度分层）+ **轨迹质量**（工具选择准确率、参数正确率、步数/成本效率）+ **可靠性**（幻觉频率=无依据断言占比、越权调用率、异常恢复率）+ SLO（延迟、token 成本）。幻觉度量：抽轨迹逐断言与检索证据比对（LLM-judge + 人工抽检校准）。

### Q9. 三个串行外部工具 + 高并发 → 端到端延迟高，怎么降？（MM一 16）

先归因（哪段工具最慢/是不是排队），再组合拳：

1. **依赖并行化**：3 个工具若逻辑上可并行/部分并行，改 DAG 并发执行（最大头）；
2. **消除工具内延迟**：预热连接（连接池/长连接）、无服务器冷启动预热、边缘部署就近调用；
3. **缓存**：工具结果缓存（参数哈希 + TTL）、语义缓存（相似请求复用）；
4. **异步与流式**：非阻塞调用 + 事件回调；先行流式输出（首 token 提前），工具结果增量渲染；
5. **限流排队治理**：入口限流 + 优先级队列，防高并发互相踩踏；舱壁隔离保证重请求不拖死轻请求；
6. **模型侧**：更小/更快的调用模型（工具决策不需要旗舰模型）、投机执行（预测工具结果先算，错了回滚）、KV prefix cache 复用系统提示；
7. **SLO 分级**：区分交互式（P99 卡死）与后台（吞吐优先）流量分开部署。

## 二、MiniMax：训练与对齐

### Q10. SFT 与 RLHF 训练目标的本质不同？为什么 SFT 后还要 RLHF？（MM实1 2、MM实2 3）

- **SFT**：**模仿学习**——最大化示范数据的对数似然 $\max \mathbb{E}_{(x,y)\sim D}[\log \pi_\theta(y|x)]$，学"人类怎么做"；监督信号是稀疏 token 级标签，分布是窄的高质量流形；
- **RLHF**：**偏好优化**——最大化学到的奖励下限约束 KL $\max_\pi \mathbb{E}_{r,x\sim\pi}[r(x,y)] - \beta\, \mathrm{KL}(\pi\|\pi_{ref})$，学"人类觉得什么更好"；可以在模型**自己生成的分布上**对比好坏（on-policy），修 SFT 数据覆盖不了的行为；
- **为什么 SFT 不够**：① SFT 只能克隆示范，无法表达"比 B 好多少"的偏好强度，也学不会示范里没有的解法；② 模型生成时会偏离示范分布（exposure bias），SFT 没有在自身分布上纠错的机会；③ 对齐目标（无害/有用/诚实）本质是偏好判断，用 RM/偏好损失直接优化更对题；④ RLHF 对负样本有梯度（抑制坏行为），CE 对负样本只有间接抑制。

### Q11. SFT 之后的 Post-Training 阶段有哪些方法？各自优化目标？（MM一 10）

时间线版图：

| 阶段 | 方法 | 优化目标 |
|---|---|---|
| SFT | 指令微调/Continued pretrain | 模仿示范：max log-likelihood |
| 偏好对齐 | **RM+PPO** | max reward − β·KL(π‖π_ref)（Q13） |
| 偏好对齐 | **DPO** | 直接偏好对数似然比：−log σ(β(Δlogπ_c − Δlogπ_r))（Q14） |
| 偏好对齐 | KTO/SimPO/IPO | 无配对偏好/无参考模型变体 |
| 群体相对 | **GRPO** | 组内相对优势，去 value model（Q15） |
| AI 反馈 | RLAIF / Constitutional | 用 AI 偏好标签替代人工 |
| 推理强化 | RLVR（o1/R1 式） | 可验证奖励（代码单测/数学答案）上做 RL，长思维链 |

### Q12. 微调 Qwen 的训练策略选择与 loss 设计考量？（MM一 11）

- **策略选择**：7B 以下 + 领域数据充分 → full fine-tune（效果上限高）；14B+ 或多任务快速迭代 → LoRA/QLoRA（省显存可多任务热切换，[11](./11-深度学习与训练.md) Q15）；数据 <1e4 条优先 LoRA 防过拟合；要学新语言/知识 → continued pretrain + SFT 两段；
- **loss 设计考量**：① **loss mask**——只对 assistant 段计损失（prompt/user 置 −100），多轮里系统段与用户段不清零会教模型复读用户（实现见 `sft_loss.py::sft_loss_multiturn`）；② **shift right** 对齐（Q22）；③ 类别/难度加权（难任务加权防被简单样本淹没）；④ packing 时按序列边界重算 position id 且注意力加块掩码（防跨样本泄漏）；⑤ 防灾难遗忘——混入 5-10% 通用数据/回放；⑥ 优化器 AdamW + cosine + warmup，梯度裁剪。

### Q13. PPO 在 RLHF 框架中优化的核心目标是什么？写出目标函数并解释每一项（MM实1 6、MM实2 4）

$$L^{\text{PPO}}(\theta)=\mathbb{E}_{(x,a)\sim\pi_{\theta_{old}}}\Big[\min\big(r_\theta A,\ \text{clip}(r_\theta,1\pm\epsilon)A\big)\Big] - \beta_1\,\mathrm{KL}(\pi_\theta\|\pi_{ref}) \big(+\beta_2\,(\hat v - V_\phi)^2\big)$$

RLHF 总目标：$\max_\theta \mathbb{E}[r_\phi(x,y)] - \beta\,\mathrm{KL}(\pi_\theta\|\pi_{ref})$（reward 最大化 + 不跑离 SFT 参考模型太远）。逐项：

- $r_\theta = \pi_\theta(a|x)/\pi_{old}(a|x)$：重要性采样比率；
- $A$（GAE）：优势估计——动作比平均好多少（critic $V_\phi$ 学出来的基线）；
- $\text{clip}(\cdot,1\pm\epsilon)$：限制单步策略更新幅度（信任域的一阶近似）；
- $\min$：取悲观界，ratio 偏离时不再放大梯度（防 reward hacking 惯性）；
- KL 惩罚：约束在 $\pi_{ref}$ 邻域（保语言质量、防模式坍塌），或实现为 reward 里的 −β·KL 项；
- value loss：训练 critic（PPO 是 actor-critic）；RLHF 工程再叠 **reward 归一化、长度惩罚（防啰嗦）、whitening**。

### Q14. PPO 与 DPO 的核心区别？DPO 训练要注意什么？（MM一 7）

**DPO 推导**：RLHF 目标有闭式最优解 $\pi^*\propto\pi_{ref}e^{r/\beta}$ → 反解 $r=\beta\log(\pi/\pi_{ref})+C$，代入偏好对 (y_w,y_l) 的 Bradley-Terry 模型，得**免 RM、免 RL** 的直接损失：

$$L_{\text{DPO}}=-\mathbb{E}\Big[\log\sigma\big(\beta[\log\tfrac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-\log\tfrac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}]\big)\Big]$$

- **核心区别**：PPO 三模型在线采样（actor+critic+RM，训练不稳、工程重）；DPO 离线偏好对 + 一个 reference 模型，二分类式监督训练，稳定便宜。代价：off-policy（不在自身分布上探索，上限通常略低、易过拟合）；
- **DPO 注意事项**：① 偏好对质量与多样性是生命线（噪声标签直接学坏）；② β 太大欠拟合/太小漂移过远；③ **chosen likelihood 下降现象**（损失降但正例概率也降——只拉开了差值），监控 Δlogπ 两边走向；④ **长度/格式偏置**（长答案更受偏好）→ 显式长度正则或配对去偏；⑤ 必须 good SFT 初始化（π_ref 决定地基）；⑥ 数据要 on-policy 化（用当前模型采样再造偏好标签，如 iterative DPO）。

### Q15. GRPO 简述（MM一 8、DeepSeek 系）

Group Relative Policy Optimization：去掉 PPO 的 critic（value model 与 policy 同量级，占显存/易偏），对每个 prompt 采一组（G 个）回答，用**组内相对奖励**做优势：$\hat A_i = (r_i - \text{mean}(r_{1..G}))/\text{std}(r_{1..G})$——组均值即基线，天然无 critic。策略损失沿用 PPO clip + KL(π‖π_ref)。优点：省一个模型、适合"结果可验证"的奖励（数学/代码，组内自然有好坏差）；缺点：每 prompt 要 G 次采样（rollout 成本×G）、全对全错组 advantage=0 无梯度。与 PPO 的关系一句话：GRPO = PPO 的 critic 换成"组内基线估计"，优势去均值后数学期望不变、方差更低。

### Q16. MoE 路由如何分配 token？负载不均的原因？利用率低怎么改进？（MM实1 3/4、MM实2 6/7）

- **路由机制**：router（门控）对每个 token 输出专家 logits → top-k（常用 k=2，Fine-grained 专家则 k=6~8）+ softmax 归一化权重 → 加权组合专家输出。DeepSeek-V3 细化：sigmoid 门控 + 偏置项 $\text{topk}(s_i + b_i)$，b 可学习并按负载动态调整；
- **负载不均原因**：① 专家容量因子 cap（每专家 token 上限）触发 token dropping；② router 初始化偏置 + 训练早期正反馈（强者愈强，"赢者通吃"坍缩）；③ 数据分布本身倾斜（某些领域 token 天然涌向某专家）；④ 辅助损失与主损失权重失衡；
- **改进手段**：**auxiliary load-balancing loss**（平均分配为目标，DeepSeek-V3 的无 aux-loss 版本更好——bias 调整而非梯度惩罚）；**router z-loss**（logits 过大惩罚，稳定路由）；**容量因子调优**（cap 放宽降 dropping，代价显存）；**token dropping 策略**（drop 的 token 走残差直通）；**EPLB 专家并行负载均衡**（按热度重排专家到卡）；**Dropless（MegaBlocks）**按需执行；数据层面 shuffle/重配比。

### Q17. MoE 为何参数涨而训练效率仍高？（MM实1 7、MM实2 2）

- **稀疏激活**：总参数 N 大，但每 token 只过 k 个专家 + attention/共享层 → 每 token FLOPs ≈ 稠密 N_active 模型，"参数量/计算量"解耦；通算比（总参/激活参）8-16× 常见；
- **算力效率**：同样训练 FLOPs 预算下，MoE 把容量花在专家宽度/数量上（记忆知识），attention 等每次都要算的部分不膨胀——loss/FLOP 更优（Chinchilla 之后的扩展新轴）；
- **工程效率**：专家并行（EP）把专家摊到多卡，all-to-all 通信与计算可重叠；专家 GEMM batch 大而规整，好打满；
- **代价**：显存要装下全部专家（部署痛点）、负载均衡难、通信量增加（每层两次 all-to-all）。

### Q19. ZeRO 三阶段切分什么？通信量与显存如何递进？（MM二 2）

### Q20. DP/TP/PP 的设计思想与适用条件？（MM二 3）

[07 分布式训练](./07-分布式训练.md) Q4/Q5/Q12 已详解，本篇速记：**DP**——每卡全模型不同数据，梯度 all-reduce 同步；适用单卡装得下、追求吞吐。**TP**——层内权重切到多卡（行/列切分），每层前后 all-reduce；适用单卡装不下且卡间带宽极高（NVLink 域内，≤8 卡）。**PP**——层间切微批次流水（1F1B/ZB1H 调度），点对点通信小；适用超大模型跨节点、吞吐容忍 bubble。组合范式：DP×TP（机内）×PP（机间），MoE 再叠 EP；选型顺序=先 TP 消除单卡显存墙 → PP/EP 跨机 → DP 兜底扩吞吐。

### Q21. 训练 70B 模型，单卡显存怎么粗算？（MM二 4）

以 Adam 混合精度训练，每参数字节账（公式与 ZeRO 关系见 [07](./07-分布式训练.md) Q3）：

- 参数 fp16 2B + 梯度 fp16 2B + 优化器态（fp32 master 权重 4B + m 4B + v 4B）= **16 B/参数**；
- 70B × 16 = **1120 GB**，单卡（80GB）显然放不下 → 至少 ZeRO-3/TP 跨 16 卡（70B）；再加**激活**（与 batch×seq 成正比，梯度检查点可压到 ~O(层数×隐藏维) 级别）与通信缓冲——经验再留 20-30% 余量；quick estimate：`总显存 ≈ 16Ψ + A·L·B·S·h`，A≈8-16（含重计算系数）。推理由 2Ψ（权重）+ KV cache 主导。

### Q22. 现场编程：PyTorch 写 SFT loss（shift right）（MM一 17）

完整工程实现（三种写法 + 多轮 loss mask + 等价性对拍）：`answers/torch_impl/sft_loss.py`，核心 8 行：

```python
def sft_loss(logits, labels, ignore_index=-100):
    shift_logits = logits[:, :-1, :].contiguous()   # 位置 i 的预测
    shift_labels = labels[:, 1:].contiguous()       # 位置 i+1 的目标(shift right)
    return F.cross_entropy(shift_logits.view(-1, logits.size(-1)).float(),
                           shift_labels.view(-1), ignore_index=ignore_index)
```

追问点：① 是 **label 左移**（logits 去尾、labels 去头），本质 next-token prediction；② `ignore_index=-100` 让 pad/prompt 段自动跳过且不进分母；③ 全 mask 序列 cross_entropy 会出 nan，工程上要特判返回 0；④ 等价性验证 `test_torch_impl.py::test_sft_loss_shift_semantics`。

## 三、阶跃星辰：训练系统

### Q25. 序列并行的实现原理、通信开销与进一步优化？（阶 4）

- **为什么**：TP 解决权重切分，但 **LayerNorm/Dropout/输出 logits 的激活随序列长度 S 膨胀**且不在 TP 切分范围内，长上下文时激活显存成墙；
- **Megatron-SP 原理**：LayerNorm/dropout 的计算沿序列维切到 TP 组各卡（每卡 S/t），进入 attention/MLP（需要完整 S）前 **gather**（all-gather 拼回 S）、算完 **scatter**（reduce-scatter 沿序列切回去并完成残差归约）。关键设计：这两个集合通信与 TP 原有的 all-reduce **融合**——reduce-scatter+all-gather 替代 all-reduce，总通信量不增加（详细推导见 [07](./07-分布式训练.md) Q5）；
- **其他两种序列并行**（面试加分）：**DeepSeek Ulysses**——把 head 维切到各卡，Q/K/V 用 **all-to-all** 转置成"每卡拿全部序列的若干 head"，注意力算完再 all-to-all 转回，通信量 O(S/N) 且一次 all-to-all；**Ring Attention**——KV 块沿环流动与本地 Q 块计算重叠，支持超大 S；
- **实测开销**：SP 通信在 NVLink 域内（与 TP 同组）延迟小，长序列（≥8K）显存收益远大于通信损失；跨机做 SP 则通信成为瓶颈，应换 Ulysses/Ring 系；
- **进一步优化**：与 TP 融合调度、通信-计算 overlap（cp.async 双缓冲 all-to-all）、异步 RR LAYERNORM（DeepSeek 把 LN 梯度归约异步化）、减少 gather 范围（只对必要算子 gather）。

### Q26. 训练稳定性与容错的常见方案？（阶 5）

- **数值稳定**：bf16 为主（动态范围大，免 loss scaling）或 fp16+动态 loss scaling；fp32 累加的归约/优化器主权重；梯度范数裁剪（如 1.0）；attention softmax 与 RMSNorm 的数值安全实现（减 max/eps）；混合精度下的随机舍入；
- **训练异常处置**：loss spike → 跳过 batch/回滚 checkpoint 重放并降 lr；NaN 检测 → 定位层（dump 激活统计）、跳过/缩放；MTP/辅助头等易溢出模块单独监控；
- **容错**：**checkpoint 周期保存 + 异步保存**（不阻塞训练，存到分布式存储）；**弹性训练**（torch elastic/Megatron-EL：节点故障缩容续训）；**straggler 检测与隔离**（慢卡降速全员等待 → 迁移或剔除）；NCCL timeout 调大 + 死锁检测（[03](./03-gemm与算子优化.md) Q9 千卡定位）；冗余副本/热备节点；数据管道幂等（dataloader 断点续读）。

### Q27. Infra 领域值得关注的前沿方向（阶 6）

开放题，按层各点一两个并说清动机：**kernel/硬件**——Hopper/Blackwell 的 TMA+warp specialization kernel 范式（FA3/cutlass 3.x）、FP8/FP4 训练与推理、NVLink5/NVSwitch 拓扑；**推理系统**——PD 分离与 KV 传输网络（Mooncake/NIXL）、投机解码（EAGLE-3/MTP）、continuous batching 与 SLO 调度、长上下文稀疏注意力落地（NSA/DSA 的 kernel 化）；**训练系统**——MoE 大规模 EP（DeepEP 的 node/HD 内分层 all-to-all）、异步/1F1B overlap、Moonlight 式 KV 卸载；**RL 基建**——rollout 引擎与训练引擎复用（veRL/OpenRLHF 的 colocate vs 分离）、大 batch 采样调度；**编译**——torch.compile/Triton 的自动融合与 shape 泛化、AI 生成 kernel（[03](./03-gemm与算子优化.md) Q12）。答法：选自己最熟的一条讲出"现状瓶颈 → 代表工作 → 还没解决什么"。

**区间调度**（阶 7）核心 6 行——按结束时间贪心，结束早的先选给后面留最大余地（交换论证可证最优）：

```python
def max_complete_activities(shows):
    chosen, last_end = [], float("-inf")
    for start, end in sorted(shows, key=lambda s: s[1]):
        if start >= last_end:
            chosen.append((start, end)); last_end = end
    return chosen
```

追问点：为什么按结束而非开始排序（反例：超长节目开头最早）；区间调度（max 不相交）与会议室 II（max 重叠数，`algorithms/dp.py::min_rooms_meetings`）是一体两面；带权区间调度要 DP。
