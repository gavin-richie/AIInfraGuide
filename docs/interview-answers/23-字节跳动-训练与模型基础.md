## Q1. DeepSpeed 框架的核心设计理念和主要功能（实习-一面-4 基础知识 1）

同《07 分布式训练》Q12。理念一句话：**把大模型训练的状态（参数/梯度/优化器状态）当作显存问题来工程化**，用"以通信换显存"的显存-计算-通信三角权衡换大模型可训性。主要功能矩阵：

| 功能 | 机制 | 解决什么 |
|---|---|---|
| ZeRO 1/2/3 | 优化器状态/梯度/参数分片 | 显存墙（见 Q2） |
| ZeRO-Offload/Infinity | 状态卸载 CPU/NVMe | 单卡/极少卡训大模型 |
| ZeRO++ | 通信量化 + 分片层次化 | 通信量 |
| DeepSpeed-MII / Inference | 推理引擎 | 部署 |
| 1-bit Adam/Lion | 梯度压缩 | 通信带宽 |

## Q2. 选择 ZeRO Stage 3 的原因，推导显存节省公式（实习-一面-4 基础知识 2）

同《07》Q3（含三阶段通信量对比与"论文与代码的差距"）。混合精度下每参数的显存构成（Adam，单卡未切分）：

| 状态 | 每参数字节 |
|---|---|
| FP16 参数 + FP16 梯度 | 2 + 2 |
| FP32 master 权重 + 一阶动量 + 二阶动量 | 4 + 4 + 4 |
| **合计** | **20 B/参数** |

7B 模型单机单卡：14GB × ... = 7e9 × 20B = **140GB**（远超单卡，且还没算激活）。ZeRO-3 把三类状态全部按数据并行度 $N_d$ 切片，每卡稳态只持有 $\frac{1}{N_d}$：

$$\text{显存/卡} = \frac{20\Psi}{N_d} + (\text{通信时短暂 all-gather 的参数分片})$$

- **公式**：混合精度 + ZeRO-3 + Adam，$\Psi$ 参数量、卡数 $N_d$：稳态 $16\Psi/N_d$（参数+梯度 FP16）+ $12\Psi/N_d$ 优化器状态... 合计即 $20\Psi/N_d$，对比 DP 的 $20\Psi$；
- 64 卡 100B 模型：$2000\text{GB}/64 ≈ 31\text{GB}$/卡 → 单卡可训；
- **为什么选 3 而不是 1/2**：模型大到 1/2 仍放不下参数本身；代价是前向/反向各一次 all-gather（通信量 $\approx 2\times$ DP 的 1.5 倍梯度 all-reduce），用通信换显存（《07》Q3 的通信量表）。
- 激活显存另算：checkpointing 折半（$\sqrt{}$ 级缓存，见《07》Q13 训练慢排查与 Q8 显存优化全景）。

## Q3. 除 DeepSpeed 外的分布式训练框架及区别（实习-一面-4 基础知识 3）

| 框架 | 路线 | 特点 |
|---|---|---|
| Megatron-LM（NVIDIA） | TP/PP/SP/EP 的"张量级"并行 | 为 NV 互联优化（NCCL），模型代码需按其并行模式改造；业界大预训练主力（+Megatron-Core/LMFlow 生态） |
| FSDP（PyTorch 原生） | ZeRO-3 思想的官方实现 | 与 PyTorch 无缝（DTensor/完全分片 DataParallel），HuggingFace Trainer 一键开；复杂拓扑支持弱于 Megatron |

选型口径：百亿以下 FSDP/DeepSpeed-2 最省事；千亿以上 Megatron 系 TP+PP+SP 是事实标准；显存极限场景 DeepSpeed ZeRO-3 + Offload。维度差异本质：**切什么（数据/张量/流水）+ 谁来切（用户标注/编译器自动）+ 通信时机**。

## Q4. BLIP 与 BLIP-2 的主要区别；当前主流多模态架构（实习-一面-4 基础知识 4）

**BLIP**（2022）：单阶段预训练一个 **CapFilt** 结构——image encoder（ViT）+ text encoder + text decoder 共享大部分权重，额外训一个"过滤头"用 LLM 生成伪标注清洗网络噪声图文对；理解（检索）与生成（caption）任务统一。

**BLIP-2**（2023）核心变化：**冻结单模态模型 + 轻量桥接**。

1. 冻结 ViT 与冻结 LLM（两种 LLM 都试：OPT 生成式 / FlanT5），只训中间的 **Q-Former**（见 Q5）——预训练成本骤降（比端到端小 ~54 倍）；
2. 两阶段训练：第一阶段表征学习（ITC/ITM/ITG 三个损失，query 与图文对齐），第二阶段把 Q-Former 输出投影成 LLM 的 soft prompt 接到冻结 LLM 上做生成；
3. 区别一句话：BLIP 是"自己训一个图文都懂的模型"，BLIP-2 是"站在两个冻结巨人之间的翻译官"。

**当前主流多模态架构**（回答要体现 2024-2026 演进）：

| 范式 | 代表 | 特点 |
|---|---|---|
| 轻量桥接（prompt 层融合） | BLIP-2、Flamingo（gated x-attn） | 保留冻结 LLM，训练便宜，天花板受限 |
| Projection-only | LLaVA 系（MLP projector） | 极简：ViT 特征线性投影进 LLM 词嵌入空间，指令微调效果好，已成开源标配起点 |
| 原生多模态早期融合 | GPT-4V/Qwen-VL/InternVL、Fuyu | 视觉 token 化（ViT/patch 直接入 LLM 或专用 vision tower + 深度适配）、端到端联合训练 |
| Diffusion 生成侧 | Stable Diffusion（CLIP 文本编码 + U-Net）、DiT | 文生图管线，与 LMM 对称 |

## Q5. Q-Former 的设计原理和作用（实习-一面-4 基础知识 5）

**结构**：一个带 **32 个可学习 query 向量**的轻量 Transformer（~188M），一侧 cross-attend 图像特征，另一侧与文本自注意交互。

**要解决的问题**：图像特征数（257 个 patch token）与 LLM 期望的输入（几十个 token）不匹配，且冻结两边的表征空间差异大——直接拼会浪费 LLM 上下文且对不齐。

**原理**：

1. 32 个固定 query 把任意分辨率/任意 patch 数的图像特征"蒸馏"成**固定长度 32 个向量**——信息瓶颈 + 输出定长；
2. query 之间共享参数地与文本任务联合训练（ITC 图文对比 / ITM 图文匹配 / ITG 图像条件文本生成），迫使 query 学会"抽取与文本语义相关的视觉表示"——相当于**可学习的、任务感知的池化**；
3. 第二阶段投影为 LLM 的 soft prompt，等效于"把图压缩成 32 个视觉词"喂给 LLM。

**作用总结**：压缩（257→32）、对齐（视觉→语言语义空间）、解耦（冻结的单模态骨干可随取随换，Q-Former 复用）。后继演进：LLaVA 用实验证明一个 2 层 MLP projector 在足够指令数据下也能打平甚至超过 Q-Former（"够好的对齐 + 够多数据 > 精巧结构"）——这是面试很好的观点分。

## Q6. 内容理解任务的技术路线；chart-to-story 模型的数据构造（实习-一面-4 训练优化 6）

**内容理解（chart/文档图像 → 结构化/叙述）技术路线**：

1. **判别式小模型时代**：图表元素检测（目标检测出轴/图例/数据点）+ OCR + 规则解析成表格/数值——精确但泛化差、管线脆；
2. **VLM 端到端**：视觉编码（ViT/DocVLM）+ LLM，输出结构化（表格 markdown/JSON）或自然语言描述；当前主流；
3. **两段式混合**：VLM 出草稿 + 程序化校验（数值一致性、表格语法）回修——生产环境常用。

**chart-to-story 数据构造**（考数据工程能力，按"来源-规模-质量"答）：

- **合成打底**：程序化生成图表（matplotlib/ECharts 参数随机化：图型×主题×字体×噪声），**标签免费且精确**（生成参数即 GT 数值），可造百万级；覆盖配额按图型/复杂度/数值范围分层采样防偏；
- **真实图表对齐**：爬取/购买带上下文的报告图表，人工或半自动（强模型预标 + 人审）转写"故事"叙述；解决合成与真实的 domain gap；
- **任务分层构造**：元素识别 → 数值抽取 → 趋势总结 → 洞察叙述（推理链 CoT 标注：图表事实 → 统计观察 → 业务解读），训练从易到难混合；
- **质量闭环**：数值一致性校验（叙述中的数字必须能在图中找到）、反例构造（改数值造"文不对图"负样本教模型不自嗨）、去重与均衡；
- **配比**：合成:真实 ≈ 7:3 起步，SFT 后用真实数据 DPO/RLHF 对齐语气与深度。

## Q9. Efficient Attention、MoE、分布式训练在工业场景的实际效果（实习-一二三面 三面 17）

开放题，答"真实数字 + 边界条件"（有论文/工业报告背书的数据）：

- **Efficient Attention**：FlashAttention 训练提速 2-4×（端到端 BERT-large 15%↑，GPT 训练注意力段 3×）且已标准化（所有框架默认）；稀疏/线性 attention 论文多但工业落地少——长文本窗口 + 滑窗 + KV 淘汰（H2O 等）在推理侧更实用（省 KV 显存 2-10×）；
- **MoE**：同等训练算力下质量显著优于 dense（Switch：7× 参数仅 1/5 稀疏计算打平 dense）——DeepSeek-V3（671B 总参/37B 激活）证明 MoE + 细粒度专家是前沿标配；代价是显存（全部专家驻留）、all-to-all 通信、负载均衡调参；
- **分布式训练**：TP+PP+DP 让千卡线性度做到 80-90%（MFU 40-55% 是大模型常态口径），NCCL/重叠通信是基建核心；回报是"能训"与"训得快"两个量级。
- 总结句：三者分别解决**访存、算力效率、规模**三个不同瓶颈，正交叠加；工程上"效果"最终都以 MFU/_tokens per dollar/单位算力质量 三个指标汇报。

## Q10. 过拟合的解决方案；L1 与 L2 的区别；L2 的导数形式（抖音 基础知识 1）

**方案**：数据侧（增数据/增强）、模型侧（降容量/早停/ dropout）、训练侧（正则化/权重衰减/标签平滑/集成）、验证驱动（early stopping 以验证集为准）。

**L1 vs L2**（$L = L_0 + \lambda\sum|w_i|$ vs $L = L_0 + \lambda\sum w_i^2$）：

| | L1 | L2 |
|---|---|---|
| 梯度（对 $w$） | $\lambda\,\text{sign}(w)$ 恒定大小 | $2\lambda w$ 与 $w$ 成比例 |
| 约束区域形状 | 菱形（顶点在轴上） | 圆形 |
| 解的特性 | **稀疏**（推向 0，特征选择） | 小而不为 0（权重收缩） |
| 0 点处 | 不可导（次梯度），$w$ 一步跨过 0 后仍被拉回 | 平滑，靠近 0 越拉越轻 |

几何直觉：损失等高线与约束区域相切的点落在顶点 → L1 产生稀疏解。

**L2 导数**：$\frac{\partial L}{\partial w} = \frac{\partial L_0}{\partial w} + 2\lambda w$；代入 SGD 更新 $w \leftarrow w - \eta(\nabla L_0 + 2\lambda w) = (1-2\eta\lambda)w - \eta\nabla L_0$——每步先按 $(1-2\eta\lambda)$ **衰减**再走梯度，故 L2 正则 ≡ weight decay（Adam 下两者不等价，AdamW 修正的正是这个耦合，《11》Q14）。

## Q11. Dropout 在训练与推理阶段的行为差异（抖音 基础知识 2）

同《11 深度学习与训练》Q8。训练以 $p$ 概率置零并按 $1/(1-p)$ **放大**（inverted dropout，训练期完成缩放）；推理**不 dropout 也不缩放**（整网络确定性前向，期望已对齐）。测试中 `model.eval()` 忘调是经典 bug——顺带说明 eval/train 模式还控制 BN 统计（《11》Q1）。变体：DropConnect、R-Drop、LLM 训练的 attention dropout/residual dropout。

## Q13. 特征筛选的常用方法（抖音 基础知识 4）

三大类 + 工业 RD 顺序：

1. **过滤式（filter，先筛后模型）**：单变量统计——方差过滤（近常量剔除）、Pearson/Spearman 相关、互信息/卡方（与标签的关联度）、ANOVA F 值；一次性处理海量特征，快但忽略交互；
2. **包裹式（wrapper，以模型为准）**：前向/后向/递归特征消除（RFE），交叉验证评分子集——质量高、组合爆炸慢；
3. **嵌入式（embedded，训练中自带）**：L1 正则（稀疏系数即选择，Q10）、树模型 feature importance（gain/split）、permutation importance（训练后打乱单特征看掉点，模型无关）、SHAP（一致性的归因）。
4. 工业推荐系统口径：先 IV 值/PSI 稳定性粗筛 → 树模型重要性 + 精排模型消融 → 线上保留可控集合；注意 label leakage 检查（过于强的特征先怀疑穿越）。

## Q14. 常见机器学习模型；树模型与线性模型的对比（抖音 基础知识 5）

模型地图：线性（LR/线性回归/Ridge/Lasso）、SVM、树系（决策树/随机森林/GBDT 系 XGBoost、LightGBM、CatBoost）、神经网络（MLP/CNN/Transformer）、无监督（聚类/降维/异常检测）。

| 维度 | 线性模型（LR） | 树模型（GBDT） |
|---|---|---|
| 表达能力 | 线性边界（需手工交叉特征） | 非线性、自动特征交互 |
| 特征工程 | 重（组合/离散化） | 轻（原始特征直接喂） |
| 类别/缺失值 | 需 one-hot/impute | 原生支持（CatBoost/LGBM） |
| 外推 | 边界外可外推（有先验） | 训练分布外恒值（不可外推） |
| 可解释 | 系数即重要性 | importance/SHAP |
| 规模 | 大规模稀疏（推荐 CTR 主力之一） | 中大规模稠密，表格数据 SOTA |
| 在线更新 | 方便（SGD） | 增量较难（重新拟合） |

工业口径：**表格/小数据 GBDT 常胜**（"两类问题：NN 与其他，其他里 GBDT 是王"）；**大规模稀疏 CTR** 传统 LR+FE 或 FM/DeepFM 双塔；NN 赢在原始多模态输入与极大标注量。

## Q15. CLIP 的训练原理（抖音电商 基础知识 8）

**双塔对比学习**：image encoder（ViT/ResNet）与 text encoder（Transformer）分别嵌入，batch 内 $N$ 对图文做 **InfoNCE**：相似度矩阵（$N \times N$，对角为正样本），对称 cross-entropy 拉近配对、推远非配对：

$$L = -\frac{1}{2N}\sum_{i=1}^N\left[\log\frac{e^{sim(I_i,T_i)/\tau}}{\sum_j e^{sim(I_i,T_j)/\tau}} + \log\frac{e^{sim(T_i,I_i)/\tau}}{\sum_j e^{sim(T_i,I_j)/\tau}}\right]$$

要点：① **温度 $\tau$ 可学习**（控制分布锐度）；② 对比目标**只在 batch 内互斥**，故效果依赖大 batch（32768）+ 海量弱监督对（4 亿 WIT）；③ 双塔结构使检索可以预索引（零样本分类 = 与各文本模板算相似度 argmax）；④ 局限：细粒度/计数/密集任务弱，后续 BLIP/DINO 补。**作用**：开放词表视觉分类、跨模态检索、扩散模型文本条件编码器（SD 的 text encoder 即冻结 CLIP）。

## Q16. Multi-Head Attention 的原理（抖音电商 基础知识 10）

同《04 Attention 与 KV Cache》Q5：$Q=XW^Q$ 等三投影 → 切 $h$ 头各自 $\text{softmax}(Q_iK_i^T/\sqrt{d_h})V_i$ → 拼接过 $W^O$。**为什么要多头**：单头 softmax 平均掉多种关注模式，多头允许在不同子空间关注不同关系（语法/位置/语义），且 $d_h = d/h$ 时总计算量与单头相同；scale $1/\sqrt{d_h}$ 防内积方差 $d_h$ 增大把 softmax 推向 one-hot 梯度消失。手写实现（self/cross/causal 三变体）：`solutions/python/src/answers/attention/mha.py`，与 SDPA 对拍。

## Q17. LoRA 的原理；秩 r 的大小对训练的影响（抖音电商 基础知识 11）

同《11 深度学习与训练》Q15（原理、B=0 初始化、推理可合并、部署零开销）。r 的影响口径：$\Delta W = BA$（$B_{d\times r}, A_{r\times k}$），r 是**增量权重的秩上界**——r 小（1-8）：只学低秩主方向，参数少易训但容量受限，简单任务/大模型适配够用；r 大（32-256）：表达力强但过参数化易过拟合、显存与合并开销升，复杂知识注入（继续预训练/新语言）需要。经验：r 与目标模块比例（α = 2r 常用）、注意力 QV 优先；每层秩需求不同（AdaLoRA 自动分配）。代码：`solutions/python/src/answers/torch_impl/lora.py`。

## Q18. ViT 的训练原理（抖音电商 基础知识 12）

1. **输入 token 化**：图像切 16×16 patch → 线性投影成 token（+可学习 [CLS] + 位置嵌入，1D 即可，2D 无明显增益）；
2. **主干**：标准 Transformer encoder（MHA + FFN，LayerNorm 残差结构）；
3. **头**：[CLS] 接线性分类器（或 GAP）。
4. **训练特性（追问核心）**：ViT **缺乏 CNN 的归纳偏置**（局部性/平移等价），中小数据集（ImageNet-1k 从头训）不如 CNN；**大数据（JFT-300M/2B 预训练）反超**——"规模换先验"；预训练用强监督或掩码（MAE 自监督：75% mask 重建像素，ViT 的"BERT 时刻"）。
5. 后续：DeiT（蒸馏+数据高效）、Swin（层级化，Q19）、DINOv2（自监督通用特征）。视觉 token 化思想是所有多模态 LLM 的输入端基石（Q4/Q5）。

## Q19. Swin Transformer 的核心设计思想（抖音电商 基础知识 13）

把 ViT 改造成**层级化（hierarchical）+ 局部窗口（window）**的通用视觉骨干：

1. **W-MSA（窗口自注意）**：attention 限制在不重叠的 7×7 局部窗口内，计算量从图像平方 $O(HW)^2$ 降到线性 $O(HW \cdot w^2)$——大分辨率可行；
2. **SW-MSA（移位窗口）**：相邻层窗口划分错开半个窗口（⌊w/2⌋），跨窗口信息通过"错位的窗口"逐层传播——用划分巧思替代全局注意；实现上做 cyclic shift + attention mask 处理跨界的块；
3. **层级化**：patch merging 每 stage 合并 2×2 邻块降分辨率、通道翻倍——像 CNN 的金字塔，天然接多尺度任务（检测 FPN/分割 UPerNet）；
4. **相对位置编码**（窗口内相对偏移的 bias 表）替代绝对位置。

一句话对比：ViT 是"整图一窗、全局注意、单尺度"；Swin 是"局部窗口 + 移位跨窗 + 金字塔"，通用视觉任务（检测/分割）当时的 SOTA 骨干。

## Q20. Qwen3 中快思考与慢思考的实现原理（抖音电商 基础知识 14）

Qwen3（2025）用**一个模型 + 思考预算开关**统一两模式（对比:分开训两个模型如 R1-distill vs 直答版）：

1. **数据与训练**：预训练数据混入长链推理（数学/代码 CoT）与普通语料；后训练分四阶段——长思维链冷启动 SFT → 推理强化学习（RL on 可验证奖励）→ **思考模式融合 SFT（把 <think> 长推理与无 <think> 直答统一在同一模型）** →通用 RL——融合阶段保证单模型内两模式共存；
2. **推理控制**：chat template 里 `enable_thinking` 开关（软切换——同权重）；思考预算 `thinking_budget` 上限：达到预算注入"停止思考"引导直接给答案——快慢连续可调而非二元；
3. **机理**：慢思考 = 生成 <think>...</think> 中的长 CoT（test-time compute 换准确率），快思考 = 跳过该段直接答；两模式由模板 token 引导同一权重进入不同"分布区域"，训练时的融合 SFT 是不互相干扰的关键；
4. 使用侧收益：线上按 SLO 选模式（高频简单 query 快思考，复杂 query 慢思考），配合推理引擎对 <think> 段流式隐藏与 KV 管理。

（对比 OpenAI o1/o3 与 GPT-4o 的"双模型"路线、Claude 的 extended thinking 开关——答出"单模型统一 vs 双模型"的 tradeoff 是加分点。）

## Q21. Decoder-only 架构为什么成为当前大模型的主流选择（豆包 基础知识 1）

1. **训练目标统一且高效**：next-token prediction 每个位置都是监督信号（密度 100%），无 [MASK] 与预训练-微调偏差（BERT 的 MLM 只看 15% 且双向）；encoder-decoder 的 cross-attention 路径无监督复用；
2. **因果 mask 天然适配生成**：训练即推理（teacher forcing → decode 自回归无缝），KV cache 顺理成章（左到右不改写历史，见《20》Q1）；
3. **scaling 友好**：GPT 系列验证同架构从 1 亿到万亿无损外推；模型与算力（线性序列注意 + 因果裁剪）匹配度好；
4. **任务统一**：prompt/指令/少样本全部塞进前缀（GPT-3 in-context learning），无需任务头——translate/QA/summarize 同一目标；
5. **工程生态**：flash attention 的因果块裁剪、投机解码、prefix cache 全围绕 decoder 优化；encoder 双向注意的这些优化都更复杂。
6. 反例边界（体现思辨）：双向编码仍有优势的场景——embedding/检索（BERT 系仍主流）、理解型小模型、NLU 评测；填空类（FIM 补全，代码模型用双向式 objective 补齐）。

## Q22. Qwen2 的模型结构；相较 Qwen1 的改进（豆包 基础知识 2）
