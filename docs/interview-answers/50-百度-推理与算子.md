## Q1. Attention 机制的原理；近期模型的注意力机制（一1 Q2）

标准 scaled dot-product attention：$\text{Attn}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$。Q 是查询（当前 token "想找什么"），K 是键（每个 token "能被如何检索"，与 Q 做相似度打分），V 是值（检索到的内容本身）；多头 = 在 $d_{model}$ 上切 h 份独立做注意力再拼接，让不同头关注不同子空间（句法/共指/位置邻近）。

近期模型的演进（按论文/产品线答 2-3 个即可）：

- **稀疏/线性注意力系**：Longformer（滑窗+全局）、Performer（随机特征近似 softmax 核）、线性 attention（$\phi(Q)(\phi(K)^\top V)$ 消二次项）；
- **效率系（推理主流）**：**MQA/GQA**（多查询/分组查询，压 KV Cache，Llama-2 70B/Gemma 用 GQA）、**MLA**（DeepSeek，低秩 KV + 权重吸收，容量≈MHA、开销≈MQA）；
- **长上下文系**：NSA/DSA（DeepSeek-V3 系原生稀疏注意力）、MoBA（混合专家式分块注意力）、Mamba/RWKV（状态空间模型的线性递归替代 attention）；
- **多模态/变长**：ViT 的无掩码双向注意力、DiT（patch token 化后标准 MHA + adaLN）。

详解与手写实现见 [04 Attention 与 KV Cache](./04-attention与kvcache.md) Q4/Q5。

## Q2. QKV 中 K 的作用？能否省略 K 直接用 V？（一1 Q3）

K 的作用是提供**检索键**：与 Q 做点积得到"该 token 对当前 token 的重要性"，V 才是被加权的**内容**。二者角色不同：K 决定"看谁"，V 决定"看到什么"。

省略 K（即 $S=QV^\top$，再用 softmax(V) 加权）的问题：

1. **语义退化**：打分矩阵 $QV^\top$ 不再是"查询-键匹配"，而是查询与内容的内积——检索与内容耦合，注意力分布失去可解释的相似度结构；
2. **对称性破坏**：标准注意力中 K 使每个 token 的"被检索接口"与"输出内容"解耦（等价于对 value 做了一次可学的线性投影重排）；去掉 K 相当于强制 value 空间=检索空间，表达力下降；
3. **数值问题**：$QV^\top$ 无 $\sqrt{d_k}$ 缩放意义，且 V 无界时 logits 方差不可控。

反例直觉：如果 K=V 恒等（即省略投影），softmax($QV^\top$)V 是"用内容自相似度加权内容"——退化为对输入做一次非线性平滑，多头各方向的表达被压扁。**实验角度**：去掉 K 的消融在同等参数预算下困惑度显著变差。相关变体：线性注意力确实把 K/V 都做核映射 $\phi$，但那是"换近似"而不是"删 K"。

## Q3. BatchNorm / LayerNorm / RMSNorm 对比（一1 Q4、实一1 Q3 追问）

计算与统计维度全解见 [11 深度学习与训练](./11-深度学习与训练.md) Q1。**RMSNorm 比 LayerNorm 快的原因**（实一1 特有追问）：

- 计算量：LN 要两次归约（mean + var，其中 var 又依赖 mean，实际是 mean(E[x]) 与 E[x²] 两次求和可并行）+ 一次减法平移；RMSNorm 只需 $E[x^2]$ 一次归约，去掉减均值步骤，访存与计算各省一截；
- 数值：不需要维护减法后的 $\hat x$ 中间量，寄存器压力更小，kernel 更好融合（fused add + RMSNorm + residual 一把算完，见本篇 Q15 与 `solutions/python/src/answers/baidu/fused_add_rmsnorm.py`）；
- 效果：多篇工作（原论文、Llama 系）表明去掉 mean-centering 精度几乎无损。

## Q4. 常见位置编码方式与特点（一1 Q5、二2 Q5 前半）

- **绝对正弦**（原版 Transformer）：固定 $\sin/cos$ 不同频率，可外推、无参数，但绝对位置对相对关系表达弱；
- **可学习绝对**（GPT-2/BERT）：一张 $L_{max}\times d$ 查表，效果常略优于正弦，但外推差（超长直接没表）；
- **RoPE 旋转位置编码**（Llama 系主流）：对 Q/K 按 2D 旋转矩阵作用于不同频率分量，$q_m^\top k_n$ 只依赖相对位置 $m-n$——"绝对形式实现相对性质"。长上下文局限（二2 特有追问）：训练长度外推时高频分量旋转角周期错位 → 需要 NTK-aware 缩放 / YaRN / 位置插值（PI）等重标定；数值细节见 [04](./04-attention与kvcache.md) Q8；
- **ALiBi**（BLOOM）：注意力打分直接加线性距离惩罚 $-b\cdot|m-n|$，免编码、外推平滑；
- **相对位置偏置**（T5/DeBERTa）：bias 表按相对距离查。

## Q5. Transformer 从输入 token 到输出 logits 的完整流程（二2 Q1、实2 Q17）

按推理路径答：`tokenize → embedding(+位置) → N × Block → 最终 norm → lm_head`。每个 Block：

1. **输入嵌入**：id → 查 embedding 表得 $x\in\mathbb{R}^{L\times d}$（Llama 无额外位置编码，RoPE 在每层 attention 里注入）；
2. **Attention 分支**：$x\to$ RMSNorm → QKV 三投影（GQA 时 KV 头少）→ Q/K 加 RoPE → scaled dot-product（causal mask，推理带 KV Cache）→ O 投影 → residual add；
3. **FFN 分支**：RMSNorm → SwiGLU（gate 投影 + up 投影，SiLU(gate)⊙up，down 投影回 $d$；升维倍数 ~2/3·4h，Llama-2 7B 为 11008）→ residual add；
4. **输出**：最后一个 RMSNorm → lm_head（$d\times V$ 投影）→ logits → 采样（greedy/temperature/top-p）。

训练时差异：无 KV Cache（teacher forcing 全并行）、后接 CE loss（shift 一个 token 对齐标签）、dropout 开启。

## Q6. FFN 为何先升维再降维？对表达能力的影响（二2 Q2）

- **动机 1：Token mixing 的非线性空间**。FFN 是 per-token 的"键值记忆"（Geva et al. 观点）：升维后的每个中间维度是一个可学的特征检测器，SiLU/GeLU 门控筛选，再由降维加权合成——$d\to 4d\to d$ 把输入投到更高维空间做非线性可分，再压回；
- **动机 2：与 attention 分工**。attention 负责跨 token 信息搬运（token mixing），FFN 负责逐 token 特征变换（channel mixing），升维给后者足够的"记忆槽位"；
- **表达影响**：中间维太小 → 记忆容量不足、欠拟合；过大 → 参数/显存/延时增长且边际收益递减。经验上 4× 是经典配置；MoE 可以看作"超宽 FFN 稀疏激活"，等效扩展中间维而不等比增加 FLOPs；
- **追问**：Llama 用 SwiGLU 后系数从 4 变 $8/3$（≈2.67×），因为 gate/up/down 三个投影多一份参数，调整倍数保持总参数量对齐。

## Q7. MHA/MQA/GQA 在推理阶段的 KV Cache 与效率差异（二2 Q3、一1 Q2 相关）

设层数 $L$、KV 头数 $h_{kv}$、头维 $d_h$、序列长 $S$、batch $B$、精度 $b$ 字节：

$$\text{KV} = 2\,L\,h_{kv}\,d_h\,S\,B\,b$$

- **MHA**：$h_{kv}=h$（如 32）——KV Cache 最大，decode 阶段读 KV 是带宽瓶颈，batch 上不去；
- **MQA**：$h_{kv}=1$——KV 缩小 $h$ 倍，但所有 Q 头共享一组 KV，质量略掉；
- **GQA**：$h_{kv}=g$（如 8，Llama-2 70B）——折中：KV 缩小 $h/g$ 倍，质量接近 MHA（分组内共享）；
- 计算量三者 Q 投影后的 attention FLOPs 相同（Q 头数不变），差别在**访存**：decode 每 token 读 KV 的量 $\propto h_{kv}$，GQA/MQA 直接线性下降 → 更大 batch / 更长上下文。MLA 更进一步（低秩压缩 + 解码时吸收进 Q/O 投影，KV 只存 $d_c$  compressed 向量），详见 [04](./04-attention与kvcache.md) Q3/Q5。

## Q8. 推理为何只缓存 K/V 不缓存 Q？（二2 Q4）

生成第 $t$ 个 token 时，attention 的 query **只有当前 token 的那一行**（自回归因果性：历史 token 的输出已经"写进"了 $t-1$ 步之前的输出与 KV），历史 Q 在后续步中不再参与任何计算——缓存它没有复用价值。K/V 不同：每个新 token 的 Q 都要和历史**所有**位置的 K 打分、给 V 加权，历史 K/V 逐步复用，故缓存。补充：prefill 阶段整个 prompt 的 Q/K/V 一次算完，K/V 写入 cache 供 decode 用；Q 用完即弃。

## Q9. FlashAttention 核心原理与数学推导（实一1 Q1、实一3 Q9，百度最高频）

**问题**：标准 attention 物化 $S=QK^\top$、$P=\text{softmax}(S)$ 两个 $N\times N$ 矩阵，HBM 写回再读取——访存 $O(N^2)$，长序列下显存和带宽都爆。

**数学核心：softmax 的分块不变性 + online rescaling**。把 Q/K/V 分块（块长 $B_r/B_c$），对第 $i$ 个 Q 块维护运行中的 $(m_i, \ell_i, O_i)$（行最大值、指数和、未归一化输出）：

$$m_i^{(t)}=\max(m_i^{(t-1)}, \max_{j\in \text{block}_t} \frac{q_i^\top k_j}{\sqrt{d}}),\qquad
\ell_i^{(t)}=e^{m_i^{(t-1)}-m_i^{(t)}}\ell_i^{(t-1)}+\sum_{j\in \text{block}_t}e^{\frac{q_i^\top k_j}{\sqrt d}-m_i^{(t)}}$$

$$O_i^{(t)}=e^{m_i^{(t-1)}-m_i^{(t)}}O_i^{(t-1)}+\sum_{j\in \text{block}_t}e^{\frac{q_i^\top k_j}{\sqrt d}-m_i^{(t)}}v_j,\qquad
O_i=\frac{O_i^{(\text{final})}}{\ell_i^{(\text{final})}}$$

正确性验证（归纳法）：每步对旧累加器乘 $\alpha=e^{m_{old}-m_{new}}$ 重缩放，等价于把历史贡献的分母从 $e^{m_{old}}$ 平移到 $e^{m_{new}}$ 基准——最终 $O_i^{(T)}=e^{-m_i}\sum_j e^{s_{ij}}v_j$，除以 $\ell_i$ 后与精确 softmax 一致。减 $m$ 保证 $e^{s-m}\le 1$ 不上溢。

**工程核心**：分块后 $S/P$ 碎片驻留 SRAM（shared memory/寄存器），Q/K/V 每元素只从 HBM 读一次、输出只写一次——HBM 访存 $O(N^2 d^2/B_r)$ 级别的大幅下降（精确地说从 $O(N^2)$ 元素级物化变为 $O(Nd)$ 流式），且精确无损（区别于稀疏/线性近似）。

**逐块数值演示**：`solutions/python/src/answers/baidu/fa_math.py` 的 `fa2_forward_with_trace()` 记录每个 KV 块处理后的 $(m,\ell,\alpha)$ 中间量并逐步对拍精确 attention——面试时可直接口述这份轨迹。v1/v2 差异、Bc 切分见下题。

## Q10. FlashAttention v1 与 v2 的区别；Bc 块切分与 1-loop 实现（实一3 Q10/Q11）

见 [04](./04-attention与kvcache.md) Q1/Q2 的全解，要点：

- **循环结构**：v1 外层 K/V、内层 Q——一个 KV 块被多个 Q 块用，中间结果 $O_{ij}/\ell_{ij}$ 必须写回 HBM；**v2 交换为外层 Q、内层 KV**（即"1-loop"：单个 Q 块的完整循环在一份寄存器状态内跑完），$(m,\ell,acc)$ 全程驻留寄存器，一个 Q 块只写回最终输出一次；
- **非 matmul 计算**：v2 把逐行 rescale 尽量合并（循环结束才做一次除以 $\ell$；块间重缩放用乘 $\alpha$ 的 FMA），非 GEMM FLOPs 占比从 v1 的 ~1/3 降到极低——Tensor Core 利用率上来；
- **并行度**：v2 在 batch×head×Q 块三维并行（v1 主要在 KV 块维），小 batch 长序列、decode 场景 SM 也能打满；
- **$B_c$/$B_r$ 切分经验**：SRAM 容量约束 $B_r\cdot d\cdot b_q + 2B_c\cdot d\cdot b_{kv}\le \text{SRAM}$（v1 论文取 $B_r=16,B_c=16$ fp16 或 128/32）；$B_c$ 大 → GEMM 效率高、重缩放次数少，但占 SRAM 多、occupancy 降；实践中 fp16 常取 64/128 且 $B_r\ge B_c$（v2 让 Q 块大一点，重缩放次数 $\propto N/B_c$ 变少）。causal 时下半三角的整块跳过 + 斜跨对角块局部 mask（块数 $\approx N^2/(2B_rB_c)$，省一半计算）。

手写代码：`solutions/python/src/answers/attention/flash_attention.py`（v1/v2 双版本 + causal 分块裁剪 + SDPA 对拍，测试 `test_attention.py::test_flash_matches_reference`）。

## Q11. FusedAttention 的优化策略有哪些？（实一1 Q2）

分层答：

1. **kernel 内融合**：QK^T → scale → causal mask → softmax → PV 一体（FA 本体）；进阶把 RoPE、GQA 的 head broadcast、top-k/滑窗 mask、alibi bias 也融进同一个 kernel（省中间物化与 launch）；
2. **前后算子融合**：fused (residual add + RMSNorm) → QKV 投影 → RoPE → FA → O 投影 + residual 的链式融合（CUTLASS/Triton 生态里如 FlashInfer 的 `fused_add_rmsnorm`、`prefill_with_kvcache` 一条龙）；decode 路径 fused QKV+RoPE+attention+MLP 的 megakernel（如 Tesla/llm.c 风格）；
3. **KV Cache 布局协作**：PagedAttention 的 block table 索引融进 attention kernel（免 gather）；GQA 的 KV 头维排布成 `[(kv_head, block, token, dim)]` 让一个 warp 连续读；
4. **调度与 backend**：CUDAGraph 消 launch、Tensor Core（WGMMA/MMA fp16/bf16/fp8）、warp specialization（Hopper：producer warp 走 TMA 装载、consumer warp 算）、Persistent kernel + KV cache 逐层流水；
5. **变体支持**：sliding window、logit softcap（Gemma-2）、attention sink、_SPEC decode 的 tree mask 融合。

一句话总结：**"访存不出 SRAM、中间不落 HBM、launch 不进 CPU"**。

## Q12. Llama 模型中有多少个全连接层？（实一1 Q4）

考察对参数结构的账感，以 **Llama-2-7B**（$L=32$ 层，$d=4096$，GQA 前 7B 仍是 MHA $h=32$，SwiGLU 中间维 $d_{ff}=11008$）数"全连接（Linear）层"：

- 每层 attention：**Q/K/V/O 四个**投影（$d\times d$ 各一）；
- 每层 FFN：**gate/up/down 三个**（gate/up 是 $d\times d_{ff}$，down 是 $d_{ff}\times d$）；
- 全局：embedding（查表非 FC）+ lm_head（1 个 $d\times V$，与 embedding 不共享）；RMSNorm 无全连接。

所以"层内"每层 7 个 Linear，32 层共 **224 个**；加上 lm_head 是 **225 个**（70B 用 GQA：Q/O 是 $d\times d$，K/V 是 $d\times d_{kv}$，每层仍是 7 个）。面试先给"每层 4+3=7 个"的结构化数法，再按面试官口径（是否含 lm_head/是否区分投影）给总数，展示的是拆解能力而非背数字。

## Q13. Llama2 的推理流程，每一层包含哪些算子？（实一1 Q5）

单层算子序列（decode 一步，自底向上）：

| 步骤 | 算子 | 形状/说明 |
|---|---|---|
| 1 | RMSNorm | $1\times d$，逐元素统计（fused add+norm 时与上一步残差合并） |
| 2 | QKV GEMV×3 | $d\to d$（+GQA 时 K/V 投到 $d_{kv}=d/h\cdot g$）；prefill 是 GEMM |
| 3 | RoPE | 逐元素旋转（Q/K），Q 拼当前位、K/V append 进 KV Cache |
| 4 | Attention | Q 与全部历史 KV：score→mask→softmax→加权 V（GQA broadcast；FA/FA2 kernel） |
| 5 | O 投影 + 残差 | GEMV $d\to d$，加回输入 |
| 6 | RMSNorm | 第二个 norm |
| 7 | SwiGLU FFN | gate/up 两个 GEMV → SiLU(gate)⊙up → down GEMV |
| 8 | 残差 | 加回，进入下一层 |

循环 32 层（7B）后最终 RMSNorm → lm_head GEMV → logits → 采样。decode 阶段所有 GEMV 都 memory bound（权重读一遍），因此工程上重点优化：fused kernel（norm/RoPE/SwiGLU）、量化权重（W4A16）、CUDA Graph、PagedAttention。配套代码：`solutions/python/src/answers/baidu/fused_add_rmsnorm.py`（表中步骤 1/6 的融合算子 Triton 实现）。

## Q14. 设计比 cudaMalloc 更灵活高效的显存分配方案（cudaAllocator）（实一1 Q6）

参照 PyTorch CUDACachingAllocator 的设计答：

1. **为什么 cudaMalloc 慢**：同步开销（隐式 device sync）、驱动级加锁、反复 alloc/free 走驱动路径（µs~ms 级），且碎片化后可能失败；
2. **核心思路——缓存池 + size class**：请求按 2 的幂（或 512B 对齐 + round-up 阶梯）归到 size class，每类维护空闲块链表；free 只把块挂回链表（不还驱动），下次同尺寸请求 O(1) 命中；
3. **分裂与合并**：大请求从大块分裂（buddy/split-list），释放时与物理相邻空闲块合并对抗碎片；
4. **stream 语义**：块记录"在哪些 stream 上被使用"，free 时插入 event，块在所有相关 event 完成后才真正可复用（跨 stream 安全，免全局同步）；
5. **API 设计**：`allocate(nbytes) -> ptr`、`free(ptr)`、`empty_cache()`（真正还驱动）、统计接口（显存水位/碎片率）；OOM 时先尝试 release_cached_blocks 再 fail；
6. **进阶**：segment 按 mmap 大块申请、显存压力下 `retry_after_free`、与 CUDA Graph 配合的 graph pool（capture 期间私有 arena）。

**手写可运行简化版**：`solutions/python/src/answers/baidu/cuda_allocator.py` —— `SimpleCachingAllocator`（size-class 空闲链表 + round-up + 相邻合并 + 分配/释放统计 + 碎片率报告），CPU 上验证分配器逻辑（复用同一套结构管理 torch 显存块亦可），测试 `test_baidu.py::test_cuda_allocator_*`。

## Q15. RMSNorm 的具体实现；手写 CUDA LayerNorm Kernel（实一3 Q15/Q20）

## Q17. CUDA 向量加 Kernel（一2 Q3）

__global__ void vec_add(const float* a, const float* b, float* c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    int stride = gridDim.x * blockDim.x;          // grid-stride loop

}

## Q19. Float32 与 INT8 相互转换（模型量化）（一2 Q5）

对称量化：$x_{int8}=\text{clip}\!\left(\operatorname{round}(x/s), -127, 127\right),\ s=\max|x|/127$；反量化 $\hat x = x_{int8}\cdot s$。非对称：加零点 $z$（$x/s+z$，适合偏移分布如 ReLU 后）。流程：校准集前向收集激活分布 → 选 scale（absmax/percentile/MSE/entropy=KL）→ 逐层量化权重与激活 → 微调（QAT）或直接部署（PTQ）。细节、GPTQ/AWQ/SmoothQuant 见 [06 量化](./06-量化.md) Q1-Q3。

## Q20. 量化粒度：per-tensor / per-channel / group-wise（实一3 Q3/Q4）

- **per-tensor**：整个张量一个 scale——存储/反量化开销最小，但离群值会把全张量动态范围撑爆，精度最差；
- **per-channel**（权重按输出通道，激活按 token/通道）：每通道独立 scale，权重分布通道间差异大时误差显著下降，权重 only 量化的事实标准（scale 存 $C_{out}$ 个）；
- **group-wise**：通道内再分组（g=64/128），组内 absmax——离群集中在少数维度时（LLM 权重的 emergent outliers），每 64 个元素有独立 scale，量化误差 further 降（AWQ 用 g=128）；代价是 scale 元数据变多（$C_{out}\cdot C_{in}/g$ 个）与反量化时插入更多 dequant 计算（W4A16 kernel 里在寄存器内做，Marlin 把它藏进 GEMM 流水）。

**为何 group-wise 误差更低**（Q4）：量化噪声 $\propto$ 组内动态范围；分组越细，单组内 max 与典型值越接近，round 误差越小。精度排序经验：per-tensor < per-channel < group-wise（W4 下差距更明显，per-tensor W4 常崩）。

**计算开销与优化**（Q5）：细粒度增的是 **scale 装载与乘法**（反量化）与**元数据存储**，而非 GEMM 本身——优化：dequant 融进 GEMM kernel（warp 内寄存器解包 int4 → fp16 用位操作，scale 广播乘）、scale 布局按 tile 重排让一次装载服务整 tile、int4 打包（两个 int4 一个 int8）减带宽。**outlier 处理**（Q6）见 [06](./06-量化.md) Q6：SmoothQuant（等价变换把激活离群搬回权重）、AWQ（保护显著通道）、clip/percentile、混合精度（离群通道保留 fp16，如 LLM.int8()）。

## Q21. KV Cache 量化的原理与实现（实一3 Q8）

原理：KV Cache 是 decode 显存大头（公式见 Q7），量化到 int8/int4 显存线性下降、每步读 KV 带宽同降。做法：

1. **per-token（或 per-block）per-head absmax**：每个 token 的每头 K 向量算一个 scale（粒度细、误差小），量化存 int8；V 同理；
2. **Q8/K8 按 FP8 更稳**：K 的 outlier 对 attention 打分敏感，KV FP8（E4M3）几乎无损、int8 需细粒度 scale，int4 常配 per-block + 重打分校准；
3. **实现位置**：KV 写入 cache 前插 quant kernel，attention kernel 里 dequant（FA 的 KV quant 支持 / FlashInfer 的 `kv_cache_dtype="fp8"`）；旧引擎做法是 attention 前整块反量化（省显存不省带宽，收益打折）；
4. **配套**：KV 淘汰（H2O/StreamingLLM sink）压长度、KV 压缩（MLA 本质）。

**手写对拍**：`solutions/python/src/answers/baidu/kv_cache_quant.py` —— per-token-per-head int8 量化 KV → 反量化做 attention，与全精度 attention 比较输出误差和"下游 top-1 logit 一致率"（实测误差 ~1e-2 量级、top-1 基本不变），测试 `test_baidu.py::test_kv_cache_quant*`。

## Q22. PagedAttention 的设计思路（实一3 Q12）

## Q23. Prefill 与 Decoding 阶段的区别及成因（实一3 Q13）

见 [05](./05-推理引擎与优化.md) Q1 全解。核心：prefill 并行处理整段 prompt，GEMM 形状大 → **compute bound**（追求 TFLOPS、可用 FA/TP 切分）；decode 每 step batch 个 token 各自 GEMV + attention → **memory bound**（读全部权重 + KV Cache，算术强度 ~1，追求带宽利用、batch 越大越好）。成因一句话：并行 token 数决定了算术强度。

## Q24. FlashAttention 在 decoding 阶段的问题与 FlashDecoding 改进（实一3 Q14）

decode 时 Q 只有 1×d（batch 头），FA2 的并行维度 batch×head×Q块 中"Q 块"=1——**并行度塌缩到 B×h**（小 batch 时几个 SM 干活），长 KV 序列串行扫。**Flash-Decoding**：把 KV 序列也切块并行（extra dimension split），每块独立输出部分 $(m,\ell,\text{acc})$，最后一个小 kernel 做 **combine**（跨块 logsumexp 归并：$\ell=\sum \ell_j e^{m_j-m}$，$\text{acc}=\sum \text{acc}_j e^{m_j-m}$，再除 $\ell$）。combine 计算量极小（$\propto$ 块数×d），占不到 1%。vLLM/SGLang 的 decode kernel 即此思路（配合 PagedAttention block table 直接按物理块切）。

## Q25. CUDA Kernel 优化的一般方法论（实一3 Q16）

按"测量→瓶颈→手段→验证"循环答：

1. **先测量**：正确性对拍 → `nsys`/`ncu` 看时长、SOL（sm/memory 利用率）、stall 原因（详见 [08 编译器与性能分析](./08-编译器与性能分析.md) Q5）；
2. **memory bound 路线**：coalesced 访问（相邻线程相邻地址）、向量装载（float4/int4 打包）、shared memory 缓存复用 + padding 消 bank conflict、L2 局部性（block 调度顺序/warp 排布）、减少重复读写（fusion）、异步预取（cp.async 双缓冲）；
3. **compute bound 路线**：Tensor Core（mma/WGMMA、fp16/bf16/fp8）、ILP（每线程多累加器）、指令调度（解开依赖链）、查找表/近似（exp2 代替 exp、`__expf`）、避免 divergence（warp 内分支收敛）；
4. **latency bound / launch bound**：occupancy 调整（block 尺寸、寄存器上限 `__launch_bounds__`）、CUDA Graph、persistent kernel、kernel 融合减少 launch；
5. **迭代验证**：每改一步对拍 + 记录带宽/TFLOPS 相对 SOL 的百分比，防止"感觉优化"。

结合本仓库实例答最有说服力：归约 124×（原子→树+warp shuffle）、直方图 19.9×（全局原子→smem 私有化）、转置 L2 命中掩盖差距的测量教训（[02](./02-cuda-编程题.md) Q1/Q4/Q5）。

## Q26. CPU 上算子优化的方法（实一3 Q18）

- **SIMD 向量化**：AVX2/AVX-512（16/32 个 fp32 lane）、FMA；手写 intrinsics 或依赖 `#pragma omp simd`/`-O3 -march=native`；数据对齐（`alignas(64)`）、SoA 布局让连续 lane 连续内存；
- **多核并行**：OpenMP `parallel for`（注意归约子句 `reduction(+:sum)`，见 [52](./52-百度-系统与cpp.md) Q1 的竞态题）、线程池避免反复创建、NUMA 亲和（`numactl`/first-touch）；
- **访存**：cache blocking/tile（GEMM 分块住进 L1/L2）、预取（`_mm_prefetch`）、避免伪共享（每线程计数器 pad 到不同 cache line）、数据布局 NCHW→NHWC 类比；
- **其他**：查表（exp/激活函数近似）、循环展开、分支消除（`cmov`/掩码）、GCC/Clang 自动向量化报告（`-fopt-info-vec`）、profile（perf）定位热点。

## Q28. RT-DETR 相比 DETR 的优化改进（校二1 Q3）

- **backbone 效率**：用轻量 CNN（如 ResNet/HGNetv2）+ **高效 PAN/CCFM 融合**（卷积做跨尺度融合，替代 DETR 系（DINO）的大 kernel/多尺度 attention 融合），多尺度特征 $S_3\sim S_5$ 送入 encoder；
- **不确定性最小的 query 选择**：从 encoder 输出按分类不确定性（不是分类分数）选 top-K 特征初始化 decoder query——query 起点质量高，收敛快、AP 高；
- **结构化 decoder**：decoder query 只与被选中的少量 encoder 特征做 cross-attention（而不是全图），计算量随 query 数线性；
- **去 NMS/去 anchor 的同时保速度**：一对一匹配保留端到端特性，实时性（R50 一套 ~108 FPS / 46+ AP 量级）远超 DINO 系；
- **与 DETR 原版对比**：原版 DETR 收敛慢（500 epoch）、小目标差、decoder query 全图 cross-attention；DETR→Deformable DETR（稀疏采样）→DAB-DETR（query anchor 化）→DINO（denoising）→RT-DETR（实时化 + query 选择）这条演进线可顺带讲。

## Q29. CNN 与 DNN 的核心区别（校二2 Q2）

DNN（全连接 MLP）：每神经元与上一级**全部**输入相连，权重 $O(\prod d_i)$，忽略空间结构、平移不变性无从谈起。CNN 三大归纳 bias：**局部连接**（感受野 k×k）、**权值共享**（同一卷积核滑全图，参数 $\propto k^2C_{in}C_{out}$ 与位置数无关）、**平移等变**（卷积+pooling 天然对平移鲁棒）——参数量骤降、小数据可训、特征图保留空间结构。现代视角：CNN 是带空间先验的网络，Transformer（ViT）则是"放弃先验换数据"的另一极；CNN 常出现在百度这题的追问里：**感受野计算**（$r_l = r_{l-1} + (k_l-1)\prod_{i<l}s_i$）、**1×1 卷积的作用**（通道混合/升降维）。

## Q30. Tensor Core 与 CUDA Core 的差异（实一1 Q14）

CUDA Core：标量 ALU，每时钟每核一条 FMA（fp32/fp32 累加），可编程任意精度/逻辑；Tensor Core：**矩阵乘累加专用单元**（HMMA/WGMMA/QGMMA），一条指令完成如 16×8×16 的 $D=AB+C$（Ampere fp16/bf16→fp32 累加、Hopper fp8、Blackwell fp4），等价上百条 CUDA Core 指令。使用方式：`mma.sync` PTX / WMMA API / CUTLASS / cuBLAS 自动调度，Triton 的 `tl.dot` 也走 TC。取舍：TC 要求 tile 对齐与特定布局（fragment swizzle）、低精度（fp16/tf32/fp8）——所以 GEMM 类算子吃 TC，elementwise/归约/稀疏逻辑仍在 CUDA Core；一个 SM 内两类单元并存，理想情况下相互流水掩盖。

## Q31. CUDA 提供的编程模型/方式（实一1 Q13）

- **kernel 并行**：grid/block/thread 层级 + shared memory 同步模型（本篇主线）；
- **Stream/Event 异步**：多流并发 + event 依赖，host 异步排队；
- **CUDA Graph**：整图 capture/replay 消 launch 开销；
- **Unified Memory**：`cudaMallocManaged` 单地址空间自动迁移（简化编程，性能需 prefetch 指导）；
- **Dynamic Parallelism**：kernel 内 launch kernel；
- **Cooperative Groups**：grid 级同步、跨 block 归约协作；
- **高级封装**：cuBLAS/cuDNN/TensorRT 库、CUTLASS/CuTe DSL、Triton/Python 生态、MPI+NCCL 多卡。
