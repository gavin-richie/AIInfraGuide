## 一、大模型结构与训练基础（米哈游/联想/数坤/海康）

### Q1. 大模型的主要结构特征；Transformer 整体结构；主流架构的变化（米哈游 Q2/Q3、联想 Q2/Q3）

**Transformer 结构**（白板级）：输入 embedding（+位置编码 RoPE）→ N 层 × {Multi-Head Self-Attention（QKV 投影→缩放点积→softmax→加权 V→输出投影）+ FFN（两层 MLP + 激活）}，每子层残差连接 + RMSNorm（Pre-Norm）；解码器侧 causal mask + KV Cache 增量解码。手写实现与 Mask 位置见 [103](./103-t5-算法题.md) Q2。

**LLM 时代的变化**（答"与早期相比"）：① Post-Norm → **Pre-Norm**（训练稳定，深层可训）；② LN → **RMSNorm**（省均值中心化，快）；③ 绝对位置编码 → **RoPE**（相对位置、外推友好）；④ 激活 ReLU/GELU → **SwiGLU**（三矩阵 FFN，效果好）；⑤ MHA → **GQA/MLA**（KV Cache 省存省带宽，见 [04](./04-attention与kvcache.md)）；⑥ 稠密 FFN → **MoE**（激活参数小、总参数大）；⑦ 训练目标从纯 next-token 到多阶段（预训练→SFT→RL，见 Q8）；⑧ 上下文长度 512 → 128K+（长外推：RoPE 缩放/NTK/YaRN、 attention 稀疏化）；⑨ 多 token 预测（MTP）等辅助头；⑩ 适配推理的结构化改进（MTP 服务投机采样、 MLA 吸收友好）。

**注意力机制的作用一句话**：动态按内容相关性加权聚合序列信息——每个 token 的表示由所有相关 token 的加权和更新，解决了 RNN 长程依赖衰减与不可并行两个痛点；多头让不同子空间学不同关系模式。

**为什么要除以 $\sqrt{d}$（讯飞校招 Q2）**：q·k 是 d 个分量内积，若各分量独立同方差（$\sigma^2$），内积方差 = $d\sigma^2$——维度越大点积的绝对值越大（标准差 $\sqrt{d}\sigma$）；softmax 对大 logits 极其敏感（饱和区梯度趋 0），不缩放时点积动辄 ±30，softmax 变近似 one-hot，梯度消失 + 注意力退化成"只看一个位置"。除以 $\sqrt{d}$ 恰好把内积方差拉回 $\sigma^2$（与维度无关），使 softmax 工作在温度适中区。不缩放的后果可实测：初始训练 loss 尖峰、收敛慢或发散。延伸：这也是 attention 温度参数的出处（$\sqrt{d_k}$ 是默认温度）。

### Q2. 大模型训练常见优化算法及优缺点；梯度消失/爆炸处理（米哈游 Q4/Q5）

详见 [11 深度学习与训练](./11-深度学习与训练.md) 优化器题。速答表：

| 优化器 | 核心机制 | 优缺点 |
|---|---|---|
| SGD+Momentum | 一阶动量惯性 | 泛化好、简单；调参难、收敛慢 |
| Adam | 一阶+二阶动量自适应 | 收敛快、稳；内存 2×参数、泛化略差 |
| **AdamW** | Adam + 解耦权重衰减 | LLM 事实标准——decay 只作用于权重不作用于动量 |
| Adafactor | 因式分解二阶矩 | 省 optimizer state 显存（T5 时代） |
| Lion/Muon 等 | 符号更新/正交化 | 近年提效方向，验证中 |

LLM 练法补充：warmup（初期 lr 线性升防二阶矩失真）+ cosine 衰减；大 batch 混合；权重衰减只加在 2D 矩阵（embedding/LN/bias 不加）。

**梯度消失/爆炸**：成因——深链式求导连乘（<1 消失 / >1 爆炸），RNN 尤甚；不合适初始化、损失饱和区。处理：① 结构上——残差连接（梯度高速路）、LN/RMSNorm（每层重标定）、LSTM/GRU 门控、深网络 Pre-Norm；② 初始化——Xavier/He（维持方差）；③ 激活——ReLU 系防饱和；④ 裁剪——**梯度裁剪**（clip by norm，训练 LLM 标配，阈值 1.0）；⑤ 数值上——bf16 换 fp32 关键层、loss scaling（fp16）、权重/梯度监控（norm 突增= spike，定位坏数据/学习率）；⑥ 爆炸定位：打印各层梯度范数，二分找层。

### Q3. 模型复杂度与性能的平衡；大规模计算资源的可行方案（米哈游 Q6/Q7）

**平衡**：① 定律级参照——Scaling Laws（Chinchilla：数据/参数 20:1 最优）先定预算再定规模；② 结构上省参数不减容量——MoE（激活/总参数解耦）、GQA/MLA（省 KV）、知识蒸馏（大教小）、参数共享（ALBERT）；③ 训练上正则调容量（dropout/权重衰减/数据增强）防过参；④ 部署上量化/剪枝降 serving 成本而保精度（见 [101](./101-t5-量化与算子.md)）；⑤ 评估驱动：每档规模画 loss-成本帕累托，选边际收益拐点。回答框架："**先定任务与预算 → 缩放定律定形 → 结构省参数 → 蒸馏/量化落地**"。

**大规模算力方案**（工程侧，呼应 [07](./07-分布式训练.md)）：① 数据/模型/流水线/专家并行的组合（3D 并行、ZeRO 系显存切分）；② 混合精度 + 重计算 + 8-bit optimizer 省显存；③ 弹性/容错（checkpoint 常备、故障自动重启、弹性调度）；④ 云边协同（按需租用/潮汐调度）、多集群吞吐优先训练；⑤ 推理侧 PD 分离/量化/投机降服务成本；⑥ 数据与 IO 并行（流式数据加载不让 GPU 等）。

### Q4. 分布式训练的主要性能瓶颈（海康一面 Q3）

① **通信**：梯度 all-reduce 与计算串行（未重叠）、跨机带宽受限（IB/以太网）、慢节点 straggler；② **负载不均**：数据长尾（变长序列 padding）、MoE 专家不均、流水线气泡（PP 气泡比例 (p-1)/m）；③ **显存**：激活/优化器状态挤占 batch 空间（触发重算换时间）；④ **kernel/框架开销**：小算子 launch、graph break、CPU 侧数据管道饥饿；⑤ **同步语义**：频繁 `.item()`/日志同步打断流水；⑥ 集群级：故障恢复、checkpoint 写入停顿。优化对应：通信计算重叠（bucket/DDP）、分层通信（机内 NVLink 先归约）、1F1B/interleaved/DualPipe 减气泡、ZeRO/FSDP 平衡显存通信、序列长度分桶、NCCL 调优与拓扑感知（详见 [07 分布式训练](./07-分布式训练.md) 各题）。

### Q5. 评估大模型性能的常用指标；性能与效率优化方法；并行策略总览（米哈游 Q8/Q9、数坤 Q3）

**评估指标**分三层：① **能力基准**——通用（MMLU/CMMLU、BBH、GPQA）、代码（HumanEval/SWE-bench）、数学（GSM8K/MATH）、长上下文（Needle-in-Haystack、RULER）、推理（GPQA/AIME）；② **对齐/偏好**——MT-Bench、Arena Elo（人类偏好）、RewardBench；③ **效率指标**——训练 MFU、推理 TTFT/TPOT/吞吐/显存、$/M tokens。方法上强调：固定版本自动回归评测 + 人工抽检 + LLM-as-judge（见 Q12）。

**效率优化**：训练侧（并行策略、混合精度、算子优化、数据管道——[07](./07-分布式训练.md)/[11](./11-深度学习与训练.md)）；推理侧分层答（模型：量化/蒸馏/结构；kernel：FA/融合；引擎：batching/KV 管理/投机；系统：PD 分离/多级缓存——[100](./100-t5-推理引擎.md) Q16 体系化答案）。

**并行策略总览**（数坤 Q3）：**DP**（数据复制模型，梯度同步——吞吐首选小模型）/**TP**（层内切矩阵，通信重适合机内 NVLink）/**PP**（层间切，气泡需调度）/**SP**（序列维切 attention/FFN，长序列）/**ZeRO/FSDP**（显存三切片：参数/梯度/优化器态）/**EP**（MoE 专家维+all-to-all）；实战组合 3D（DP×TP×PP）/Megatron+DeepSpeed、DeepSeek-V3 的 EP+PP（DualPipe）。

### Q6. Transformer 架构中 KV-Cache 在推理加速中的体现；KV Cache 的作用与实现（数坤 Q2、传音 Q18）

作用：自回归解码每步只需新 token 的 Q，历史 K/V 不变——缓存后每步从 $O(L^2)$ 计算降为 $O(L)$，且省掉重复投影。加速体现（三层）：① **计算**：每步只算 1 个 token 的 QKV 投影与它对 L 个键的 attention（而非重算全序列）；② **访存**：增量写入 + 顺序读，配合分页（PagedAttention）与 prefix cache（多轮对话免重算 prefill，TTFT 从秒级到毫秒级）；③ **工程**：per-layer pre-allocate 块池 + block table 索引、GQA/MLA 压缩缓存体积（[04](./04-attention与kvcache.md) 全系题解，可跑实现 `solutions/python/src/answers/attention/paged_attention.py`）。

## 二、微调与对齐（米哈游/贝壳/小厂）

### Q7. LoRA 的基本原理；为什么 A 矩阵不能初始化为零（贝壳 Q1/Q2）

**原理**：微调增量低秩假设——$W' = W_0 + \Delta W = W_0 + BA$（$B\in\mathbb{R}^{d\times r}, A\in\mathbb{R}^{r\times k}$，秩 $r\ll d$）。冻结 $W_0$，只训 $A,B$（可训参数 ~0.1-1%），推理前可合并 $BA$ 进权重**零额外延迟**；作用在 attention/FFN 的投影矩阵上（常见 q,v 或全部）。可运行实现：`solutions/python/src/answers/torch_impl/lora.py`（[11 深度学习与训练](./11-深度学习与训练.md) LoRA 题）。

**初始化**：**高斯初始化 A、B 初始化为零**——保证训练起点 $\Delta W = BA = 0$（模型行为与预训练完全一致，从"不破坏"起步）。若 A 也置零，则 $BA$ 恒为 0、梯度 $\partial L/\partial B = \partial L/\partial (\Delta W)\cdot A = 0$、$\partial L/\partial A = B^\top(\cdots) = 0$——**两个矩阵的梯度互相依赖对方非零**，全零初始化导致永远学不动（死锁）。答到"梯度为零/对称性破坏"即满分；延伸：LoRA+（初始化前先跑一步 SVD）、rsLoRA/DoRA 变体。

### Q8. P-Tuning v2 的实现方式及与前代的区别（贝壳 Q3）

prompt tuning 家族演进：**P-Tuning v1**——只在**输入层**插入少量可训练的连续 prompt 向量（<20 个），与冻结的 embedding 一起过模型；深层模型传到后面 prompt 影响被稀释，NLU 效果一般。**P-Tuning v2（Prompt Tuning 的深度版）**：**每一层**都注入可训练的 prefix 向量（prefix-token 形式：每层 attention 的 K/V 前面拼接 $P_{KV}$ 个可学习向量，本质与 **Prefix-Tuning** 相同），参数量每任务几十 MB、小模型也能追平全量微调；实现上是"假 token"拼进 KV 序列（含门控重参数化 MLP 稳定训练）。对比 v1：注入位置（仅输入层 vs 每层）、任务通用性（NLU 弱 vs 通用）、参数规模。与前代大家族的关系：v2/Prefix ≈ 深度可训 KV 前缀；与 LoRA 的对比——LoRA 改权重增量（与输入无关）、Prefix/P-Tuning2 占用序列位置与 KV（与输入相关、影响有效上下文长度）。

### Q9. 预训练与后训练的目标与内容；预训练与 SFT 的 loss/数据差异（贝壳 Q4、小厂实2 Q1）

**预训练**：目标——next-token 预测（交叉熵）+（可选）MTP 多目标；数据——数万亿 token 网络级语料（清洗/去重/配比：代码、多语言、书籍、数学加权），无标注对话结构；loss 对**所有 token** 计算。**SFT**：数据——万到百万级高质量指令/对话样本（多样化任务、格式统一 chat 模板）；loss **只对 assistant 回复 token** 计算（user/prompt 部分掩掉——不学"生成问题"）；长度通常打包（packing）填满序列提高 token 效率（见 [100](./100-t5-推理引擎.md) Q12 packing vs 多轮）。**后训练全景**（贝壳 Q4 的完整答）：SFT（行为模仿）→ 偏好对齐（RM+PPO / DPO / GRPO，见 Q10-Q12）→（reasoning 时代）可验证奖励的 RL（数学/代码用判分器，DeepSeek-R1 路线）与自我进化（拒绝采样再 SFT 迭代）。演进要点：从 RLHF 到 DPO 的简化、从人类偏好到可验证奖励（RLVR）。

### Q10. GRPO 的基本流程；RL 完整流程与模型角色；PPO vs GRPO；GSPO 等 GRPO 改进（贝壳 Q5、小厂实2 Q5、联想 Q4）

**RL（RLHF）完整流程与模型角色**：① **SFT 起步模型**；② **RM 训练**（同 prompt 多响应人类排序 → Bradley-Terry 损失学偏好，见 Q11）；③ **RL 优化**：**policy 模型**（被训的 LLM，生成响应）+ **reference 模型**（冻结的 SFT 模型，KL 惩罚防漂移）+ **reward 模型**（打分）+ **critic/value 模型**（PPO 需要的基线，估计状态价值降方差）+（推理引擎承载的 rollout 生成）；④ 每步：采样 prompt → policy rollout 生成 → RM 打分 + KL 罚 → PPO/GRPO 更新。

**PPO**：actor-critic，价值网络估计 GAE 优势 $A_t$，clip 目标限制单步更新幅度——稳但工程重（value 模型与 policy 同尺寸、显存/训练翻倍，且 LLM 上 value 估计难）。

**GRPO**（DeepSeekMath/R1 采用）：**去掉 value 模型——同一 prompt 采一组（G 个）响应，用组内回报的标准化做优势**：$A_i = (r_i - \mathrm{mean}(r))/\mathrm{std}(r)$。流程：prompt → 组采样 → 打分（RM 或可验证规则）→ 组内基线 → 策略梯度（+KL 罚）。优点：省 value 模型（显存减半）、天然适合"结果奖励"（数学对错/代码测试），长 CoT 推理训练的事实标准。缺点：组内基线有偏（同组全对/全错时梯度为零）、样本效率依赖 G、对长度敏感（后来加长度归一化）。

**改进方法（联想 Q4 追问）**：**GSPO**（Qwen 团队，Sequence-level Policy Optimization——把 KL/重要性比从 token 级提升到**序列级**（几何平均），解决长序列 token 级 ratio 乘积不稳/剪枝过度）；Dr.GRPO（去长度归一化偏差）、DAPO（clip-higher/动态采样解全对全错与熵塌缩）、RLOO（留一基线）、在线过滤（过滤全对组）。答题：先 GRPO 流程，再说两个你知道的改进与"它解决什么问题"。

### Q11. Reward Model 的训练流程与目标；Reward Bench 的分类；奖励函数设计与评估（米哈游 Q11/Q12、贝壳 Q6）

**RM 训练**：数据（prompt + 同 prompt 多个回复的人类偏好对 chosen/rejected）→ 模型（LLM 去掉 lm_head 接 scalar head，或直接用 logits 偏置）→ **Bradley-Terry 损失**：$L = -\log \sigma(r(x, y_{chosen}) - r(x, y_{rejected}))$（拉开好坏分差）——目标是学出**相对偏好序**而非绝对分数；配 KL 正则防 reward hacking、多 RM 集成降方差。推理/部署中 RM 还充当 best-of-n 重排器。

**RewardBench 分类**（对齐评测集四类）：**Chat**（多轮对话有用性）、**Chat Hard**（对抗/棘手指令、安全挑战）、**Safety**（拒绝有害请求）、**Reasoning**（数学/代码/logic 正确性偏好）——评测 RM 在四类的排序准确率 + 可信度分析。

**奖励函数设计**：① 可验证任务（数学/代码）用**规则奖励**（答案比对、单测通过）——免 RM、不可 hack；② 结果奖励 vs 过程奖励（PRM，逐步打分引导 CoT）；③ 组合项：helpfulness + 安全拒答 + 格式合规（JSON 可解析）——各项量级归一、防某项主导；④ 防 hacking：KL 罚、奖励模型集成、对抗样本回训、长度惩罚（防"更长=更好"捷径）。**评估**：RM 排序准确率（RewardBench/自建 held-out）、与人类偏好相关性、训练后策略的端到端指标（win-rate、benchmark 分）、hack 探针（注入引导越界的 prompt 看分数是否异常高）。

### Q12. DPO 的损失与目标；相较 RLHF 的改进；LLM as a Judge（米哈游 Q13、贝壳 Q7）

**DPO（Direct Preference Optimization）**：绕开 RM 与 RL——从偏好数据直接优化策略。目标由 RLHF 的 KL 约束最优解闭式改写：最优策略 $\pi^* \propto \pi_{ref}\,e^{r/\beta}$，反解 $r = \beta\log(\pi/\pi_{ref}) + const$ 代入 BT 损失得：

$$L_{DPO} = -\mathbb{E}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right)\right]$$

直觉：拉大 chosen 的对数比、压低 rejected 的（均相对参考模型）——"隐式奖励"由策略自己定义，损失即分类式的 sigmoid。

**相较 RLHF 改进**：① 免 RM 训练与在线采样/RL 的不稳定性（无 reward hacking、无 rollout 工程）——一个**监督学习**跑完；② 显存与流程大减（无 value/reward 模型）；③ 数学性质好（有最优解闭式支撑）。**代价**：离线数据分布（策略不探索，数据外泛化弱）、对数据质量敏感、迭代在线偏好（如 R1 类 RLVR）仍需 RL 类方法——实践中 DPO 常作 SFT 后的轻量对齐，与 GRPO 互补（可先 DPO 后 RL）。

**LLM as a Judge**：用强模型（GPT-4 级）代替人工评生成质量——模式：单点打分（rubric + CoT 评分）、**成对比较**（A/B 谁好，更稳）、参考答案对比。关键设计：**位置偏差**（A/B 交换位置重评取一致）、长度偏差（长答案偏好——prompt 里显式约束）、自我偏好（判别模型偏自家输出——换模型交叉评）；rubric 结构化（分维度：帮助性/正确性/安全）+ few-shot 校准 + 置信度过滤。用途：RLHF 数据合成、回归评测（MT-Bench/AlpacaEval 都是此范式）。

### Q13. 大模型安全的理解（米哈游 Q14）

四个层面：① **内容安全**——拒答有害请求（暴力/违法/隐私）、越狱攻击防御（prompt 注入、角色扮演绕过、多轮诱导）、多语言/编码形式绕过；② **价值观对齐**——RM/偏好数据覆盖安全维度、Constitutional AI 类自 crit 修正；③ **系统安全**——prompt 注入（数据变成指令）、工具调用安全（agent 执行越权）、检索内容污染（RAG 投毒）、模型文件供应链（pickle 反序列化）；④ **滥用防护**——水印/检测生成内容、deepshit 防护、速率与身份治理。训练侧手段：SFT 安全语料 + 安全 RM + PPO/DPO、红队对抗数据回训、拒绝采样增强；推理侧：输入/输出双向内容审核（分类器+规则）、系统 prompt 加固、工具沙箱。答法：**"模型自身对齐 + 系统层防御 + 红队评测闭环"** 三层。

## 三、RL 训练工程与并行细节（小厂/数坤）

### Q14. Megatron TP 如何切分参数矩阵？MLP 两个线性层的行列切分与通信原语（小厂实2 Q2、数坤 Q4）

Megatron TP 把每层权重按维度切到多卡（推导见 [07 分布式训练](./07-分布式训练.md) TP 题）。**MLP**（两层：$Y = W_2\,\mathrm{act}(W_1 x)$，$W_1: h→4h$、$W_2: 4h→h$）：

- **第一层 $W_1$ 列切分（column-parallel）**：$W_1 = [W_1^1; \dots; W_1^p]$（按输出维切）——各卡拿不同输出列，输入 x **每卡全量**（identity 输入），输出是各卡的 $4h/p$ 切片（无需通信）；
- **第二层 $W_2$ 行切分（row-parallel）**：$W_2 = [W_2^1, \dots, W_2^p]$（按输入维切）——正好吃上一层的切片输出，各卡算出部分和（$h$ 维），**all-reduce 求和**得完整输出。

**通信原语配对**：列切分输入侧 identity/输出 partial；行切分输出侧 **all-reduce**（前向）——attention 同构（QKV 列切、O 投影行切，O 后 all-reduce）。为何这样配：**列后行**使两层之间零通信、整块 MLP 只在结尾一次 all-reduce（反向再一次），通信次数最少。数坤 Q4"矩阵切分的数学原理"：$(AB)^T$ 与分块乘法保证分片乘积可加和——$Y = \sum_i W_2^i \mathrm{act}(W_1^i x)$（行切的加法结构）；切分要**沿着与激活广播维度正交的方向**，并保持 TP 后每卡 GEMM 仍是规整大矩阵。

### Q15. 1F1B 与 DualPipe 的设计原理（小厂实2 Q4）

流水线并行基础与气泡分析见 [07 分布式训练](./07-分布式训练.md) PP 题。

- **GPipe**：先整体前向再整体反向——所有卡的激活都要缓存到反向，**显存峰值 = 全部 micro-batch 激活**；
- **1F1B（one-forward-one-backward）**：warmup 期各卡做若干前向后进入稳态——每做一次前向立刻回收最早前向对应的反向（发-收一一交替）。效果：**每卡同时驻留的激活从 m 个降到 ~p 个（深度）**，显存大降；气泡不变（$\frac{p-1}{m}$）但能开更大 m；
- **Interleaved 1F1B**：每卡持有多个模型块（virtual pipeline），前向反向按块交错调度——通信与计算重叠更多、气泡减为 $\frac{p-1}{mv}$；
- **DualPipe（DeepSeek-V3）**：针对 **EP+PP 组合**的 all-to-all 通信与计算难重叠设计——把每个 micro-batch 拆成两半**反向成对注入**（从两端同时启动，两半在中间汇合），调度上把"通信 bubble"与"前向/反向"错位排列，让 **all-to-all 通信完全被计算掩盖**，且保持 1F1B 的激活驻留数。V3 用 8 卡 PP × 双向注半 micro-batch，使通信开销近乎归零。

答法：先 1F1B 显存动机（驻留激活 p 个），再 interleaved 减气泡，最后 DualPipe=为 EP 的 all-to-all 重叠而生。

### Q16. DeepSeek 论文的技术要点：FP8 训练方案（小厂实2 Q3）

DeepSeek-V3 技术报告的 FP8 混合精度训练（4D 缩放 + 细粒度分块）——LLM 首次全链路 FP8 验证：

1. **动机**：Hopper FP8 Tensor Core 2× 于 BF16——但 naive per-tensor 缩放精度不够（激活 outlier、动态范围大）；
2. **细粒度量化**：**权重按 128×128 block、激活按 1×128（每 token 每 128 通道）tile** 计算 scale（per-block scaling）——离群值只影响自己块；
3. **在线安全缩放**：发现异常大激活时**增量放大该 tile 的 scale 并按 2 的幂对齐**（右移不损失精度），避免缩放来回除乘误差；
4. **高精度累加与关键路径保 BF16**：FP8 GEMM 输入、BF16 累加；GEMM 结果**chunk 累加**（每 128 元素升 BF16 累加）防 FP32 大数吃小数；attention 的 softmax/LN/embedding 等敏感算子保持 BF16/FP32；
5. **收益**：训练加速 ~1.2-1.3×、显存/通信减半、精度几乎无损（BF16 基线对齐）。
   其他要点（可各一句带过）：MLA（[100](./100-t5-推理引擎.md) Q4）、DeepSeekMoE 细粒度+共享专家、**无辅助损失的负载均衡**（bias 调节路由，替代 aux loss 的表达能力损失）、MTP 多 token 预测目标（推理时投机）、14.8T token 训练、FP8 + DualPipe + 通信压缩（寄存器级打包）的集群效率（MFU 与通信细节）。

### Q17. RL 训练中 Rollout 耗时占比与 Policy 的 MFU；MFU 与 6Nd 公式（小厂实2 Q6）

**Rollout 占比**：RL 训练一步 = 采样（rollout 生成）+ 打分 + 训练更新。policy 模型在 rollout 阶段跑的是**推理引擎**（小 batch、逐 token decode、memory bound）——MFU 通常只有 **10-30%**，而训练阶段可到 40-60%。rollout 占一步时间的比常见 **40-70%**（长 CoT 的 reasoning 任务更高，生成长度决定）——所以异步/offload 优化是重点（见 Q18）。答法：给出量级 + 解释"为什么 rollout 慢"（decode 带宽 bound + 训练引擎复用推理栈时 batch 小）。

**MFU 公式**：$MFU = \frac{实际\ FLOPs}{峰值\ FLOPs × 时间} = \frac{6Nd}{T × N_{gpu} × FLOPs_{peak}}$（N 参数、d token 数）；其中 **6Nd**：每 token 前向 2N + 反向 4N FLOPs（乘加各计 1）。例（[05](./05-推理引擎与优化.md) Q11）：7B×1T token×MFU 40%×H800×8 卡 ≈ 15.3 天。注意重算（+33%）、MoE 按激活参数近似、attention 二次项长序列时额外加。

### Q18. Rollout 阶段的优化手段；预训练权重如何同步到推理引擎（小厂实2 Q7/Q8）

**Rollout 优化**：① **异步 RL（A3C 式**：1-step 优势 / AGIL 类解耦）——rollout 与 training 引擎分离，各自持续吞吐（样本带旧策略的 importance ratio 修正）；② **训练/推理引擎分离（vLLM/SGLang 跑 rollout，Megatron/FSDP 跑训练）**——推理引擎的 continuous batching + KV cache 优化直接复用；③ **Rollout 量化**（W8A8/FP8 采样，接受轻微分布差）与投机采样（draft 加速生成）；④ **大 batch 采样/并发**（数百并发请求摊权重读取）；⑤ **部分 rollout / 提前终止**（坏样本早停省算力）、**动态采样**（DAPO 过滤全对全错组）；⑥ 权重/优化器 offload、CPU 推理分担短 rollout；⑦ 长上下文 KV 复用（同一 prompt 多组采样共享 prefix）。

**权重同步（训练引擎 → 推理引擎）**：① 帧同步——训练 step 完成后广播最新权重再采样（on-policy 严格但串行等）；② **异步各版本**：推理引擎持有 v_t，采样标 importance ratio $\pi_{\theta_{new}}/\pi_{\theta_{old}}$ 修正（1-step / off-policy 校正）；③ 工程路径：TP 全部 rank 广播分片 → 推理引擎 all-gather/合并（或直接按 TP 布局分发）；bf16 转换 + 权重名映射（训练侧 module 前缀差异）；④ **增量同步**：RL 里只有 policy 变、reference/reward 冻结可常驻；LoRA-RL 只同步低秩增量；⑤ vLLM `sleep/wake_up` 与 `CollectiveRPC` 广播权重、SGLang `update_weights` 是现成接口；⑥ 防撕裂：版本号 + 屏障，采样任务标 version。

### Q19. 通信时延的主要影响因素与缓解（数坤 Q5）

**影响因素**：① 物理距离/跳数（同卡〈机内 NVLink〈机间 IB〈跨机房 RTT）；② 带宽与消息大小（时延 = 启动延迟 α + 消息/带宽 β——小消息延迟主导、大消息带宽主导）；③ 集合通信算法（ring/tree，参与进程数 p）；④ 拓扑与竞争（多作业共享链路、NIC 队列）；⑤ 协议栈（TCP 栈开销 vs RDMA kernel bypass）；⑥ 同步语义（barrier 等最慢者——straggler 放大）；⑦ 序列化/拷贝（GPU↔CPU↔网卡）。**缓解**：算法-通信重叠（梯度 bucket 反向重叠）、分层归约（机内 NVLink 先 reduce 再跨机）、拓扑感知分配（rank 与数据局部性）、大消息切分流水（chunked ring all-reduce）、量化/压缩梯度（fp8/bf16、1-bit 类）、异步/解耦（参数服务器、all-reduce 换 all-gather+本地更新）、RDMA/GPUDirect（网卡 DMA 直达显存）、慢节点治理（detect + 重调度）。公式化答（α-β 模型）+ 每条缓解手段对应哪个因素，是满分结构。

### Q20. 无 RL 经验如何设计智能体；实际使用/开发大模型的案例（数坤 Q6、米哈游 Q10）

**智能体设计框架**（展示方法论而非经历）：① 任务定义——目标、动作空间（工具 API 列表）、终止条件；② 架构——ReAct 循环（思考→行动→观察）或 plan-and-execute；记忆（短期上下文/长期向量库）；工具路由（function calling + 结构化输出约束）；③ 学习信号——从轨迹数据 SFT（行为克隆）起步（最容易），再上偏好优化（DPO 失败/成功轨迹对），最后 RL（环境回报 = 任务完成判分，GRPO 组采样）；④ 评测——任务成功率、步数、成本/token、失败归因分类；⑤ 安全——动作白名单、人工确认高危操作。这样答把"没做过 RL"转化为"我知道从模仿学习到 RL 的渐进路径"。

**案例题（米哈游 Q10）答法模板**：背景（业务/指标）→ 我的角色与具体工作（技术选型/实现）→ 难点与解法（最好有量化：吞吐 ×2、显存 -30%）→ 收尾（上线效果/复盘）。准备一个部署/训练/优化各一。

## 四、检索与应用层（贝壳/虾皮）

### Q21. Tokenizer 的原理与优化；TF-IDF 的作用（贝壳 Q8/Q9、传音 Q17）

**Tokenizer 原理**：文本 → 子词序列。主流 **BPE**（从字符起迭代合并最高频对直至词表大小）、WordPiece（BPE 变体，合并打分按似然）、Unigram（概率模型反向拆分）、SentencePiece（语言无关、把空格当符号，直接吃原始文本）；词表 3-150K，中文常配 byte-fallback（未登录字回退字节级不产生 UNK）。**优化方法**：① 词表裁剪/领域扩充（重新训练 BPE 覆盖领域术语，减序列长度）；② tokenizer 训练数据与模型语言配比一致（多语言均衡防某些语言碎片化）；③ 推理服务侧——tokenizer 前置到客户端/网关（CPU 密集从引擎卸载）、Rust 实现（HF tokenizers）+ 并行批编码、缓存重复 prefix 的 token id；④ 结构上：chat 模板开销合并、与多模态 processor 融合；⑤ 长度分布监控（异常膨胀提示 tokenizer 不匹配）。对训练/推理的影响：序列长度直接决定计算与 KV 成本——同文本 token 数少 10% ≈ 成本降 10%。

**TF-IDF**：词权重 = 词频 × 逆文档频率（$\log(N/df)$，越稀有越重）——经典稀疏检索/关键词抽取表示，"验证"作用（贝壳问的语境）：① 做 RAG 的**基线检索器/召回校验**（BM25 与向量检索互为对照，评估 embedding 质量）；② 特征重要性/停用词过滤；③ 语料清洗统计（文档相似度去重）。一句话：**向量检索之前的可解释基线，也是 embedding 效果的下界对照**。

### Q22. RAG 的实现流程与向量检索选型；RAG 效果评估、面向 RAG 的生成模型训练；CoT 数据构造（贝壳 Q10/Q11、虾皮 Q5/Q6/Q7）

**实现流程**：离线——文档解析（PDF/HTML/表格）→ 切块（chunk，512-1024 token，重叠 10-20%，结构感知切分）→ embedding 模型编码 → 向量库入库（+倒排/BM25 混合）；在线——query 改写（指代消解/HyDE）→ 检索（top-k，向量 + 关键词混合 RRF 融合）→ 重排（cross-encoder rerank）→ 上下文拼装（优先级/截断）→ LLM 生成（引用标注）→（可选）后校验。

**向量检索选型**：① 精确 kNN——小规模（<100K）直接矩阵乘；② **ANN 索引**——Faiss（IVF/HNSW/PQ 压缩，单机快）、Milvus/Qdrant/Weaviate（分布式、过滤、多租户）、Elasticsearch（BM25+vector 混合成熟）、pgvector（已有 PG 栈、中等规模）；③ 选型维度：规模（百万 vs 亿级）、QPS/延迟、过滤条件（元数据混合查询）、内存预算（PQ/标量量化）、运维复杂度；④ 模型侧：bge/gte/jina 类 embedding + reranker，注意"query 与 passage 不对称编码"要用非对称模型。

**效果评估（虾皮 Q5）**：分层——① **检索指标**：Recall@k / MRR / nDCG（对照人工标注的相关块）；② **生成指标**：faithfulness（答案是否忠于检索内容——LLM-judge 抽取支撑句）、answer relevance（答非所问率）、context utilization（引用块被用比例）；③ 端到端：领域 QA 准确率、人工/LLM 打分、拒答正确率；④ 系统：延迟、成本/查询。工具：RAGAS（上述指标自动化）、自建金标集回归。

**RAG 生成模型训练（虾皮 Q6）**：① 指令微调注入 RAG 行为——数据形如 (query, 检索块, 引用式回答)，训练"仅基于 context 回答 + 引用 + context 不足时拒答"；② 负样本构造（检索到无关块时拒绝使用——抗干扰训练）；③ 与检索器联合优化（指令微调 embedding 模型适配 query 分布 / LSR 类反馈到检索器）；④ 域适配预训练（领域语料继续预训练 + 术语）。

**CoT 训练数据构造（虾皮 Q7）**：① **蒸馏强模型**——用 GPT-4o/o1 类模型对题目生成逐步推理，题目来自开源数学/代码集（GSM8K/MATH）+ 自建；过滤：答案对 + 推理链一致（去掉"答案对但推理错"）；② **拒绝采样（STaR/R1 路线）**——用被训模型自己采样多条推理，保留答案正确的（可再用 verifier 判分），SFT 回去，迭代；③ **过程奖励标注**——PRM 类逐步人工/模型标注（贵但引导过程正确）；④ **规则可验证任务**优先（数学/代码——判分自动化）；⑤ 数据清洗要点：长度控制（防冗余步骤）、语言一致、去重、难度分层课程化（由易到难）；格式统一（`<think>...</think>` 模板）。

## 五、CV 与多模态基础（传音/识渊/Teleai）

### Q23. 目标检测的基本原理；类别数与数据集规模的影响；YOLOv5 的改进点（传音 Q4/Q5/Q6）

**原理**：分类+定位——图像上滑窗/锚框提出候选区域（two-stage：RPN 提 proposal 再分类回归，如 Faster R-CNN；one-stage：密集预测每个 anchor/grid 直接出类别+框偏移，如 YOLO/SSD/RetinaNet），输出经 NMS 去重。核心组件：backbone（特征提取）+ neck（FPN/PAN 多尺度融合）+ head（分类分支 + 回归分支）；训练损失 = 分类损失（CE/Focal）+ 回归损失（IoU/GIoU/CIoU + 框置信度 obj 损失）；标签分配决定正负样本（IoU 阈值/ATSS/SimOTA 动态分配）。

**类别数与数据规模的影响**：类别多——头部分类矩阵变大、类间混淆上升（长尾类别样本少需重采样/重加权/损失调整）、每类样本下限经验 ~几百-上千框（否则过拟合）；数据规模——小数据易过拟合（用预训练 backbone/增强/早停）、多样性比绝对量更重要（光照/尺度/遮挡覆盖）；类别数与数据量共同决定模型容量选择（大类别数要更大 backbone 或解耦头）。

**YOLOv5 改进点**（相对 v3/v4 语料）：① **Focus/下采样改进**（v6.0 后换 6×6 conv）+ **PANet neck**；② **自适应锚框**（训练时 k-means 自动聚类 anchor 并进化调整）；③ **自适应图片缩放**（letterbox 到 32 倍数，短边补灰——减信息浪费）；④ 数据增强（Mosaic 4 图拼接 + Copy-Paste、HSV 扰动、仿射）；⑤ 损失（GIoU 回归 + conf 用 BCE 类平衡）；⑥ 工程化——CSP backbone、自动混合精度、模型缩放族（n/s/m/l/x 一键不同规模）、易用的训练/导出（ONNX/TRT/NCNN）生态。答"为什么工业界爱用"：速度-精度-易部署三位一体。

### Q24. ByteTrack 的匹配流程（小厂实4 Q9）

核心洞察：**低分检测框（0.1-0.3）也是好跟踪候选**——传统只用高分框（>0.5）丢掉了被遮挡目标。流程：① 当前帧检测按置信度分两组（高分 D_high / 低分 D_low）；② **第一轮匹配**：所有活跃轨迹（含 lost 暂留）与 D_high 做**级联匹配**——IoU 矩阵 + **用运动模型（Kalman 预测框）与 ReID/外观（可选）算代价**，匈牙利算法指派；③ **第二轮匹配**：第一轮未匹配的轨迹与 **D_low** 只用 IoU 匹配（低分框外观不可靠）——把被遮挡目标"接上"；④ 两轮都没匹配上的检测框新建轨迹（连续 2 帧确认），轨迹连续 miss 达 max_age 转 lost/删除；⑤ 输出轨迹 ID 平滑。为什么快且准：**两轮都是简单矩阵运算（无重特征）+ 低分框兜底遮挡**——多目标跟踪（MOT）里 tracking-by-detection 的代表。答法：分组 → 两轮匈牙利 → 遮挡解释。

### Q25. KNN 的完整流程；训练数据质量问题处理（识渊 Q5/Q6）

**KNN**：惰性学习（无训练阶段）——预测时：① 特征标准化（距离对量纲敏感）；② 计算样本到全部训练点的距离（欧氏/曼哈顿/余弦——余弦对文本/embedding 常用）；③ 取最近 K 个（KD-tree/ball-tree/ANN 索引加速，高维用 HNSW）；④ 投票（分类，可距离加权 $1/d$）或平均（回归）；⑤ K 选择：交叉验证，小 K 噪声敏感、大 K 边界糊；加权/范围查询变体。复杂度：暴力 O(nd)、KD-tree 近似 O(log n)（低维有效，高维退化——维度灾难）。推理系统里的 KNN：embedding 检索（RAG 召回）本质是 ANN-KNN。

**训练数据质量问题**：① **探查**——统计画像（缺失率/分布漂移/重复/类别不平衡）+ 可视化抽样 + 规则断言（schema 校验）；② **标签噪声**——置信学习（cleanlab 类：训练集交叉验证找疑似错标）、多标注一致性（Kappa）、人工复核高损失样本；③ **离群值**——IQR/孤立森林检测，判断"删 or 保留"（业务上真实的长尾要保）；④ 缺失值——插补（均值/模型）/缺失指示特征/算法原生支持；⑤ **重复与泄漏**——去重（精确+近似 simhash）、防 train/test 泄漏（按实体/时间切分）；⑥ 分布不匹配——重采样/重加权（类别平衡、难例挖掘）、域适配；⑦ 建立数据版本与 lineage（data card），回归对比。框架答题：**先量化问题（画像）→ 分类型处理 → 用小模型验证清洗收益 → 固化进管道**。

### Q26. CLIP 的工作原理与推理流程（Teleai Q1）

**原理**：双塔对比学习——image encoder（ViT）与 text encoder（Transformer）分别嵌入到同一 d 维空间；训练时 batch 内 N 对（图，文）算 N×N 余弦相似度矩阵，对角线为正样本，**对称 InfoNCE 损失**（cross_entropy( logits, arange(N)) 双向）拉正推负，配大 batch（32K）与 4 亿图文对。产出：对齐的图文表征 + zero-shot 分类能力（类别转 prompt："a photo of a {label}" 与图匹配）。

**推理流程**：① **zero-shot 分类**：预计算所有类别文本 embedding（可 ensemble 多模板）→ 图像 encoder 出向量 → 余弦相似度最大类（或 softmax 概率）——无需训练新 head；② **检索**：图搜文/文搜图的向量近邻；③ **作为 VLM 的视觉编码器**（LLaVA 类）：CLIP ViT 输出 patch 特征经投影层进 LLM，文本塔弃用；④ **开放词汇检测/分割**：区域特征与文本 embedding 对齐（GroundingDINO 类）。工程点：预计算文本向量缓存、图像 batch 编码 + 归一化后矩阵乘、fp16 加速（对比训练细节见 [11](./11-深度学习与训练.md) 对比学习）。

### Q27. DeepSeek-R1 与一般基座模型的区别（Teleai Q3）

R1 = DeepSeek-V3 基座 + **推理能力后训练**的产物，不是新结构：① **训练方法**——纯 RL（GRPO + 可验证奖励：数学/代码判分，无初始 SFT 的 R1-Zero 路线展示"推理行为自发涌现"：长 CoT、自我验证、反思；正式 R1 = 少量冷启动 SFT → 推理 RL → 拒绝采样造 SFT 数据 → 全场景 RL）；而一般基座只到预训练（+基础 SFT/RLHF）；② **行为差异**——输出长思维链（`<think>` 段）、推理 benchmark（AIME/MATH/GPQA）大幅超越同尺寸非推理模型；③ **部署差异**——生成 token 数多几倍到几十倍（成本/时延、KV 管理、投机采样适配、R1 后来蒸馏了 Qwen/Llama 系小模型）；④ 与 V3 结构相同：MLA + MoE + MTP（[100](./100-t5-推理引擎.md) Q13）。对比 V3（chat 版）：V3 通用对话/函数调用、R1 深度推理——生产线常按任务路由（R1 复杂问题、V3 快速任务）。

## 六、框架与其他（上海AI/格灵/软性题）

### Q28. MindSpore 的主要特点与前后端架构（上海AI Q3/Q4）

**特点**：① **自动并行**（开发者只写单卡程序，框架按策略自动切分数据/模型/流水线——"自动并行"是华为主打差异化）；② **动静统一**（PyNative 动态图调试 + Graph 模式静态执行，一行 `set_context` 切换）；③ **函数式可微**（源码变换自动微分，`mindspore.grad`/`ops.grad` 函数式接口，转置正向算子得反向）；④ 华为全栈协同（Ascend/CANN/MindIE 一条龙）+ 端边云（Lite/Micro 微内核，TinyOS 级部署）；⑤ 安全（静态图可形式化分析）。**前后端架构**：前端（Python API/DSL → 表达式生成 MindIR）→ **MindIR**（函数式 IR，控制流为一等公民、DAG）→ 中端（自动微分/自动并行/图优化/算子融合 pass）→ 后端（硬件无关优化 → 硬件相关：tiling、算子选择、内存复用，下发给 GE 运行时）→ runtime（流/事件调度到 Ascend/GPU/CPU 算子库）。与 PyTorch 对比：PyTorch eager+compile 路线 vs MindSpore 编译器优先路线；PyTorch 生态大，MindSpore 自动并行+昇腾亲和。

### Q29. 软性与项目类问题怎么答（海康/荣耀/米哈游等汇总）

**项目介绍框架**（海康一面 Q1、联想 Q6、米哈游 Q1、好未来 Q6、识渊 Q1、小光子 Q5/Q6、数坤 Q1、类脑 Q18、曙光 Q9、Teleai Q4、上海AI Q1、小厂实4 Q1/Q10、智源无、讯飞校面 Q8/校招 Q5、格灵 Q1 通用）：**STAR + 量化**——背景（为什么做/规模量级：QPS、模型大小、GPU 数）→ 难点（技术含量最高的 1-2 个）→ 我的方案（选型对比：为什么 A 不 B）→ 结果（量化：吞吐 ×N、延迟 -N%、精度保持）→ 反思（更好的做法）。每个项目准备 1 分钟/5 分钟两版；追问预埋：准备好"最深的点"和"如果重做"。

**经典软性题速答**：

- **国产与国外计算平台差异**（海康一面 Q2）：生态成熟度（CUDA cuDNN vs CANN/ROCm 软件栈完整度）、算子库覆盖与文档、工具链（profilers/调试器）、单卡算力/带宽代差缩小但集群与互联（NVLink/NVSwitch）差距仍在、稳定性与故障恢复、人才池——结论"硬件追近、软件生态仍在追赶"，并举一个自己踩过的例子最加分。
- **期望工作/职业方向**（海康一面 Q7）：方向明确（推理优化/训练框架/算子）+ 理由（项目经历衔接）+ 长期性（想成为某领域的 owner）。
- **快速进入新领域**（海康一面 Q8/实习 Q12）：建立知识地图（survey/经典 paper/开源代码）→ 跑通最小 demo（环境+复现）→ 读工业界实践（官方 blog/issue）→ 动手改一个小点验证理解 → 输出（笔记/分享）倒逼输入。
- **困难经历**（海康一面 Q9/实习 Q11）：技术难题 + 过程（定位/假设/验证循环）+ 结果与成长，忌纯抱怨。
- **团队协作**（海康实习 Q9）：具体例子——接口约定/文档/互备、分歧处理（数据/实验说话）。
- **测试架构设计**（海康实习 Q10）：分层（单测-集成-回归）+ 覆盖目标（核心路径行覆盖、精度对拍、性能阈值 CI）+ 数据构造（随机+边界+线上采样）。
- **AI 知识接触/兴趣广度深度**（海康实习 Q13/Q14）：一条主线深（如推理优化）+ 相邻广（训练/量化/系统），说清"深在哪"（读过 vLLM 调度器源码、写过 kernel）。
- **读博原因/收获、offer 情况、家庭**（荣耀一面 HR 类）：动机真诚 + 抗压稳定性信号；offer 如实但表达明确优先级。
- **技术学习途径/论文**（格灵 Q4）：信息源分层（论文: 关注的会议/作者、工程: 官方 blog 与 release note、社区: GitHub issue/技术群）+ 最近在读的一篇 + 一句评价——**提前准备一篇近期热点论文**（如 NSA/DSA、EAGLE-3）能瞬间具体化。
- **职业规划**（数坤 Q7）：3 年技术深度（成为某方向专家）→ 5 年广度（系统 owner），与公司方向挂钩。
- **课程相关性**（智源一 Q3）：体系结构（缓存/流水线——kernel 优化的底座）、OS（调度/内存/并发——引擎与服务的底座）、网络（分布式通信）、算法与数据结构（调度器/索引）、编译原理（图优化/TVM）、数值计算（精度/稳定性）——各配一句"在 AI Infra 里对应什么"。
- **感知/规划/控制算法的了解**（海康 Q11，自动驾驶栈语境）：感知——检测/分割/跟踪（YOLO 系、ByteTrack 见 Q23/Q24）、BEV 多视角融合、占用网络；规划——行为预测、轨迹规划（lattice/优化式）、近期端到端（UniAD 类）与 VLM 驾驶；控制——横纵向控制（PID/MPC）。AI Infra 视角落点：感知模型的量化部署（INT8 端侧）、BEV/占用网络的算子优化（Transformer 化带来的 attention/视锥变换 kernel）。
- **AI 框架开发涉及的核心模块**（类脑 Q19）：见 [100 T5 推理引擎](./100-t5-推理引擎.md) Q18（计算图/运行图/内存管理/调度器/算子后端/服务层的分层设计）——框架类公司问这个是在考你有没有"系统"的图景。
- **荣耀一面技术面**（项目侧重模型压缩 + 训练优化 + 底层优化）：模型压缩答 [101](./101-t5-量化与算子.md) 量化体系 + 蒸馏/剪枝（[11](./11-深度学习与训练.md)）；训练优化答 [104](./104-t5-其余公司杂题.md) Q2/Q5；底层优化答 [101](./101-t5-量化与算子.md) Q11（算法层）+ Q23（硬件层）——三层各给一个自己项目的例子。
